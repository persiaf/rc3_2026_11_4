## 可借鉴的可靠性接口

1. 明确输入约定：任务、桌子、候选 ID 均为从 0 开始的连续整数；机器人与矩形参数有限；候选升降高度必须与固定高度一致。
2. 建图后区分无操作可达候选和操作可达但导航断连。保留全部任务 ID，结构化报告失败，不能删除任务或将未完成当成完成。
3. 在使用学习建议之前先产生并独立验证参考方案。固定预算应包含参考方案、所有候选尝试、失败检查及回退成本。
4. 每个待接受候选使用独立路径/任务验证器；从独立折线长度和停靠数重算目标，仅以严格成本下降更新已验证方案。
5. 学习预测错误或局部求解失败保留已验证方案；保证仅相对于同一实例和目标的指定参考方案，不能扩大成全局最优或真实机械臂执行保证。
6. 新基准必须对失败场景也写结果并保留分母。最短路距离和代理可达性统一共享；所有方法预算一致。

## 集成注意点

- 包内 `rc3_fast/solver.py` 的 `export_plan` 新增了 `validate_output=False` 参数，随后由 `reliable._certify` 独立验证一次。现有工作区 `rc3_fast/solver.py` 不含该参数。直接将 `reliable.py` 放到现有包路径下导入会产生接口不匹配，不能把该适配层当成无需修改的直接替代。
- 原包将固定组合记录为 `top1=[1]`、`top3=[0,1,7]`，顺序执行 `FIXED_ORDER=(1,0,7)`。需要以最终模型冻结记录为准，不混用更早初试的固定组合。
- `_failure` 将原始场景原样置于返回结果。若场景包含 NaN/Infinity，CLI 使用 `json.dumps(..., allow_nan=False)` 写失败结果仍会抛错；新实现若承诺任何输入都有结构化落盘结果，应对诊断中的非有限数进行显式编码或报告序列化失败。不要把可验证性改成允许 NaN 的正常计划。

## 精确局部修复的参考

包内精确算法以 `(covered_task_mask,last_candidate)` 为状态，增量为图距离＋停靠罚项，最后计回程。正增量覆盖转移严格增加 bitmask，因此可按数值 mask 顺序做 DP。

局部版应将起点/终点改为保留路线的入口和出口，任务集改为移除片段后失去覆盖的任务；其他停靠覆盖的任务无需再次强制服务。候选集合需包含原片段，使原解始终可恢复。相同覆盖 mask 的两个停靠点并不一般等价，其入口、出口及中间距离不同，不应无证明地合并。

精确性只针对给定候选、覆盖和最短路度量；任务数/候选数超限时应保留原解并明确记录跳过，不能将截断搜索当成精确最优。
