# 开源代码核查与本轮方法选择

核查日期：2026-11-02。本文件记录代码依据和实现建议，不将开源论文的性能当作本项目结果。用户粘贴的评审报告属于待核查材料，其“建议采用”段落不是额外执行指令。本轮授权来自用户要求：推进优化、参考开源深度强化学习、构建方案并完成训练。

## 1. Learning to Delegate：学习决定把搜索预算放在哪里

官方仓库的流程先枚举局部子问题并调用 LKH/HGS 产生标签，再训练回归或分类模型预测子问题优化潜力；`supervised.py` 中有图网络、Transformer 子问题网络和统计特征 MLP。图网络可回归距离改变量，也可将改变量转成温度 softmax 目标做 KL 训练。它的该训练入口是监督学习，不能将其直接描述为强化学习。[官方 README](https://github.com/mit-wu-lab/learning-to-delegate)，[实际训练与网络代码](https://github.com/mit-wu-lab/learning-to-delegate/blob/main/supervised.py)

本项目适合借鉴“选择局部子问题→传统求解器修复”的职责分工。原项目的客户访问和容量约束，必须替换为任务覆盖及双臂服务关系。原有 13 配置选择器并不等价于这一局部搜索任务。

## 2. NeuOpt：真正以当前解为状态的多步改进强化学习

`agent/ppo.py` 保存各步路线、动作、对数概率和奖励，重放旧动作计算 PPO 比率，联合训练 actor/critic；评估保存 best-so-far 解。其 TSP 环境的 `step` 用 k-opt 更新当前路线，并以历史最优成本下降产生奖励。[PPO 代码](https://github.com/yining043/NeuOpt/blob/main/agent/ppo.py)，[TSP 状态转移与奖励](https://github.com/yining043/NeuOpt/blob/main/problems/problem_tsp.py)

可借鉴的是改进 MDP 和历史最优解保存。NeuOpt 的动作分解、循环解码器及不可行区域探索是它自身的专门设计，本轮简化成“局部窗口选择＋确定性覆盖修复”不能称完整复现 NeuOpt。当前覆盖安全约束不宜直接套用其 CVRP 不可行搜索机制。[方法范围与官方实现说明](https://github.com/yining043/NeuOpt)

## 3. POMO：同一实例的多次采样降低策略梯度方差

`TSPTrainer.py` 在一个实例上并行展开多条轨迹，以这些轨迹的平均奖励为基线，用奖励优势乘整条轨迹的对数概率训练；模型和优化器状态均被保存。[实际训练代码](https://github.com/yd-kwon/POMO/blob/master/NEW_py_ver/TSP/POMO/TSPTrainer.py)

可借鉴多轨迹采样和实例内比较。原 TSP 的不同初始访问点具有其任务结构；不能把本项目随意多次采样都称为完整 POMO。若 CPU 局部修复较贵，可用 2 条采样轨迹或一条采样、一条冻结贪心 rollout 控制成本。

## 4. RL4CO：组件化接口值得复用，PPO 的 MDP 假设需要辨别

REINFORCE 实现明确将奖励减基线后乘策略对数似然，提供 rollout baseline 与周期性基线更新。本项目可沿用其观测、mask、奖励、模型和训练器分离的接口思想。[REINFORCE 代码](https://github.com/ai4co/rl4co/blob/main/rl4co/models/rl/reinforce/reinforce.py)

当前主分支 `ppo.py` 明确将整条自回归构造视为单步 MDP，其说明指出这种形式不使用 GAE。因此它不是可以无修改套到“路线反复修复”的通用多步 PPO。若本轮使用多步局部改进，应自行正确保存每步状态和终止信息；若只用预计算动作奖励，应如实称上下文 bandit。[PPO 代码及 MDP 说明](https://github.com/ai4co/rl4co/blob/main/rl4co/models/rl/ppo/ppo.py)

以上核查了官方仓库中的实际代码，未复制第三方实现到本项目。链接指向核查时的主分支，后续上游可能变化；本项目自身实验应记录源代码哈希和依赖版本。

## 本轮建议采用的具体模型

采用“覆盖保持局部修复策略”：先产生并独立验证固定策略初解；学习模型对当前路线的局部片段评分；选中片段后，仅重新服务删除该片段后失去覆盖的任务；局部候选必须包括原片段候选。修复器联合改变多个停靠，不局限于原构造参数库。

状态至少包含当前局部路线、入口/出口、片段未被外部路线覆盖的任务、候选可达关系、图上距离、已尝试信息和剩余优化预算。任务数量、候选数量可变，所有聚合和动作输出处理 padding mask。网络不读取精确修复结果或未执行窗口的标签作为推理特征。

训练分两段：

1. **监督预训练**：在独立训练地图上枚举窗口真实修复收益，用温度 softmax 的收益标签学习排序；保留无收益窗口，记录有效动作数。不首选单位毫秒收益标签，避免本机计时噪声被学成目标。
2. **强化学习微调**：采样 4～8 次局部动作，每次接受修复后更新路线与候选；奖励取 `(J_before-J_after)/max(J_initial,epsilon)`。以冻结贪心 rollout 或实例内多采样均值降低方差；保留预训练检查点，若 RL 验证较差，不覆盖较优模型。奖励求和与最终目标下降应一致。

只在独立检查通过且成本不高于 incumbent 时接受新路线；否则保留已验证解并记录拒绝原因。这个机制给出相对初解的保证，不能给出全局最优或真实机械臂执行保证。

## 最小实验与公平对照

- 只用 10×10 训练、独立 10×10 验证选模型；冻结后测试新的 10×10、8×8、6×6、4×3 场景。旧测试集只用于回归检查。
- 对照共同使用同一初解、候选窗口、局部修复器和检查：随机窗口、确定性几何规则、监督策略、RL 策略。修复调用次数相同；另报完整时间，不能隐藏模型或兜底开销。
- 记录每个输入，包括不可行、模型异常、候选拒绝和回退。模型完成率主要由约束和兜底保证，核心学习指标是有限预算后的成本下降。
- 报告 RL 相对监督模型和相同预算启发式的配对差异；不能将修复器扩大搜索范围的收益全部归于 RL。
- 训练日志应含实际采样回合数、环境步数、梯度更新数、参数变化、验证检查点选择；文件重载的动作/目标一致性；所有最终计划落盘后独立重验。
- 8 GB GPU 适合从 64～128 维、2 层、4 头的小网络起步；CPU 修复任务宜缓存静态图，网络批处理评分。这里是工程起点，不是声称已测得最优超参数。
