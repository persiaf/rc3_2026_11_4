# v5机器人资产与配置预检复核

## 判断

**v4缺少可核对本地机器人资产的问题已经补齐。** 当前包内的两份AlohaMini1固定版本URDF与19个STL均能按清单复核，原模板保持未填，预检按预期阻断。不能继续笼统说“还没有URDF/mesh”，也不能把资产完整等同于真实运行配置或IK闭环完成。

本次只执行本地资产与输入校验器审查，尊重暂缓标定和真实IK的安排。没有填入任何真实限位、TCP、零位等数值，没有求IK、计算碰撞、驱动机器人或联网替换资产。

## 新发现的局部一致性缺口

既有预检检查左右TCP是否位于相应运动臂链上，但夹爪只比较配置中的角色名与引用，不检查实际URDF链归属。在原合成测试fixture中，互换左右夹爪的角色、引用及park关节集合后，左夹爪实际挂在右臂，右夹爪实际挂在左臂，仍被判为inputs_complete、0 blocker。

证据是`gripper_chain_counterexample.json`。这是输入完整性判定的假通过，不涉及实际标定或机器人运行；当前真实模板依然被阻断，因此不改变v5代理规划、缓存或MLP实验结论。

已在相邻`robot_patch`目录提供窄补丁：沿URDF实体祖先链检查夹爪关节位于所有本侧运动关节与升降关节下游，并且不经过对侧运动臂。固定工具连接允许，未增加机器人型号或具体关节数假设。该补丁不对标定真实性作认证，也不生成真实可达关系。

## 三层证据应分别命名

1. **资产完整性：已完成。** 文件、版本、URI解析、引用与数值记录可核对。
2. **运行输入一致性：真实模板仍被阻断。** 有效配置填妥后才可进入下游生成；来源文件的哈希绑定不能替代标定真实性审核。
3. **真实服务与运动可行性：按用户安排暂缓。** 仍需将来独立的IK见证、残差、碰撞与运动验证，当前不把它记为已完成。

无需重新下载同一套资产。当前可以冻结规划研究成果；夹爪链补丁作为独立输入检查维护件记录，不把修订后的源码冒充原v5测试版本。
