给 Codex 的总要求
完成一个有明确边界的研究周期：把任务级假设落实为实现、真实训练、完整路线评价、独立确认和论文证据。获得用户对完整计划的一次明确批准后，依据事前条件连续推进已授权阶段。遇到科学否定、技术阻塞或预算用尽，执行本文件规定的收尾，不无限增加实验，不以制造阳性结果为完成标准。

本任务书提供默认方法、资源和门槛。它们是此次提出的研究设计，不是已有实验结果，也不是经功效分析证明的最优预算。Codex 应在计划模式中结合真实代码、合法数据和现有硬件，把必要的执行信息补齐，输出一个具体可审阅的最终计划；只能在首次正式执行前调整建议值，且必须醒目标明差异和理由。用户批准后冻结，不能看结果后放宽。

一、最终研究目标

在多种复杂 10×10 父场景及其局部任务上训练任务级深度强化学习策略，训练结束后冻结权重；收到 4×3、6×6、8×8 局部任务请求时，通过一次确定性贪心解码及固定后处理，快速交付完整可行路径。

完整输出至少包含：停靠节点/位置集合、访问顺序、导航路径、任务覆盖与服务臂分配，以及同一验证器给出的可行性结论。

最终应回答四个问题：
1. DRL 是否改变了停靠覆盖选择与访问顺序，并改善完整任务代价？
2. 改善是否超过冻结 SL 和匹配的继续监督训练，能否说明强化学习的独立价值？
3. 冻结后的模型在未参与开发的新父布局上是否保持收益？
4. 在规定部署方式下，能否以接近强规则的质量显著减少完整请求时间？

当前问题边界为二维静态导航和双臂可达性代理约束。没有真实逆运动学或关节轨迹认证，报告不得写成已完成真实双臂机器人运动规划。训练混合父场景和局部任务，因此不得称为“只在大场景训练的零样本大到小迁移”。

研究流程完成与科学目标达成分开登记。有效负结果可以完成一次研究周期，但不能登记为 DRL 目标成功，也不能据此保证论文创新要求已经满足。

二、既有事实与关闭边界

1. 固定 32 状态诊断已经 CLOSED：
   共享表达见证 PASS；CE 14/32、Adam 排序 18/32、QP 13/32 均未达到原门槛。
   不新增损失、优化器、学习率、幅度、网络、状态或轮数，不改名续跑。
   诊断权重不得用于正式初始化、训练迁移或部署。

2. 当前可靠基础：
   完整代理约束规划、SL 起点、真实训练调用和完整评价链路已经存在。
   当前保守残差 PG 未建立可靠任务增量。
   最近 66 开发例中，FrozenSL 与 PG-cond 的 H 后平均 J 相同，PG-cond 更慢；Fixed3、Detour16 是必须保留的强对照。这些旧均值仅作历史描述，不直接并入新实验统计。

3. “SL 初始化后解冻主 Actor”不是尚未做过的新方法。
   旧 S2、GL-v4、GL-v5 已包含全参数 Actor 训练。GL-v5 的父布局收益采用“对照减候选”的正向定义，报告对 SL 的 -2.8641% 表示候选更差，不能误读为成本下降 2.8641%。

4. 原 60 保留集、旧 S3 继续封存，不读取其任务内容或结果，不用于调参、补样本、确认、最终测试。
   旧 G2.3 局部窗口选择加 STOP、已关闭的同结构 PG/critic/32 状态分支不自动重开。
   不把 DRL 局部改写路线、DDQN、GNN、额外搜索等留作未定义的自动备选。

5. 本周期只检验下述一个新候选。全参数 PG 是匹配归因对照，不是恢复旧实验或第二个可供反复选择的主线。

三、唯一主候选：保留表示，直接训练原评分映射

候选名：Decoder-PG，简称 D5-PG。

假设：
冻结 SL 已学习的场景、任务、候选与有序前缀表示，仅更新原 Actor 的评分映射，可能在保持表示稳定的同时，让完整任务回报改变停靠覆盖和顺序选择。这个假设尚未验证，不能预写为已解决根因或论文创新已经成立。

允许训练的完整参数白名单：
- key.weight
- dynamic.weight
- nav.weight
- query.weight
- query.bias

固定：
- global_net.*
- task_in.*
- candidate_in.*
- to_task.*
- to_candidate.*
- task_norm.*
- candidate_norm.*
- prefix.*

现有 hidden=64 实现中，五个可学习张量共 25,152 个标量；实施时以真实模型枚举核对。名单或维度不符先解决来源问题，不静默扩大范围。

所有正式训练均从同一份来源有效的 SL256 权重独立克隆；FrozenSL 始终保留为独立冻结副本。计划模式中登记准确文件、哈希、来源提交和预训练种子。默认使用原 seed 11622026 对应的合法 SL256；若实际仓库来源不符，必须在批准前说明，不能拿诊断权重补位。

首个候选直接使用原 Actor 评分路径，不同时训练 A1 的附加残差头。
不宣称它使用原 206 维残差输入中新增的四维摘要；原 Actor 实际输入是什么就如实记录。
保留原打分尺度、mask、任务覆盖规则、导航定义、J、H 和部署解码。
不沿用“原始 SL 两两分数最多只能变动固定幅度”的永久硬限制作为候选定义；稳定性采用本文件固定优化配方和工程检查。任何 KL/TV/残差保护的新增都属于方案变化，不能运行中补上。

模型动作的真实含义：
选择下一个合法停靠节点；服务该节点覆盖的剩余任务；形成停靠集合与访问顺序。
当前模型不直接选择同一节点对之间的替代通道，不直接学习左右臂选择、连续停靠姿态或关节轨迹。导航和服务规则决定的部分必须在方法图中明确。

四、统一训练配方与匹配对照

4.1 固定训练配方

D5-PG 与 Full-PG 必须采用完全一致的下列配方，区别仅为参数开放范围。

- 自然起点，无强制首动作。
- 每个训练任务采样一条完整轨迹，所有实际采样动作均计入 log probability。
- 一次 optimizer 更新的逻辑 batch 为 8 个任务。
- 每 batch：4 个完整 10×10 任务，4 个局部任务。
- 局部 4×3、6×6、8×8 数量按 (2,1,1)、(1,2,1)、(1,1,2) 循环。
- 终局成本和奖励保持现有定义：J = L + 0.75K；完整 return = -J_H。
- 冻结 SL256 在同一任务上贪心加同一 H 的 J_H 作为不依赖采样动作的参考。
- 最小化：
  L_PG = mean_i { stopgrad[J_H(tau_i) - J_H(tau_SL,i)]
                   × sum_t log pi_theta(a_it | s_it) }。
- 保留正、负和零优势，不只学习成功样本，不截断负优势。
- gamma=1，entropy_weight=0，不增加 Critic，不新增优势标准化或 CE 混合项。
- Adam：lr=1e-4，betas=(0.9,0.999)，eps=1e-8，weight_decay=0。
- 全局梯度范数裁剪为 1。
- 每个 PG 训练流固定 4,096 个逻辑更新机会；本候选没有策略接受/拒绝 guard，不扫描学习率、优化器、熵权重或训练轮数。一次有限零梯度机会也照常计入，不免费补足有信号的更新；技术失败恢复仅按第九、十节处理。
- 只在更新 0、1,024、2,048、4,096 做预定开发评价；中间检查用于记录曲线、发现工程故障，不根据排名改方法。
- 主分析与部署使用固定 4,096 终点，不从中间检查点事后挑最好者。
- OOM 时允许等价微批累积，必须保持同一逻辑 batch、采样流、loss 归一化和 optimizer 次数。
- 训练按 on-policy 语义执行。任何更新后的新轨迹都用新参数；不能复用旧轨迹冒充新 on-policy 数据。

上面的配方是新周期登记的共同控制，不等同于原 GL-v5 的“三轨迹、batch4”配方。不能以与历史均值之差单独归因于冻结范围；归因依赖本周期匹配的 Full-PG。

4.2 训练任务与参考成本

首先使用合法、已有教师序列的训练任务池，登记全部可用父布局和三种局部尺寸。
预先生成一个 32,768 槽位的共同训练任务池，对应 4,096×8；槽位可按既定规则重复合法任务，但不能缩减为固定几十个动作拟合集。
三个微调种子分别在 full 和每种 local 类别内部作预定独立排列，再按第四节比例组成各自日程；共同任务池及各类别暴露次数相同。同一 seed 内，D5-PG、Full-PG、D5-SL 使用完全相同的任务顺序。
这样检验固定预训练起点和任务池下，任务顺序与策略采样的随机性；不宣称已检验预训练起点的不确定性。三个 SL 不再只是同一起点、同一确定性顺序的重复执行。
继续 SL 的延长段循环该 seed 的同一日程，不新增训练父布局或临时改变难度。

FrozenSL 参考可按唯一任务身份预先计算一次并复用，因为它与可学习 Actor 参数无关。缓存键必须包含原始任务身份、SL 权重、mask/环境版本、H 和代价定义。仅允许读取已完整验证的参考结果；缓存失效、重算和失败均计账。
训练 Actor 的 encoded keys 和前缀缓存不能借用该静态参考缓存，也不能跨参数版本错误复用。
原则上不新增教师查询。计划模式发现现有合法标签不足以支持所定任务清单时，应在最终计划中明确解决办法及额外资源；不能在批准后静默改任务分布或生成未登记标签。

4.3 对照及其用途

A. FrozenSL：同一 SL256，完全不训练。
B. D5-SL-U：与 D5-PG 相同五个参数，同一初始化与任务清单，固定 4,096 次更新；按原合法教师序列做每路线平均 masked CE。
C. D5-SL-C：同一 D5-SL 训练流中，按同 seed D5-PG 的训练时间确定的终点；用于检验在相同训练墙钟预算下继续监督是否足够。它可能在 SL-U 之前或之后，不是按表现挑选的最佳监督模型。
D. D5-PG：主候选。
E. Full-PG：与 D5-PG 同一 PG 配方、初始化、任务、batch 和更新数，开放全部原 Actor 参数；检验冻结表示的作用。
F. Fixed3：原生完整流程。
G. Detour16：原生完整流程。

D5-SL 的 U/C 两终点采用第四节同一 Adam 参数、梯度裁剪和无学习率调度约定；区别为 masked CE 目标、教师轨迹和既定停止规则。不能执行时再为某个分支挑选更有利配方。

D5-SL-C 的精确规则：
- 每个 seed 先完成 D5-PG，得到训练时间目标，再运行一条 D5-SL 日程。接近时间目标时保存前后相邻完整更新；在 4,096 更新保存 SL-U。SL-U 已保存且时间目标已到达后结束，最多 16,384 个逻辑更新。
- 同一硬件、线程和计时边界；比较时不并发运行有竞争的训练作业。
- 时间包含训练所需准备、Actor 前后向、PG 的参考成本与 H/验证；不含开发评价、纯网络上传或无关等待。
- 参考表统一在训练前预计算。某 PG 流的匹配时间定义为该流实际训练时间，加它使用的全部唯一任务参考的首次预计算费用；参考表读取已包含在实际训练时间。每条 PG 流的独立运行预算均分配这份必要参考费用，实际全周期资源账只计真正执行的一次。两种账不能混用。
- 取时间预算内最后一个完整更新的检查点；若边界误差不超过 2%，登记 COMPUTE_MATCHED。若单次更新过大、时间上限或 16,384 上限导致无法匹配，登记 COMPUTE_UNMATCHED，并报告实际比例。
- 如果 SL 在 4,096 更新时已经超过 PG 的时间预算，则保留事前计时日程中预算内的最后一个完整检查点作为 SL-C；不能看表现选检查点。
- 监督延长段与原段共同使用单个 8 小时训练流上限，不重新给预算。
- SL-C 有更多或更少教师任务暴露时如实记录；不能称为同时严格匹配训练时间、更新数和标签暴露。
- SL-U 支撑更新数与任务暴露对照；SL-C 支撑训练时间对照；两类结果各自报告。
- 即使匹配成功，也只支撑“在同硬件、登记训练墙钟和既有标签条件下，DRL 相对继续监督仍有增量”的结论。同墙钟不等于同 FLOPs 或相同状态暴露，不能声称排除了全部计算和数据因素。若匹配不成功，准确报告实际比例与这一证据缺口。

所有方法以相同输入、验证器与部署计时协议评价。
神经模型均采用单次贪心加固定 H；不为 DRL 偷加 beam search、多次采样择优或不同搜索预算。
规则方法的 raw 字段若本来就是内部搜索后的终局，保留 native-final 标记，不能充当神经 no-H 消融。

五、实现中必须解决的真实问题

不能只把 requires_grad 改成 True。

当前 A1 路径中的 no_grad、detach 和保存的 x/z0 不能把梯度传到原评分映射；旧 all-parameter Trainer 也会拒绝部分冻结。增加独立、窄范围的适配器，保留旧实验代码语义，不删除旧检查绕过约束。

实现要求：
1. optimizer 恰好拥有白名单中的五个张量；Full-PG 恰好拥有原 Actor 全部参数；不同模型不共享可变存储或 optimizer。
2. 使用可微的 policy.encode/score，或按同一有序动作轨迹重算完全对应的概率。
3. 更新后重新构造包含 key 映射的编码及版本相关前缀缓存。
4. 真正冻结的表示和 GRU 参数，在更新前后逐位保持不变。
5. 冻结 SL 参考无梯度、无晋升，不消耗候选策略的采样 RNG。
6. 保存完整轨迹的任务身份、动作、mask、参数版本、终局 raw/H 结果及 loss 来源。
7. 部署导出模型与训练器内同权重贪心结果一致。
8. 明确训练终止语义：核对原输入条件与动作 mask 是否保证有限步完成；若原环境允许策略性失败或截断，登记并复用其既有终止代价和有限 return。不得丢弃失败轨迹、用不完整路径的低成本奖励策略或临时发明惩罚。无法形成明确 return 契约时，P0 不通过。

工程验证只覆盖足以防止研究失效的项目：
- SL 初始化前后 logits、mask 和完整路线一致；
- 有效普通任务上，白名单计算图确实连通且梯度有限，名单外无梯度且不变；
- optimizer 身份集合正确；
- 完整 return 与 -J_H 一致；
- 非法动作概率不泄漏，完整路线同一代理验证通过；
- 保存恢复后继续同一更新，与不中断运行在既定确定性容差内一致；
- 导出后冻结推理一致。

只用合法普通训练任务或专门登记的工程合成例。工程阶段最多 24 次 optimizer 尝试、60 次完整规划计算；它们计入总账，不作为科学收益证据。
不得扩展为固定 32 状态拟合、教师排序成功率门槛或新的工程证明论文。

六、数据分工与评价指标

6.1 四层数据

训练层：上述既有合法父场景及任务清单。
开发层：现有允许的 66 请求；明确 8 个已训练 SEL 父布局与 3 个已暴露 DEV 父布局，分组报告。可用于预定检查与工程计时；不称独立泛化证据。
确认层：24 个真正新父布局，每个 6 个任务实例，共 144 个任务实例。
最终层：另外 24 个真正新父布局，每个 6 个任务实例，共 144 个任务实例。
任务实例数不等于规划调用数：后者还要乘方法、独立模型和计时重复，并计入总资源账。

新父布局每层默认 mixed/blocked 各 12 个；每父布局覆盖三尺寸与两个既定端点条件。
计划批准前固定生成器版本、种子、顺序、分层和有效性规则；只登记身份/生成规则，方法冻结前不生成或查看保留层任务内容。
新父布局必须与训练、开发及另一保留层按真实几何身份隔离，不能只换文件名、任务抽样或局部窗口便称未见父布局。
检查隔离时只使用允许的注册身份/哈希；不能为了排除重叠读取原60或旧S3封存内容。
若仅凭允许元数据无法证明不重叠，应报告限制，不能伪造独立性。

任务生成的预检只排除违反原任务定义的输入，采用事前固定规则，保留全部生成尝试及拒绝原因。
不能因某种方法困难、规则优势大或 DRL 结果差而换种子、补容易案例。
科学运行中的失败请求保留，不能删除后算“成功样本平均”。

6.2 必须保存的逐请求字段

数据层、父布局身份、任务身份、尺寸、端点/布局类型、方法、训练种子、权重身份、参数版本、请求 attempt；
输入有效性、路线可行性、失败原因；
J_raw、J_H、L_raw、L_H、K_raw、K_H；
完整请求时间 T_full、准备/推理/H/验证时间、缓存状态；
完整原始和最终路线、停靠集合、任务/臂服务记录；
规则方法计算层次标记；
来源与配置版本。

失败时 J 不填成 0，不用低成本不完整路径作收益。失败率以所有原定请求为分母。本阶段规定的 D5-PG 模型若在任何正式有效输入上产生不可行输出，候选可靠性门槛不通过；成本统计只作明确注明条件的描述，不据成功子集宣布整体优越。
对照失败独立登记，Full-PG 或规则对照失败不自动判定候选失败。但主要比较对象无法提供完整可行成本时，对应收益比较不可判定；不删请求、不伪造罚值，也不据此宣布该项收益达标。
本文件的“全部通过”只指所测试请求，不是对所有未来任务的安全保证。

6.3 主要统计

对每个父布局先平均其 6 个请求，再计算配对相对收益：
g_p(C) = [mean_J_C,p - mean_J_D5PG,p] / mean_J_C,p。
正值表示 DRL 更好。
先对父布局等权，再汇总；不把同父布局多个窗口当独立环境。

开发阶段保留 SEL、DEV、整体与三尺寸描述性结果。开发筛选不因 DEV 只有 3 父布局而强行要求显著性。
确认/最终：mixed/blocked 分层父布局 bootstrap 20,000 次，固定统计 RNG，给出单侧 95% 下界或上界。
三个训练种子先在同一父布局内汇总；同时报告各 seed，不把 3×144 行当 432 个独立父布局。区间主要反映父布局抽样，三个种子不足以完整刻画全部训练随机性。
固定 FrozenSL、SL-U、SL-C 三个 SL 比较和既定 AND 判定，不因哪个基线容易胜出就换主要比较。
候选方法级均值与事前指定的部署模型分别报告。

10.3 技术修复与科学否定

允许修复：断点/路径/schema错误、明确的计算图错误、缓存版本错误、确定的统计/计时实现错误、等价微批缓解 OOM。
修复必须有可定位证据；被影响结果作废并保留原因。修复消耗全部计账。
同一根因最多两次修复尝试，全部修复仍受工程池和总预算限制。

不把以下情况称作 bug 以获得重跑额度：
loss下降但路线不变；有效训练没有收益；某 seed 差；优势多为负；SL/规则更好；置信区间不过门槛。
改学习率、换优化器、添加 Critic、增大模型或改变奖励不是等价工程修复。

确认/最终集一旦因流程错误被暴露，不能简单修完再用同一集合宣布独立确认成功。标记其已暴露并停止对应确认主张；未经新计划批准不得自动补一套保留集。

10.4 通信和终端状态

保持简洁阶段汇报，内容只有：已完成证据、当前结论、累计资源/剩余额度、下一项既定动作。
不每做一个文件就写长报告，不在阶段中间因常规推进等待用户回复。
会话中断不等于研究完成；会话可恢复时按状态继续。平台会话、额度和运行环境有各自生命周期，不承诺一个聊天窗口无限持续运行。
若需要长期进程，使用环境允许的正常作业管理与可恢复入口，不把无限循环当研究设计。

最终状态：
- GOAL_ACHIEVED：最终层全部正式目标通过。
- PARTIAL_QUALITY_ONLY：DRL独立质量证据成立，但规定速度/强规则目标未满足。
- LIMITED_OR_UNCONFIRMED：开发有收益，复现/独立确认/归因仍未建立。
- SCIENTIFIC_NEGATIVE：已完成相应预定实验但没有所需任务收益。
- INCOMPLETE_TECHNICAL_OR_RESOURCE：实现、来源、数据独立性或预算使预定研究未完成。
另单列 workflow_complete=true/false。不得用程序退出码0或文件写完替代科学状态。
