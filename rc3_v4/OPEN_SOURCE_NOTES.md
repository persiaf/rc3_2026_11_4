# 开源方法参考与第四版输入消融

核对日期：2026-11-03。下列链接为作者官方仓库或官方文档。本轮读取了仓库说明和 RL4CO 自定义环境教程；后续代码页网络请求失败，因此本记录不声称逐行复现这三个项目，也不移植其预训练权重或引用其性能作为本实验结果。

## 可借鉴的部分

| 官方来源 | 本轮核对到的内容 | 对当前问题的应用 |
|---|---|---|
| [Learning to Delegate](https://github.com/mit-wu-lab/learning-to-delegate) | 将学习用于选择局部子问题，再由 LKH-3/HGS 子求解器处理；提供枚举子问题、采集轨迹及回归/分类训练流程 | 保持 Fixed3 初解和确定性修复器，用实际修复收益监督局部选择；输入消融时固定动作集合和标签生成方法 |
| [NeuroLKH](https://github.com/liangxinedu/NeuroLKH) | 将稀疏图网络与 LKH 启发式组合，提供 Python 与 C 求解器的 subprocess/SWIG 两种集成方式 | 学习负责引导组合优化，确定性求解器负责产生候选；总时间必须包含模型与求解器间的数据构造和接口开销 |
| [RL4CO 自定义环境教程](https://rl4co.ai4co.org/examples/3-creating-new-env-model/) | 分开定义 reset、step、动作 mask、合法性检查、奖励和生成器，以及初始、上下文、动态嵌入 | 明确环境状态与策略输入边界；新覆盖环境需自定义关系和验证，不能把原 TSP 环境当作覆盖路由环境直接使用 |

这些项目没有证明当前双臂覆盖路线问题会得到同样收益。它们也没有提供本项目所需的真实机械臂可达证书。

## 本轮具体设计推论

以下是结合第三版反例作出的工程推论，而非上述项目已经实现的功能：

1. 对每个待修复窗口编码必需任务、替代候选及两臂覆盖关系。入口到候选、候选到出口、候选之间的导航图距离必须进入观测；欧氏坐标和旧路线 detour 统计不能替代它们。
2. 候选/任务数不同，通过 padding mask 和集合池化处理。候选是否已在路线中及窗口边界作为状态属性。
3. 限制结构化编码规模并计时。数据提取、CPU/GPU 传输、推理以及最终验证都属于规划开销；只报网络前向时间不能说明规划变快。
4. 本轮先对比相同训练数据、种子、标签、初解、窗口与修复器下的统计输入和结构化输入。不要同时改成 PPO、换修复器或扩大动作池，否则不能把结果归因于输入结构。
5. 相同修复调用次数与相同墙钟预算分别评价。模型增加的信息应在新冻结场景上体现成本或时间价值；若未形成稳定收益，默认部署继续采用 Fixed3/Detour。

本轮结构化编码可以独立使用 PyTorch 实现，无须把整个工程迁移到 RL4CO。若后续转入在线强化学习，再将已验证的转移、mask、奖励和证书接口接入框架，可避免在环境未稳定时同时引入训练框架迁移误差。
