# 第四版代码审阅

日期：2026-11-03。审阅范围：`external.py`、`exact.py`、`small_benchmark.py`、`features.py`、`model.py`。这是同一协作任务内的代码审阅，不是外部实验室认证；审阅者未参与模型训练实现。此记录不替代训练完成后的结果判断。

## 已发现并关闭的 P2

**外部计划的停靠罚项没有与独立请求绑定。** 原 `validate_external` 同时信任计划自报的 lambda 和 J。对示例正常输出（lambda=0.75，J=14.7）同时将 lambda 改为 0、J 改为路径长 11.7，原验证器仍判通过。

已获主执行者授权，仅修改 `external.py` 与 `test_external.py`：

- 验证入口增加关键字 `expected_penalty`，默认 0.75；必须为有限非负实数。
- 核对计划罚项与这个独立请求值，重算目标时使用请求值。
- 内部导出传入 `problem.penalty`，独立 CLI 复验使用 `--penalty`。
- 新增联合篡改、非默认罚项和非法请求值回归。外部接口 **9/9** 测试通过。

默认验证不能推断其他调用者的真实目标；非默认目标必须在复验时独立提供。修改验证请求本身相当于验证另一个目标，不属于哈希能解决的来源真实性问题。

## 未发现阻断项的部分

小规模精确 DP 的状态、覆盖新增转移、回溯和任务上限与其证明范围一致。非负最短路度量允许删除零新增覆盖停靠，因此局部访问数量限制不会遗漏这个离散模型的最优解；有向度量也适用。超时报告保守下界与已有可行解，未标为最优。该结论只涉及给定离散候选和 float64 距离矩阵，不能迁移为连续空间或真实 IK 的最优性。

固定服务点顺序对照保留原分配，联合精确对照允许选点及排序，二者区别明确。小规模脚本保留不支持/超时状态，不将其当前解当作已证最优；一次计时明确限定为诊断。

外部接口将场景、F、ID 顺序、模型来源和见证纳入哈希，并同时检查规划表和审计表。真实检查回调可选，回调异常或拒绝会使认证失败。`built_in_physical_ik_recheck=false` 和来源级别随结果输出；文档明确外部声明、不同 producer_id 和哈希都不能证明物理正确性/来源独立性，范围表述准确。

模型的候选池化、任务到两臂覆盖聚合、导航距离注意力和各级 padding mask 未发现收益标签直接进入输入。NumPy 权重形状、有限值、标准化和模式元数据均有检查。控制组将结构化数值清零并保持同一名义架构，适合作为本轮输入消融；它不是第三版原 MLP 的同一参数化。

## 必须保留的研究边界

1. 结构化图只包含局部必需任务和候选池关系。替代候选对窗口外任务的覆盖没有完整输入，而规范化可能因此删除窗口外停靠。因此可称“加入局部 F/D 结构信息”，不可称“充分状态”或“彻底消除收益信息缺失”。
2. 单点可达证据、候选姿态和底盘圆包络验证不证明机械臂运动全程、升降过渡或双臂同时运动无碰。
3. `small_benchmark` 的直接源码清单不包含每个共享依赖。最终交付应另外绑定共同的场景、导航、验证器、环境源码，或引用已通过严格审计的第三版冻结清单。
4. 特征向量化仍在主执行者处进行，需由其数值等价测试与重新微测确认；本次审阅不对尚未看到的修改作保证。

当前代码审阅未留下已确认的未修复 P1/P2。模型收益、时限通过与部署选择必须等实际结果审阅后判断。
