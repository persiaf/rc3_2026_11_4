**建议继续推进一条独立的“构造式深度强化学习”研究线：让模型直接决定服务停靠点及访问顺序，生成满足可达与覆盖约束的完整任务路径。**

第三部分可以暂定为：

> **面向双臂可达覆盖约束的移动操作任务路径联合构造与跨规模泛化方法。**

首要实用目标建议设为：**在接近 Detour 的路径质量下，显著缩短完整规划时间。** 同预算进一步降本作为次要目标。

我核对了你当前 GitHub 提交 `f7a057d` 的主要规划、约束、验证和精确求解模块，也查阅了更贴近本课题的覆盖路径学习论文及作者代码。下面给出可以据此实施的研究方案。**其中的实验数量和验收指标均为建议设计，尚不是新的训练结果。**

## 一、研究方向需要怎样调整

### 1. 把主要路径决策交给学习模型

新模型每一步回答：

> **面对尚未完成的任务，下一次应该在哪个服务位置停靠，才能使最终完整路线的代价更低？**

一次动作会同时影响：

- 本次完成哪些任务；
- 后续还需要访问多少个服务点；
- 剩余任务的空间分布；
- 后续绕行与最终返航距离。

这些影响可以通过完整轨迹回报训练，使强化学习承担第三部分的主要决策。

已有代码值得继续利用，但需要准确描述其能力：**Fixed3 已包含多配方构造、2-opt、候选服务点替换和冗余停靠删除。** 因此，新方法的区别应落在“直接学习完整路线的构造策略及其质量—时间表现”，不能写成“首次允许改变停靠点集合”。这一点可以从当前 [`rc3_fast/solver.py`](https://github.com/persiaf/rc3_2026_11_4/blob/f7a057d92252427bdd76ab0d88247404685d49e5/rc3_fast/solver.py) 中核实。

### 2. 优先研究“快速达到强基线质量”

此前多轮实验说明，现有强规则方法已经较有效。继续要求学习器在完整开销更大的同时，仅靠小幅降本证明价值，会比较困难。

新路线更适合检验这样的假设：

> 通过离线训练，把部分在线搜索过程转化为策略推理，在新场景中用较少计算获得接近强搜索方法的路径。

如果最终能够做到“Detour 附近的质量、明显更低的完整规划时间”，模型就具有实际用途。随后再检验它是否能在相同时间预算下取得更好的解。

这仍需要实验验证。逐点解码包含多次网络调用，**构造式模型并不会天然比规则快**，所以要把推理开销诊断放在训练之前。

### 3. 保持当前问题边界清楚

目前生成器每桌提供 8 个候选服务配置，因此百桌场景通常对应 **800 个候选点**。任务与候选服务点是两类对象，不能把百桌场景直接视为 TSP100。

同时，当前标准规划入口使用固定升降高度、独立顺序单臂任务，并明确拒绝可变升降输入。新研究第一阶段继续沿用这一范围，论文中应称为“考虑双臂可达约束的任务规划”，不能提前写成升降过程或双臂协同运动已经完成优化。相关定义见 [`baseline.py`](https://github.com/persiaf/rc3_2026_11_4/blob/f7a057d92252427bdd76ab0d88247404685d49e5/rc3_baseline/baseline.py) 与 [`rc3_v4/plan.py`](https://github.com/persiaf/rc3_2026_11_4/blob/f7a057d92252427bdd76ab0d88247404685d49e5/rc3_v4/plan.py)。

## 二、开源起点：优先参考 CSP-Attention

本轮检索到一个比普通 TSP 项目更接近你的问题的研究：

**Li 等：Deep Reinforcement Learning for Combinatorial Optimization: Covering Salesman Problems**

- [论文全文](https://arxiv.org/html/2102.05875v1)
- [作者代码 CSP_Attention](https://github.com/kevin031060/CSP_Attention)

这项工作已经使用注意力、动态覆盖信息和 REINFORCE 生成覆盖路线，并研究跨规模泛化。因此，**“注意力＋动态覆盖＋跨规模”本身不能单独作为新创新点**。它应成为最接近的外部学习参照。[arxiv.org](https://arxiv.org/html/2102.05875v1?utm_source=chatgpt.com)

你的任务与其原始实现有几个直接影响模型设计的差异：

| 维度 | CSP-Attention 原始设定／实现 | 当前课题需要处理的内容 |
|---|---|---|
| 需求与服务点 | 城市同时承担需求与访问点角色 | 桌面任务与底盘服务候选分离 |
| 覆盖关系 | 实验主要采用几何半径或近邻覆盖 | 由机械臂可达关系决定 |
| 移动代价 | 欧氏距离 | 考虑障碍物的导航最短路距离 |
| 起终点 | 在选中城市之间闭合 | 从指定起点出发并返回 |
| 优化目标 | 巡回长度 | 路径长度与服务停靠次数的加权代价 |

上述区别是适配与改进的依据；原论文的一般定义已经允许每个节点覆盖一个集合，所以也不能把“用覆盖集合建模”本身称为首次提出。[arxiv.org](https://arxiv.org/html/2102.05875v1?utm_source=chatgpt.com)

**建议固定以下技术分工：**

| 用途 | 采用的来源 |
|---|---|
| 最接近的外部学习对照 | CSP-Attention 的本项目适配版 |
| 策略梯度与 rollout 基线依据 | [Attention, Learn to Solve Routing Problems!](https://github.com/wouterkool/attention-learn-to-route) |
| 训练和环境接口框架 | [RL4CO](https://rl4co.ai4co.org/examples/3-creating-new-env-model/) |
| 几何、可达关系、导航与独立验证 | 当前冻结工程 |

AM 作者实现采用 REINFORCE 与贪心 rollout 基线；RL4CO 官方提供自定义环境、动作掩码、奖励、合法性检查以及动态嵌入接口，适合承接新环境。这里需要自行实现覆盖任务语义，不能直接替换 TSP 数据就认为适配完成。[GitHub](https://github.com/wouterkool/attention-learn-to-route?utm_source=chatgpt.com)

首轮只保留一个训练主线：**REINFORCE＋冻结贪心 rollout 基线。** PPO、POMO 等暂不作为并行调参方向，先把问题定义、表示能力和推理开销验证清楚。

## 三、数学模型：服务点选择与访问顺序联合优化

### 1. 基本对象与目标

定义：

- 任务集合：\(\mathcal T=\{1,\ldots,n\}\)；
- 候选服务配置：\(\mathcal V=\{1,\ldots,m\}\)；
- 指定出发与返回点：\(0\)；
- 左、右臂可达关系：\(A^L_{ij},A^R_{ij}\in\{0,1\}\)；
- 导航距离：\(d_{uv}\)，取当前障碍导航图上的最短路；
- 服务配置 \(j\) 的覆盖集合：
  \[
  C_j=\{i\in\mathcal T:A^L_{ij}\lor A^R_{ij}=1\}.
  \]

对于路线

\[
\tau=(0,v_1,\ldots,v_K,0),
\]

沿用当前目标：

\[
\min_\tau J(\tau)
=
d_{0v_1}
+\sum_{k=1}^{K-1}d_{v_kv_{k+1}}
+d_{v_K0}
+\lambda K,
\qquad \lambda=0.75,
\]

满足

\[
\bigcup_{k=1}^{K}C_{v_k}=\mathcal T.
\]

这里的 \(K\) 继续表示**服务候选访问次数**，\(0.75\) 是当前实验采用的等效距离惩罚，不能直接解释为真实停靠耗时或能耗。

如果使用外部规划表与审计表，要沿用当前工程的语义：**先对同一只臂求交，再合并左右臂覆盖**。例如：

\[
B_{ij}
=
(F^L_{ij}\land Q^L_{ij})
\lor
(F^R_{ij}\land Q^R_{ij}).
\]

这样才能避免“规划表允许左臂、审计表只允许右臂，却被错误合并为合法服务”的情况。当前 [`rc3_v5/external.py`](https://github.com/persiaf/rc3_2026_11_4/blob/f7a057d92252427bdd76ab0d88247404685d49e5/rc3_v5/external.py) 已按逐臂共同约束处理，新环境应直接继承。

### 2. 当前条件下，臂归属可以确定性生成

根据现有模型，任务相互独立、顺序执行，没有每臂容量、操作时长、先后关系或同时操作耦合，而目标只包含 \(L\) 和 \(K\)。

据此可以推导：

> 在一个已选服务点完成所有当前可达的未完成任务，不会使现有目标变差。

因此，第一阶段采用：

\[
\text{本次完成任务}=U_t\cap C_j,
\]

其中 \(U_t\) 是未完成任务集合。具体执行臂再从合法臂中确定性选择。

这一处理有两个好处：动作空间只包含服务点，训练更直接；模型输出仍能保留逐任务的执行臂与验证依据。

**左右臂标签仍需保留，但在当前目标下，最优路线主要取决于左右可达关系的并集。** 如果以后引入经确认的双臂并行时间、负载、同步或先后约束，再扩展任务分组和分臂动作才有明确意义。

### 3. 构造式 MDP

采用状态：

\[
s_t=(\mathcal G,U_t,p_t),
\]

其中 \(\mathcal G\) 包含静态覆盖关系和导航信息，\(p_t\) 为当前位置。路线前缀用于输出与重放。

合法动作集合为：

\[
\mathcal A(s_t)=
\left\{
j:
U_t\cap C_j\neq\varnothing,\ 
d_{p_tj}<\infty,\ 
d_{j0}<\infty
\right\}.
\]

选择 \(j\) 后：

\[
U_{t+1}=U_t\setminus C_j,\qquad p_{t+1}=j.
\]

采用奖励：

\[
r_t=
-\bigl(d_{p_tj}+\lambda\bigr)
-\mathbf1[U_{t+1}=\varnothing]d_{j0},
\qquad \gamma=1.
\]

于是：

\[
\sum_t r_t=-J(\tau).
\]

**成功终止由全部任务完成触发，随后自动返航。** 训练目标与最终评价目标一致，也避免了此前“直接 STOP”成为主要输出的问题。

在当前静态无向导航图、每项任务至少存在一个与起点连通的可达候选、任务之间无资源耦合等条件下，每个合法动作至少完成一个新任务，因此最多 \(n\) 次服务动作即可完成。这个性质保证的是**当前模型内的完成性**，并不保证路线优于 Fixed3，也不代表真实机器人动作已验证。

## 四、模型设计：轻量覆盖关系编码器＋逐点解码

建议第一版采用：

> **任务—服务点二部图编码＋动态未完成任务聚合＋注意力候选选择。**

```mermaid
flowchart TD
    A["任务、服务点、可达关系与导航距离"] --> B["任务—服务点关系编码"]
    A --> C["覆盖与返航合法掩码"]
    B --> D["结合剩余任务逐点解码"]
    C --> D
    D --> E{"任务全部完成？"}
    E -- 否 --> F["更新剩余任务与当前位置"]
    F --> D
    F --> C
    E -- 是 --> G["返航、执行臂分配与独立验证"]
```

### 1. 保留“覆盖哪些任务”的关系

只给网络一个覆盖数量不够。

例如两个候选都能覆盖三个任务，但它们可能覆盖同一批任务，也可能分别覆盖互补的任务。两种情况对后续选点的影响明显不同。

因此，建议保留完整关联：

\[
B_{ij}=\mathbf1[i\in C_j],
\]

通过共享消息传递获得任务与服务点嵌入。每一步重新聚合：

\[
g_j^{(t)}
=
\operatorname{Pool}
\{h_i:i\in U_t\cap C_j\}.
\]

这样，候选表示会随着任务完成而变化，网络能够利用剩余覆盖关系，而不仅是静态位置。

### 2. 给解码器直接提供导航代价

候选评分至少使用：

- 候选服务点嵌入；
- 其当前可覆盖的剩余任务表示；
- 全局剩余任务表示；
- 当前位置；
- \(d_{p_tj}\) 与 \(d_{j0}\)；
- 新增覆盖数量、剩余任务比例等辅助量。

真实绕行信息应来自导航距离，避免要求网络仅凭坐标猜测障碍物影响。

若按每张地图的尺度归一化距离，\(\lambda\) 必须同步缩放，或显式保留尺度信息。否则跨规模测试时，网络面对的移动与停靠权衡会发生隐式变化。

### 3. 第一版控制网络规模和重复计算

建议起步配置为：

- 64 维嵌入；
- 2 层任务—候选消息传递；
- 一个轻量注意力解码器；
- 静态编码每场景计算一次；
- 每步只更新未完成任务聚合、动态特征和掩码；
- 参数在所有任务、候选之间共享。

这是一组起始配置，性能需要实测。优先避免每个动作都重新对全部 800 个候选做多层完整编码。

第一版保留全部合法候选动作。若后续需要候选压缩，应单独证明不会丢失所需覆盖或明确报告近似影响。

### 4. 用完整轨迹成本训练

采用标准完整轨迹策略梯度：

\[
\mathcal L(\theta)
=
\frac1B\sum_{b=1}^{B}
\operatorname{stopgrad}
\bigl(J(\tau_b)-b(X_b)\bigr)
\sum_{t=1}^{K_b}
\log\pi_\theta(a_t\mid s_t),
\]

其中 \(b(X_b)\) 由冻结策略在同一实例上贪心构造的成本给出。AM 和 CSP-Attention 均提供了这种训练路线的依据。[arxiv.org](https://arxiv.org/abs/1803.08475?utm_source=chatgpt.com)

它仍是深度强化学习：深度策略通过完整路线回报更新参数。首轮不必增加 critic、PPO 裁剪、停止分类器和收益监督等多个训练组件。

迁移开源实现时要检查变长轨迹处理。我读到 CSP 作者代码对轨迹 log-likelihood 还有按非零步数归一化的处理；新实现应明确采用上面的完整轨迹目标，不能把不同长度的归一化方式混用。

## 五、第三部分的创新应如何组织

建议把贡献组织成三个**待验证的研究假设**。

| 候选贡献 | 要解决的问题 | 必须取得的证据 |
|---|---|---|
| **面向移动操作的服务覆盖与导航联合构造** | 可达服务点选择、覆盖完成与访问顺序共同影响路径 | 与 Fixed3、Detour、强构造启发式比较，并给出小规模精确参照 |
| **显式任务—服务点关联的动态决策表示** | 聚合覆盖数量不能充分表达任务替代与互补关系 | 在相同掩码、目标和训练数据下，优于聚合特征模型及 CSP-Attention 适配版 |
| **可变规模任务的快速策略推理** | 百桌训练后处理不同任务量和桌数 | 冻结模型、零微调测试，报告质量与完整时间 |

其中，第二项最适合作为模型层面的重点。第一项提供机器人问题建模和算法设计基础；第三项证明实际使用价值。

论文中，前两部分提供的底盘／升降／机械臂模型与操作可达关系，可以通过 \(F\)、候选服务配置和导航距离进入第三部分。这样三部分之间形成清楚的输入输出关系。

**双臂结构的收益也可以单独展示**：比较单臂可达集合与双臂可达并集对应的任务可服务率、路线代价和停靠次数。它证明的是机器人配置与工作空间的价值，应与“强化学习训练带来的收益”分别说明。

## 六、具体推进顺序：四个阶段

### 阶段安排

| 阶段 | 建议工作量 | 主要产出 |
|---|---|---|
| **C0：优化空间与耗时诊断** | 12 个小任务实例；另固定 24 个百桌开发场景 | 精确参照、强规则差距、完整时间分解 |
| **C1：构造环境与强构造基线** | 复用 24 个开发场景及必要边界例 | 可重放环境、同接口启发式、独立验证 |
| **C2：一次封顶训练小试** | 1 个训练种子，最多 512 次更新，batch 32 | 最多 16,384 条采样完整轨迹与验证曲线 |
| **C3：正式对照与泛化** | 出现有效信号后扩展至 3 个种子；冻结测试 | 学习对照、消融、独立测试与跨规模结果 |

### C0：先回答“还有多少质量空间、多少时间可以节省”

当前 [`rc3_v4/exact.py`](https://github.com/persiaf/rc3_2026_11_4/blob/f7a057d92252427bdd76ab0d88247404685d49e5/rc3_v4/exact.py) 已有全局离散覆盖巡回 DP。它的状态是“已覆盖任务集合、最后服务点”，默认支持最多 14 个任务、128 个候选，因此第一阶段可以直接复用。

建议采用：

- 6、10、14 个任务各 4 个实例；
- 保留原导航几何和距离定义；
- 每例精确求解最多 30 秒；
- 超时报告上下界，不标记为最优。

为了适配候选上限，可以删除**不覆盖任何任务的服务候选**，但导航距离仍取原图最短路。不能随意截取一部分有效候选，然后把结果称为原问题全局最优。

需要比较：

1. Fixed3 的结果；
2. 预先固定预算的 Detour；
3. 完整候选集下的精确最优值或上下界。

还可以加入“只允许从基线候选集合中选点”的限制问题。注意，这仍允许删站，不能称为“固定全部停靠点、只优化顺序”。若得到

\[
UB_{\text{完整候选}}
<
LB_{\text{基线候选集合}},
\]

才足以证明集合外候选在该实例中有严格价值。

与此同时，对 24 个百桌场景做完整耗时分解。若共同预处理和验证已占总时间的 70% 以上，单靠替换搜索策略就很难实现总时间降至 0.7 倍。此时先公平共享缓存和工程优化，再评估学习策略。

**Detour 接近最优并不意味着研究没有价值**：它可能意味着降本空间小，但仍有快速复现其质量的机会。

### C1：建立一个有竞争力的构造基线

除保留 Fixed3／Detour 外，新增一个容易实现、又有实际竞争力的基线：

> **覆盖感知最便宜插入＋统一后处理。**

在当前闭合路线的一条边 \((u,v)\) 中插入候选 \(j\)，计算：

\[
\Delta_j
=
\min_{(u,v)\in\tau}
\left(d_{uj}+d_{jv}-d_{uv}+\lambda\right).
\]

根据新增覆盖量选择：

\[
j^*
=
\arg\min_{j:\,|U_t\cap C_j|>0}
\frac{\Delta_j}{|U_t\cap C_j|}.
\]

完成覆盖后，执行预先统一规定的删冗余和 2-opt。

这个基线有两个用途：尽早获得一个可工作的构造求解器；检验新神经网络是否值得其推理成本。

环境必须通过的关键检查包括：

- 完整奖励和导出 \(J\) 一致；
- 空任务、不可达任务和返航处理正确；
- 批量 padding、候选编号与原始场景映射正确；
- 保存轨迹能够重放并通过独立验证。

这些检查针对新 MDP 的实际风险，不需要重新制造大量与实现重复的测试。

### C2：做一次真正有判别力的训练小试

建议首轮固定：

- **1 个训练种子；**
- **最多 512 次更新；**
- **batch size 32；**
- **最多 16,384 条采样完整轨迹；**
- 在第 128 次更新时检查梯度、奖励、吞吐与验证趋势。

训练场景仍然只采用 **10×10 桌面布局**，任务数维持每桌 0～3，包含预定比例的 regular、mixed、blocked 类型。场景种子与生成器版本完整记录。

开发场景、模型选择场景与最终测试场景要分开。建议使用 24 个开发场景和另外 48 个模型选择场景；正式训练的不同网络种子采用相同场景种子流，减少训练数据差异带来的混淆。

小试重点看三个信号：

1. 完整路线成本是否随训练实质下降；
2. 与强基线的质量差距是否持续缩小；
3. 是否出现质量与完整时间都有竞争力的验证结果。

出现有效信号后，再进入三种子训练和正式学习对照。建议主模型总预算上限为：

\[
3\times1024\times32=98\,304
\]

条采样完整轨迹，先导训练计入其中。

这里是**采样轨迹总数**，不是 98,304 个独立场景；采用相同种子流时，三个模型会重复看到相同实例。rollout 基线计算和对照模型训练还需另外计入资源记录。实际壁钟上限应在吞吐测量后、继续训练前冻结。

### C3：冻结模型后验证

建议首先测试：

- 60 个新百桌场景，三种场景类型均衡；
- 每个训练种子分别报告；
- 对计时进行重复、交错测量；
- 达到主实用目标后，再测试 8×8、6×6、4×3，各 24 个新场景。

跨规模测试使用同一模型和解码规则，**不微调、不为每个规模重新选择权重**。196／400 桌可以作为后续压力测试，首轮先完成用户最关心的几个规模。

## 七、如何判断模型“可靠、有用，并且确有学习贡献”

### 1. 主实用目标

建议在训练前登记以下初始门槛，经过 C0 硬件标定后固定：

> 相对预先指定的 Detour 参照，平均 \(J\) 劣化的单侧上置信界不超过 **0.5%**；完整规划中位时间不超过其 **0.7 倍**，并检查 p95 是否恶化。

同时保留 **Fixed3、Detour8、Detour16** 的质量—时间比较。新方法即使达到相对某一个 Detour 配置的门槛，也应检查是否被另一个可部署强基线同时在质量和时间上超过。

“同预算显著降本”作为次目标，不能在主目标失败后才替换评价口径。

### 2. 正式实验需要的学习对照

| 对照 | 回答的问题 |
|---|---|
| CSP-Attention 适配版 | 是否超过最接近的已有覆盖学习方法 |
| 同网络的 BC 或一步学习版本 | 完整轨迹强化学习是否提供额外收益 |
| 去掉显式覆盖关联、保留聚合特征 | 关系编码是否有实际贡献 |
| 原始模型输出与统一后处理输出 | 收益有多少来自神经策略、有多少来自后处理 |

CSP-Attention 适配版也必须使用相同覆盖约束、导航距离、指定起终点、目标、掩码和训练实例，并获得必要的当前导航代价信息。任务与候选分离后，其动态标量需要明确适配；论文中应称“适配对照”，不能称为原设定原样复现。

**若 RL 与 BC 相当，可以说明学习构造器有效，但不能继续声称强化学习带来了已证实的额外收益。** 若显式关系编码也没有增益，则需要相应收缩算法创新的表述。

### 3. 完整时间与回退必须如实统计

建议统一报告：

\[
T_{\text{total}}
=
T_{\text{输入准备}}
+
T_{\text{编码与解码}}
+
T_{\text{后处理}}
+
T_{\text{路径展开与独立验证}}.
\]

模型加载时间单列；地图冷缓存与热缓存分别测量。新旧方法在同一机器、相同输入和缓存条件下重新比较，历史毫秒值只作为背景记录。

如果在线还运行 Fixed3 并择优保底，就要计入 Fixed3 的成本。若 Fixed3 只在离线训练中使用，则不能宣称在线逐实例不劣于 Fixed3。

每个方法至少同时报告：

- 原始方案合法率；
- \(L、K、J\)；
- 完整时间中位数与 p95；
- 后处理增益；
- 回退比例；
- 各规模、各场景类型与各训练种子的结果。

置信区间以独立场景为主要配对单位。多次测时不能当作新增独立场景，三个训练种子的差异也需要单独展示。

## 八、工程实现与论文展示

### 工程上采用独立、精简的新目录

建议新研究集中放在 `rc3_constructive/`，优先只增加：

| 新模块 | 职责 |
|---|---|
| `problem.py` | 将已有场景转换为任务、候选、覆盖与导航输入 |
| `env.py` | 未完成任务状态、合法动作、转移、奖励 |
| `model.py` | 二部图编码与动态解码 |
| `baselines.py` | 覆盖感知插入基线及学习对照适配 |
| `train.py` | 策略梯度、冻结 rollout 基线、检查点 |
| `evaluate.py` | 同口径质量、时间、泛化与独立验证 |
| `protocol.yaml` | 数据划分、预算、基线配置与验收指标 |

可达计算、导航距离、路径展开、代理验证和小规模精确 DP 继续调用已有模块。这样可以减少维护重复，也避免新旧方法使用不同几何语义。

训练数据优先保存种子、生成器版本、检查点和必要重放轨迹。同一地图缓存一份静态导航信息，避免为大量任务实例重复保存完整的 800×800 距离矩阵和导航前驱。

考虑到你最初提出 MATLAB 代码冗余的问题，建议训练和规划继续集中在 Python；MATLAB 如继续使用，主要读取统一 JSON／CSV 生成论文图表，减少两端重复维护规划逻辑。

### 论文主图围绕四个问题组织

1. **机制图**：任务—候选覆盖关系、动态剩余任务、服务点选择和独立验证。
2. **质量—时间图**：Fixed3、Detour8／16、插入基线、学习模型的完整成本与时间。
3. **消融与学习曲线**：完整关系编码、聚合特征、BC／一步学习、RL 的差异。
4. **跨规模结果与固定案例图**：100 桌训练后，在 64、36、12 桌上零微调测试；展示预先固定的正常、扰动、障碍案例。

三个固定展示案例仍然适合保留，但它们用于解释决策机制。总体性能结论由独立测试集支持。

## 下一阶段的具体工作范围

**建议先完成 C0＋C1，再进行一次 C2 封顶小试。**

第一份新研究结果应包含五项内容：

1. 小任务实例中，Fixed3／Detour 距离全局精确参照的差距；
2. 百桌场景的完整规划耗时分解；
3. 覆盖感知插入基线；
4. 一条能够独立重放、逐步核对覆盖与奖励的构造轨迹；
5. 最多 512 次更新的小试曲线及继续研究判断。

这条路线让第三部分的深度强化学习承担完整路径构造，并给出明确、可检验的贡献位置：**学习任务覆盖与导航之间的长期取舍，用可泛化的策略减少在线规划计算。** 最终是否成为论文核心创新，取决于它能否同时取得可靠完成、强基线前沿上的实用表现，以及相对已有学习方法和必要消融的可重复增益。
