我的建议是：**下一步开展一次有界的“训练目标一致性”对照试验，直接检验优化最终路线成本是否有效。现有证据已经足够支持这项研究，不需要再重复一轮类似归因；同时，它还不足以支持进入 C3、扩大训练或替换默认规划器。**

## 三、下一步只优先研究一个问题：训练是否应该直接优化最终路线

建议将下一阶段定义为：

> **C2.2：固定共同后处理下，原始路线成本与最终路线成本的强化学习目标对照。**

它检验一个明确假设：

> 当前模型按原始路线成本学习，而实际交付的是经过后处理的路线。把训练目标与最终交付成本对齐，是否能够改善最终贪心规划结果？

现有训练实现使用原始路线成本构造优势值。这使上述问题可以通过一个局部、明确的训练改动来检验。

:chatgpt-content-reference{index="6"}

### 1. 先固定完整后处理映射

令策略生成原始闭合路线 \(\tau\)，把最终处理流程统一记为：

\[
\mathcal H_X(\tau)
=
\operatorname{normalize}
\left[
\operatorname{joint\_search}
\left(
\operatorname{copy}(H_{0,X}(\tau)),
C_X,D_X,\mathrm{passes}=2
\right)
\right].
\]

这里：

- \(H_0\) 是原 C2 已有的归一化和 2-opt 后处理；
- \(C_X\) 是场景的候选位姿—任务覆盖关系；
- \(D_X\) 是导航距离矩阵；
- 最后的 `joint_search` 与归一化沿用 C2.1 的固定实现和预算。

**需要保留完整的 \(H_0\) 后再追加 H1 的流程。** C2.1 对保存的 H0 路线追加处理；如果新训练直接对 raw 路线调用 `joint_search`，就变成了另一套求解流程。

这一组成关系可在固定提交的 [C2.1 实现](https://github.com/persiaf/rc3_2026_11_4/blob/44aee8f508d6c39a1d5f44d631e8e519da4f8c21/rc3_constructive/c21.py)中核对。

### 2. 两组只改变训练使用的成本

| 项目 | A：原始成本目标 | B：最终成本目标 |
|---|---|---|
| 训练优化对象 | \(J_X(\tau)\) | \(J_X(\mathcal H_X(\tau))\) |
| 网络与输入特征 | 相同 | 相同 |
| 候选、约束、先验项 | 相同 | 相同 |
| 训练实例与更新预算 | 相同 | 相同 |
| 最终评价路线 | \(\mathcal H_X(\tau)\) | \(\mathcal H_X(\tau)\) |

这样，最终两组的差别才能归因于**训练目标的改变**。

这一阶段继续使用现有的轨迹策略梯度和冻结 rollout baseline 即可。注意力构造模型使用 REINFORCE 与贪心 rollout baseline 已有成熟研究依据，深度强化学习并不要求一定采用 PPO。[arxiv.org](https://arxiv.org/abs/1803.08475?utm_source=chatgpt.com)

### 3. 后处理不可微，并不妨碍训练

设 B 组的目标为：

\[
\mathcal J_B(\theta)
=
\mathbb E_{\tau\sim\pi_\theta}
\left[J_X(\mathcal H_X(\tau))\right].
\]

只要 \(\mathcal H_X\) 固定、没有可学习参数，就可以使用：

\[
\nabla_\theta\mathcal J_B
=
\mathbb E
\left[
\left(
J_X(\mathcal H_X(\tau))-b_H(X)
\right)
\nabla_\theta\log\pi_\theta(\tau\mid X)
\right].
\]

因此，无需对候选替换或 2-opt 求导。网络学习的是：**生成经过这套固定优化流程后，最终成本更低的路线。**

实现上，可沿用原损失形式，仅替换成本：

\[
\mathcal L_B=
\frac1B\sum_{i=1}^{B}
\operatorname{stopgrad}
\left[
\frac{
J_i(\mathcal H_i(\tau_i))
-
J_i(\mathcal H_i(\bar\tau_i))
}{100}
\right]
\sum_t\log\pi_\theta(a_{it}\mid o_{it}),
\]

其中 \(\bar\tau_i\) 由冻结 baseline 贪心生成。

**不要把“后处理改善量” \(J_{\rm raw}-J_{\rm final}\) 单独作为总奖励。** 那样可能鼓励生成原始成本很差、但容易被修复的路线。若保留原逐步奖励，则可以在终止时追加这个差值，使总回报由 \(-J_{\rm raw}\) 校正为 \(-J_{\rm final}\)；直接在轨迹损失中使用最终成本会更简洁。

论文中的环境状态还应包含已生成的路线前缀，因为最终后处理结果可能依赖整个前缀。本轮可以保持网络输入摘要不变，但不能宣称“剩余任务＋当前位置”已经完整表达了后处理所需的信息。

## 四、把下一轮控制在一次可解释、可停止的小试内

### 1. 建议固定的训练配置

| 项目 | 建议设置 |
|---|---|
| 共同起点 | 冻结的 RL 第 128 次权重 |
| 优化器 | 两组都新建相同配置的 Adam |
| 其余超参数 | 沿用原学习率、梯度裁剪和损失尺度 |
| rollout baseline | 两组均固定为原第 128 次权重，全程不替换 |
| 更新数 | 每组 128 次 |
| batch size | 32 |
| 训练实例 | 相同的 4,096 个新任务实例，沿用原百桌训练分布 |
| 地图来源 | 沿用原训练地图库，任务种子使用未用过的新种子 |
| 评价端点 | 固定为本轮第 128 次更新 |
| 主要变量 | 原始成本目标或最终成本目标 |

两组总计 **256 次更新、8,192 条策略采样轨迹**。由于两组复用同一实例流，这对应 **4,096 个不同训练实例**，不能写成 8,192 个独立场景。

两组都重建 Adam，是为了避免原始成本训练产生的优化器动量只影响其中一组。因此，应把它描述为“从共同权重进行匹配的暖启动”，而非原 C2 的精确续训。

任务生成与策略采样应使用独立随机数流，避免两组路线长度不同，导致后续训练任务也不同。

### 2. 使用一批新的机制评估场景

建议新增 **48 个百桌场景**，regular、mixed、blocked 各 16 个，提前固定地图种子、任务种子与统计口径。训练结束后，一次性评价：

1. 冻结的第 128 次权重＋完整 \(\mathcal H\)；
2. A 组训练终点＋完整 \(\mathcal H\)；
3. B 组训练终点＋完整 \(\mathcal H\)；
4. 纯先验＋完整 \(\mathcal H\)；
5. Fixed3 完整流程；
6. Detour16 完整流程。

合计 **288 份方案，48 个独立场景**。

这批场景用于本轮决策后，就属于后续已知研发数据。原来的 24 个开发场景和 48 个选择场景用于历史分析；**60 个保留测试场景继续用于方法冻结后的正式检验。**

### 3. 把计算成本一起记录

B 组训练需要对采样路线和 baseline 路线都执行完整后处理，按上述配置共 **8,192 次完整 \(\mathcal H\) 调用**。两组 baseline 若分别计算，还会产生共 **8,192 条 baseline 贪心轨迹**；固定 baseline 可以共享缓存，但要分别记录实际前向次数和结果使用次数。

因此，这是一项**等实例、等更新、等策略采样数**的机制对照，训练时间可能不同。额外 CPU 时间和后处理工作量应如实披露。

在首次更新前，沿用现有吞吐预登记方式锁定壁钟上限。48 个场景也只是本次评估预算，不能保证一定得到窄区间或明确结论。

## 五、提前规定怎样才值得继续，避免再次无边界追加训练

建议使用两个配对指标，所有成本均在完整后处理之后计算：

\[
g_i=100\frac{J_{A,i}-J_{B,i}}{J_{A,i}},
\]

\[
h_i=100\frac{J_{0,i}-J_{B,i}}{J_{0,i}},
\]

其中 \(J_0\) 是冻结第 128 次模型的最终成本。

- \(g\) 回答：**最终成本训练是否优于同预算的原始成本训练？**
- \(h\) 回答：**新模型是否真正改善了共同起点？**

第二项非常必要：仅仅因为 A 组退化更多而使 B 组相对更好，不足以说明得到了有用的新模型。

我建议在运行前固定以下较严格的筛选规则：

| 判定 | 建议条件 | 后续处理 |
|---|---|---|
| **出现明确机制信号** | \(\bar g\ge0.5\%\)，且 \(g\) 的配对 95% 区间下界 \(>0\)；同时 \(h\) 的区间下界 \(>0\)；可行性检查全部通过 | 再设计独立训练种子的复核 |
| **当前预算不支持继续** | \(g\) 的区间上界低于 0.5%，或 \(h\) 的区间上界低于 0，或未通过可行性要求 | 结束该配置，记录结果 |
| **无定论** | 其余情况，例如均值为正但区间较宽 | 本轮结束，保留不确定结论，不自动增加更新或重抽种子 |

这里的 **0.5% 是建议事前设定的机制筛选幅度**，不是现有数据已经证明的界限，也不改变原来的部署要求。配对区间反映场景变化；单个训练种子的结果仍不能证明训练稳定性。

原部署要求继续保持：相对 Detour16 的质量非劣上界、完整规划中位时间比、p95 时间比以及可行性要求均按原协议评价。新方法达到这些条件，需要后续规范的完整测时与独立验证。

## 六、第三部分的核心创新应怎样收敛

建议暂定研究题目为：

> **面向移动双臂机器人可达覆盖任务的构造式强化学习与路径优化协同方法。**

这个题目的核心研究问题可以明确为：

> **在机器人作业空间和导航约束下，学习策略能否生成更有利于最终优化的停靠候选序列，并在固定求解预算内带来稳定的质量或效率收益？**

论文中的证据链应围绕三个层次展开：

| 层次 | 需要回答的问题 |
|---|---|
| 约束建模 | 作业候选、任务覆盖、导航距离和左右臂可行关系，是否一致地进入规划与验证？ |
| 学习机制 | 在相同后处理下，训练目标的改变是否改善最终路线？学习是否优于纯先验和冻结起点？ |
| 实用价值 | 在独立场景上，是否达到相对强基线的质量—时间要求，并能迁移到不同场景规模？ |

“神经网络构造路线＋局部搜索”已有研究先例，覆盖巡回问题本身也已有深度强化学习工作。因此，**不能只凭采用神经网络、强化学习或追加后处理，就宣称方法创新成立**；需要用任务建模、针对性的机制设计和消融结果共同支撑。[arxiv.org](https://arxiv.org/html/2102.05875v1?utm_source=chatgpt.com)

当前的左右臂分配和可行性仍受既有约束模块与代理模型限定。论文可以说明这些约束如何进入任务路径规划，但应把“可达约束下的任务规划”与“真实双臂协同运动控制”分别表述。

**我建议下一轮就围绕上述目标一致性对照推进。** C2.1 已经把问题收敛到一个可直接检验的机制：在同样的最终优化流程下，改变学习目标能否产生额外收益。完成这一次对照，才有依据决定构造式 DRL 是否值得进入独立种子复核，以及它能否承担第三部分的核心创新。
