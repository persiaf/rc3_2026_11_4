# R1 单种子机制筛选协议说明

问题：R0 已证实完整 H 后存在有界教师改进机会，但尚未证实网络可学、导航关系增益、近似策略迭代增量或部署优势。本轮只检验一个匹配训练种子的 R1 配置，不重启旧策略梯度支线，不启动 R2/R3，不读取原保留 60 例。

## 主张与判据

主要主张 C1：同表示、同参数、匹配状态/查询/更新下，改变补全参考策略的有限近似策略迭代能改善最终路线。主要证据是 D2 相对 B2 平均改善至少 0.5%，配对 95% 区间下界大于零，同时改善共同 warm_nav 与旧第 128 次权重加 H，全部 32 例可行。仅少于另一个退化模型的退化不算通过。

支持主张 C2：候选间导航关系表示能改善本配置的价值学习效果。B 对 A、D 对 C 是完整学习流程对照；两者后续参考策略与状态分布可能不同，因此不能解释为孤立的信息必要性证明。共同 gB 标签训练的 warm_nav 对 warm_base 更接近表示归因，但也仅是有限模型的学习效果。原 G1—G4 保持未通过、未执行。

部署判据另外报告：相对 Detour16 的平均相对退化单侧 95% 上界不超过 0.5%，完整时间中位数比不超过 0.7、p95 比不超过 1，且不被 Fixed3 在质量、中位时间及 p95 上支配。R1 正结果仍只是探索性开发证据。

## 模型与四组对照

64 维、2 层覆盖关系/稀疏候选关系网络，完整有序前缀 GRU。四组参数量完全相同，并共享真实当前/回家 D、精确合法掩码、完整前缀边成本与几何/覆盖特征。A/C 的候选关系值为欧氏距离，B/D 为真实 D；所有组均用同一个纯几何的 16 近邻加 4 个确定远邻拓扑。该拓扑只限制信息聚合，不删除合法动作。

A/B 是固定 g0 参考价值监督，并获得匹配的新状态与查询；C/D 是有限近似策略迭代。首轮 g0 相同，必须 A1=C1、B1=D1 参数张量及开发集路线完全一致。首轮候选只有相对当前 g0 平均改善至少 0.5%、配对 95% 下界大于零且全部可行才晋升 g1。否则保持 g0；两轮更新本身不能称为产生了有效的参考策略更新。

按照用户本轮要求，在任何数据或训练之前将旧方案的 J-only Huber 替换为相对优势 Delta 回归加查询集合内排序损失。Y=J(H(完整前缀+强制动作+参考补全))，Delta=(Yref-Ya)/max(Yref,1e-8)，正值更好。SmoothL1 beta=0.02；排序为查询对的真实优势差加权 softplus，温度 0.02、权重 0.1。未查询动作保持未知。全合法菜单 argmax 构造，无在线终局补全和规则回退。

## 数据与资源

训练 32 张新地图各一个重采样任务实例；开发 32 张独立新地图各一个任务实例，regular/mixed/blocked=11/11/10。不是数千独立训练场景。开发集用于参考晋升及最终筛选，因此不属于未触碰确认集。R0 32 例保持已知开发证据，本轮不必重复运行。种子详见 seeds.json，既有历史及保留范围审计见 seed_audit.json。

| 类别 | 上限 | 用途 |
|---|---:|---|
| 初始化 | 4,096 | 32 次训练 Fixed3 + 最多 508×8 个 gB 补全标签 |
| 两轮配对评价 | 8,192 | 4 组×2 轮×最多128 状态×8 动作；同参考缓存共享实际结果 |
| 未知动作审计 | 1,024 | 每组每轮实际训练状态上的模型全菜单 argmax；已查询则复用，否则真实补全一次 |
| 其他验证 | 3,072 | 初始224 + 两轮256 + 最终计时1728；预留128校验，余量不按结果扩用 |
| 合计 | 16,384 | 失败尝试计费；标签使用与真实调用分开；内部搜索另记 |

共享暖启动各表示 1,024 步，复制给相应两组；每轮每组 512 步。每配置继承暖启动后共 2,048 步；实际全局优化 6,144 步，不能写成实际 8,192。Adam=1e-4，batch=8，同场景采样；暖标签仅用于暖启动；每轮仅用当轮冻结参考策略的标签，不混合不同参考目标。梯度裁剪1。首轮重建配对相同优化器，第二轮保留对应优化器状态。单种子 11412026，固定小批次序列，不调参、不择优挑 checkpoint。

标签每菜单最多8个：本组参考动作（配对时包含另一组参考动作）、增益/当前距离规则填至4、当前距离填至6、独立固定排列填至8。全部保存完整前缀、动作、参考权重哈希、真实 Y、Delta。首轮状态来自实际 g0 路线的四个覆盖进度；次轮固定 g0 与当前 API 参考路线各取两个覆盖进度。两组共用相同状态池、菜单及更新预算。

审计只核查模型实际全菜单选择；若已在查询集合不得另挑一个未知动作充数。审计不参与拟合、晋升或模型选择。它测量已见训练状态上的动作泛化，不能称为独立状态泛化。报告已查询拟合、未知选择率、乐观偏差、真实补全遗憾与最差损失。

## 执行顺序与停止

1. 冻结代码、H、种子、协议、预审；仅在协议哈希登记后才生成场景与标签。
2. 收集初始化并进行硬件标定：每表示16次无优化器 forward/backward、3条无 H 原始贪心路线；这些模型计算单独记账。
3. 在任何优化器更新前冻结壁钟：min(7200,max(1800,ceil(4×(6144×最大标定更新耗时+12288×最大初始H耗时+1728×最大准备耗时+4096×最大标定原始构造耗时)+120))) 秒。标定/初始化另记；之后覆盖训练、标签、审计与最终验证。到限停止，不扩大额度、不替换种子、不把早期权重代作完整结果。
4. 共享暖启动；初始开发质量；首轮标签/训练/审计/质量与严格配对不变量；按冻结门槛晋升或保留参考。
5. 第二轮匹配数据与训练；冻结终点；全质量—时间评价及离线配对分析。
6. 由独立 paper architect/reviewer 判断证据范围，保存结果、失败原因和门槛判定。无论结果如何，本轮不自动进入 R2。

## 完整时间与验证

Fixed3/Detour16 保持原生完整部署流水线；gB、先验、旧权重和新模型使用共同 H。两类名称分别报告，不声称原生强规则与学习模型使用了完全相同后处理。H 原函数字节不变。

每个方法每场景 cold/hot 导航缓存各3次，确定随机顺序。每请求重做 C/F/D 准备、特征与静态图编码；只允许 hot 重用导航缓存。模型载入、场景生成与文件读取在请求外，分别披露；所有动作构造、完整 H、导出、独立 scalar 验证在计时内。GPU 同步边界。部署总时间为准备、特征/决策与oracle计算三个非重叠计时段之和；研究账本的写盘/fsync开销排除，完整观测请求壁钟及其差额另存。先取场景内3次中位数，再报告32例中位数/p95，另报原始96次调用 p95。保存逐场景原始/最终路线及最终完整方案证书。

所有新完整方案均须通过既有导出验证及独立 scalar 几何验证。保留冻结源/权重/旧证据哈希，所有终局调用预扣账，不隐式重跑。20000 次固定种子场景配对 bootstrap；各支持对照为探索性，不能据多个区间宣称总体确认。
