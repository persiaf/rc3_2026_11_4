# G0/G1 原始诊断日志独立复算

日期：2026-11-03。范围：只读取交付包的 `outputs/g0/case_00..31` 中已有树查询、菜单、汇总和重放记录；没有新规划、训练、性能测量或源文件修改。

## 结论

可以继续 G2 小试，但研究主线宜表述为“预算条件下的多步动作与停止决策”。现有日志支持多步后效，暂不支持把“必须先变差”作为普遍机制。要训练预算回报策略，不能直接把用于展示机制的 selected_replay 当作最佳示范。

所有新增结果都是**已查询菜单子集与深度3的离线描述性统计**。每个节点查询16个合法非STOP动作中的前7个（4 improve +3 replace），再加STOP。这里的“最好”只指已查树内，不能外推为完整动作空间、部署策略或全局最优。32个场景是样本单位，14,592条查询不是独立场景。

| 指标 | 原始日志复算 |
|---|---:|
| 场景 | 32 |
| 查询边，含STOP | 14,592 |
| 实际提案 | 12,768 |
| STOP查询 | 1,824 |
| 严格变差首步后优于已查根一步结果 | 18/32 |
| 严格即时/后续排序反转 | 9/32 |

| 严格见证且回报高于根STOP | 10/32 |
| 任一已查叶回报高于根STOP | 24/32 |

复算与五项正式机制布尔指标没有不一致。接受提案12,752、current变差3,531、窗口外冗余停靠删除1次，也与报告一致。

## 二、补上“全程单调”对照后，非单调证据更窄

“全程单调”定义：一条日志路径上每个已执行动作的 current_change 均不大于 1e-8；这与报告仅限制第一步的口径不同。允许持平和STOP。

| 同一已查树中的比较 | 场景数 |
|---|---:|
| 所有路径的最低J严格优于全程单调路径最低J | 5/32 |
| 所有路径的最高回报严格优于全程单调路径最高回报 | 1/32 |
| 最高回报路径包含current变差 | 1/32 |
| 最高回报路径首步为STOP | 8/32 |
| 最高回报路径首步为improve | 22/32 |
| 最高回报路径首步为replace | 2/32 |

质量有非单调增量的场景是 case_01、14、22、29、31。它们并非新增场景，也未执行新增动作。

所有路径最低J相对全程单调最低J的配对降本百分比：
- 全32场景均值0.046327%，中位数0，最大0.923426%；
- 按现有回报比较，仅case_14保留严格优势，回报增量0.404632。

因此，18/32“胜过一步”不能解释成18/32“胜过多步单调搜索”。

与此同时，多步仍有明确机制信号：所有深度3叶中的最佳回报，相对“最多1次提案后STOP”的最佳回报，在14/32场景更好；全32平均回报差0.256120。最佳回报路径的提案数分布为0次8例、1次10例、2次8例、3次6例。这是G2继续研究预算分配、动作顺序与停止的直接依据，不要求所有优质策略都频繁执行变差动作。

## 三、机制示例不能直接作为BC教师

selected_replay遵循“优先选择动作ID最早的严格见证，否则选择最低J”的展示规则，未按最终训练回报选择。

- 32条展示轨迹中，29条总回报低于同树已查的最高回报；
- 14条展示轨迹总回报低于根状态直接STOP。
- 这不构成交付错误；它说明这些轨迹的用途是机制展示，不是默认最佳学习标签。

case_01的具体对照：

| 序列 | J | 总回报 | 工作量 |
|---|---:|---:|---:|
| 根STOP [16] | 267.625042 | -0.171414 | 171,414 |
| 一次improve后STOP [2,16] | 266.345313 | +0.122826 | 355,354 |
| 展示序列 [1,2,2] | 266.318222 | -0.216430 | 704,733 |

展示序列比一步方案额外降本仅0.0101716%，其工作成本使总回报更低。BC数据应另建按目标一致的教师标签，保留STOP，保存多步Q或近似等价动作集合；未查询的9个菜单动作属于未知，不能直接标为劣动作。

若工作计费或终止语义在G2前修改，旧日志仍保留原值；新教师标签要绑定新环境版本。不能把旧展示数据的奖励追溯改成新结果。

## 四、重复尝试与菜单限制

- 12,768次提案中，有4,702次最终current路线完全不变（36.83%）。
- improve的7,296次中，4,686次不变（64.23%）。
- 32个根状态中，动作0有23个不改变路线。当前廉价detour贪心若一直选动作0，可能重复停留；这支持报告对其“接口参考、非调优强基线”的定位。
- 在同一路径内，894次提案重复了此前相同current路线和相同动作（约7.00%）。
- 整棵分支树共有3,570组不同的“场景/current路线/动作”，另9,198次是跨分支重复。后者很大程度来自oracle树展开，不能直接当成部署策略的重复率。

重试处理需要统一提供给所有策略。可以记录同一完整路线和同一算子参数下的无变化尝试，作为动作特征、共享候选去重或确定性proposal缓存的依据。若缓存，计费必须说明真实调用与查表差异；接受条件依赖best与预算，不能把缓存proposal直接等同于缓存环境转移。

每个已记录展开菜单都有16个合法非STOP动作，实际仅查前7个；整个树始终为4 improve +3 replace的子集。G2可使用全部16个动作，但不能宣称旧前瞻标签覆盖全部动作。扩大诊断菜单或补充采样要在开发集另成协议。

覆盖统计也应谨慎：29,184个有效动作条目中，4,053个有正的retained_overlap_fraction，6,891个有正的pool_extra_covered_tasks；只有1次实际窗口外停靠被全局规范化删除。因此“覆盖耦合结构存在”与“主要收益确实来自跨窗口覆盖重组”仍是两项不同命题。

## 五、历史时间记录显示认证是主要已记录分量

以下来自32条 selected_replay 保存的历史 state.timings，未重测。每条选定轨迹执行3次提案。它们不包含新网络推理，也不能作为部署时延结论。

| 分量 | 场景均值 | 占四项记录分量合计 |
|---|---:|---:|
| 菜单 | 90.81 ms | 20.87% |
| proposal（排除认证） | 51.59 ms | 11.86% |
| 逐提案认证 | 219.58 ms | 50.48% |
| 最终认证 | 73.05 ms | 16.79% |

认证与终验合计占已分项时间67.27%；相对记录的重放elapsed合计占55.56%。四项分量只解释重放elapsed的82.60%，其余为记录、复制、观察等未细分成本，不能擅自归类。

历史重放elapsed中位458.34 ms、均值526.69 ms；准备阶段另有均值659.20 ms。这些记录受原执行条件和并行诊断环境影响，不可与旧版本不同机器/时间口径拼接后宣称提速或退化。

工作单元中菜单占比极高，不代表CPU时间也同样由菜单主导。G2前的可检验优化应包括：
1. 检查认证器可复用的不可变几何/导航准备工作，同时保留最终独立完整检查。
2. 精确区分终止与截断：当前 step 在 horizon、工作预算或 STOP 自然终止后已经不再构建下一菜单。G0 的 End 菜单费用来自环境 horizon=16、诊断深度3后另行外部终止；它不是 PPO 必然存在的冗余，也不能追溯从原记录中扣除。若优化外部运行截止，应在事先可知的真正终止条件下另定新版本；collector 截断仍需要后继观测来 bootstrap，不能一概省去。
3. 为重试处理和缓存建立统一语义。
4. 对训练环境做独立吞吐小测，再选择正式采样量。

## 六、奖励比例的离线敏感性

只对已有叶的J与工作量作代数重算，没有重新规划，也不是新调参成功结果：

| lambda_work | 非单调回报严格胜过全程单调的场景 | STOP为已查最佳的场景 |
|---:|---:|---:|
| 0 | 5 | 5 |
| 0.001 | 4 | 5 |
| 0.003 | 4 | 6 |
| 0.01（当前） | 1 | 8 |
| 0.03 | 0 | 18 |

改变系数不能制造新的质量后效。即使完全取消工作惩罚，非单调质量优势也只在已查5个场景出现。奖励应依据真实计算代价与任务质量需求校准，不应以“让非单调/PPO更容易赢”为选择标准。

## 复算文件

- audit_records.py：单命令复算全部下述JSON和CSV的脚本，只需Python与NumPy。
- audit_results.json：全部指标、分布与逐场景最优路径。
- cases.csv：逐场景平表。
- teacher_audit.json：展示轨迹、回报最优和STOP对照。
- multistep_return_audit.json：最多3次提案与最多1次提案回报对照。
- reward_sensitivity.json：代数敏感性统计。

以上都是分析材料；原上传包、源代码和结果保持不变。

复算命令（输出目录须在源目录之外）：

```bash
python audit_records.py --source /path/to/rc3_rl_research --output /path/to/audit_results
```

脚本只读取既有G0日志，不导入或调用规划器，不执行训练或测时。标准输出仅列关键计数与文件清单，全部逐场景证据写入输出文件。
