# G2 实施任务书：预算感知的多步 PPO 小试

日期：2026年11月3日。状态：待实施方案；不是训练完成报告。

## 0. 目标、边界与本轮依据

在已交付 G0/G1 基础上，建立真正使用新鲜 on-policy 轨迹的轻量 actor-critic 与 PPO 更新器，检验它能否比同初始化 BC 和共享动作的强规则更好地分配搜索计算、安排动作和停止。

主标题保持“可达性约束下预算感知的深度强化学习任务路径规划”。先变差再改善是可选机制。现有树内，最高回报相对全程单调路径只有 1/32 场景存在严格非单调增量；最多三次提案相对最多一次提案后 STOP，在 14/32 场景有更高回报。这支持多步选择与停止研究，尚不支持把非单调性确定为普遍获胜原因。

保留原 v4/v5/v5.1、G0/G1 源码、权重、协议和结果。建议新建 rc3_rl_g2/，以只读方式引用已有适配层和求解器；新环境/训练 schema、协议、模型和输出独立。不能重写旧报告中的计数、费用或耗时。

首版仍是二维静态批次任务，只在 10×10 百桌场景训练。先完成单种子受控小试，不自动扩展三种子长训练、真实 IK 或动态任务到达。

## 1. P0：训练前必须处理的环境接口

### 1.1 状态恢复的有限性与一致性

已复现：在一个正常夹具 state_dict 中将 anchor_cost、current_cost 或 best_cost 改成 NaN，当前 load_state_dict 可以接受，随后 step 产生非有限奖励。原因是差值比较没有先做 isfinite。累计 total_reward 的 NaN 也会继续传播。

在 G2 恢复入口先验证，再一次性提交状态：

- 所有成本、累计回报、分项奖励、计时均为有限数，拒绝 bool 冒充数值；成本和工作量满足定义的非负性。
- steps、work_used 及相应计数为非负整数；不能依靠与 0 比较自动排除 NaN。
- 对 anchor/current/best 重新认证并核对路线与成本；在适用状态检查 best≤current、best≤anchor 和 current 的接受界。
- returned_certificate、finalization 与是否终止一致。回退情况按照实际返回方案与质量修正核对，不能将历史 best 与返回 anchor 混为一谈。
- 恢复菜单必须绑定相同问题、完整路线、配置和对应状态；校验动作、mask、features 的长度、类型与有限性。
- 任一检查失败时，目标环境保持原状，避免部分恢复。

这项故障注入不表示已有 G0 日志含 NaN；应修复的是新训练断点恢复入口。

### 1.2 末尾事件必须进入训练回报

当前 terminate()/finalize() 会单独追加 event，不改最后一条 transition。event 可能包含待付菜单费、最终回退修正和势函数归零修正。只读取 step 奖励会漏记。

首版训练优先让 STOP、horizon、工作预算在 step 内自然终止。rollout 达到采样长度只是收集截断：保留环境并 bootstrap，不调用 finalize。

如果引入外部真实截止：

1. 调用 terminate 后，将该末尾 event 奖励恰好一次合并到最后一个真实动作的奖励。
2. 替换终止观测、置 terminated=True，并令 bootstrap=0。
3. 零动作回合只记运行指标，不凭空生成 actor 样本。
4. 完整回合训练器所用奖励之和必须与 env.total_reward 一致，包括失败、回退和塑形。

不要把 G0 深度3诊断的 End 费用直接删除。它来自环境 horizon=16，而诊断在深度3后外部终止。当前 step 对自然 horizon/budget/STOP 已经不再构建后续菜单；collector 截断仍需要后继观测。

### 1.3 保留奖励语义

首个小试对照组沿用当前形式：

R = 100(J_anchor − J_returned)/max(J_anchor,1e−8)
    − lambda_work × work_used/work_scale。

先保持 lambda_work=0.01、work_scale=10000、potential_weight=0，减少同时变化的因素。若因计数或实际成本校准改变定义，建立新协议和新标签，不追溯改变 G0。

工作代理单位不是毫秒或 FLOPs。奖励标定依据实际任务质量需求与计算成本，不能以提升非单调使用率或让 PPO 胜出作为标定目标。

## 2. P1：建立可比较的共享动作规则基线

现有 greedy 可能重复选择同一个无变化窗口；adaptive_operator 还会对“原样返回但 accepted=True”给正的算子分数。保留它们作为历史接口参考，新增具有明确重复管理的规则对照。

### 2.1 分离两种键

- replay_context_key：保留预算、步数、history 等完整重放状态。
- proposal_key：问题身份、完整 current 路线、算子、窗口、禁用候选和实际求解限制。

当前 action_context_key 含预算/步数/history，每步改变，不能用来发现确定性重复提案。如果求解限制受预算影响，应把实际限制也放入 proposal_key。

### 2.2 共享重复处理

对同一 current 与确定性求解条件，记录已知无变化或失败动作。可选择共享尝试特征、去重屏蔽或 proposal 缓存，但首版采用一种明确机制即可。

如果屏蔽，应在菜单截断之前过滤并补入后续候选，避免前16个条目都被尝试过后直接丢失未尝试区域。动作变化和新mask对 BC、PPO、规则、随机方法一致。

缓存的是 proposal 结果，接受判断仍根据当前 best 与预算重新计算，不能缓存整个环境转移。若缓存，区分真实求解工作与查表工作，所有策略采用相同规则。

### 2.3 最小强规则组

至少包括：

- 带共享尝试记忆的 detour 顺序搜索：不在同一确定性状态反复查询已知原样动作。
- 自适应或 ILS 式多步规则：明确改进、扰动、停滞和停止规则，只在开发集选择参数；无变化结果不获得正的算子改善分数。
- 原始 Fixed3/Detour：保留原部署流程并完整计时。
- 环境 STOP：经过共同菜单后的立即停止，用于回报参照。

Fixed3 直接返回不需要首菜单，不能强迫它承担学习方法的菜单开销。菜单前的廉价停止门控若将来需要，应明确建成新决策层，不隐式免费。

所有规则只查询所选动作；若使用完整候选预求收益，每个查询都计费。不能只增强 PPO 防重复能力后与旧原地循环的 greedy 比较。

## 3. P2：整理与目标一致的监督材料

32条 selected_replay 是机制展示轨迹。复算显示29条回报低于同树已查最高回报，14条低于根 STOP。不能批量直接当作最佳 BC 标签。

case_01 中，improve→STOP 的 J=266.345313、回报=+0.122826；展示的 replace→improve→improve 为 J=266.318222、回报=−0.216430。教师选择必须对应训练目标。

### 3.1 标签定义

对状态 s 和已查询动作 a，定义 Q_obs,d(s,a) 为固定有限前瞻深度 d 内，已查分支的最高剩余回报。包含工作费、STOP 和实际终止修正，并减去到达 s 前已经累计的奖励。可另保存相对同状态 STOP 的回报差。

此值是已查子集上的有限前瞻标签，不是 horizon=16 的完整最优 Q。保存：

- problem_id、state_signature、teacher_depth、环境与奖励版本；
- 有序动作及 legality_mask；
- 独立 evidence_mask；
- 被查询动作的回报标签、相对 STOP 优势、近似并列集合和真实查询工作；
- 由原始观测复算所需的静态输入身份及动态上下文。

G0 每节点16个合法非STOP动作只查了前7个，另外9个是未知。BC的排序损失或分类归一化应限制在有证据动作集合；未知动作不能作为负样本。PPO推理和采样继续使用实际 legality_mask，两者不能混用。

### 3.2 版本与数据边界

若 G2 修改去重、菜单、费用或终止语义，旧 action_id 和总回报不能直接沿用。允许复用旧原始场景或状态作开发材料，但需按新菜单映射语义动作；无法保持语义时，重新采集少量 G2 教师数据。

旧32场景属于训练/开发资产，排除出新验证与最终确认集。按场景划分，不把同一场景不同分支随机分到训练和验证。控制同一路线的重复状态权重；14,592条查询不是14,592个独立场景。

默认先做 BC/排序预训练。若使用有限深度价值辅助头，应显式以深度为条件，不直接把三步 oracle 值当作16步 critic 的真实目标。

离线树没有当前策略的 on-policy 行为分布，不能拿旧树记录执行 PPO clipped 更新。PPO 必须重新与环境交互。

## 4. P3：轻量观测与 actor-critic

### 4.1 调试控制模型

以现有22维动作特征，加 current-best gap、真实可用预算和每动作尝试结果为输入，使用两层64维共享动作 MLP、mask pooling 和 value head。这个模型用于管线连通性检查及架构控制，不称为图策略，也不预设摘要观测足以表达后效。

### 4.2 正式 G2 候选模型

增加由 problem_id、输入哈希和特征版本绑定的只读静态图。首版32/64维、1–2次稀疏消息传递：

- 任务、候选服务配置；
- 联合可达/覆盖关系；
- 窗口入口出口与导航距离；
- 必要任务、候选池、保留路线覆盖次数；
- 当前路线顺序、窗口外覆盖、current-best gap、预算与尝试历史。

action_builder 现有 diagnostics 已保存 required_tasks、pool_nodes、retained_coverage_counts 等。需要显式进入可重建的策略输入，不能仅存日志而让网络看不到。

当前独立单臂执行且无臂相关代价/容量时，可使用 max_a C_iqa 的路线层约化；分别编码左右臂应作为有依据的消融，不能借此宣称同步双臂协作。

避免全场800候选的稠密注意力。首先不用 dropout 或依赖批组成的 BatchNorm，降低 old/new log probability 不一致风险。

采样保存原始观测、精确动作表、mask、动作、old_logp、old_value、reward、终止标志和静态图引用。PPO更新从保存的原始输入计算新概率；不能用后来 current 重构动作，也不能重复使用旧权重的编码作为新策略输出。

部署静态缓存只对固定输入和固定权重有效。训练 optimizer 更新后必须使对应嵌入缓存失效。

## 5. P4：训练执行与对照

### 5.1 小规模连通性检查

先执行数百至约1024个真实环境动作，使用少量开发场景：

- 参数未更新时，采样 old_logp 与重算 new_logp 一致，概率比约为1。
- padding与非法动作概率为0；仅STOP合法时分布有效；动作排列改变时语义映射正确。
- STOP、自然预算终止、horizon、collector截断、外部终止事件和回退的回报处理一致。
- 回报与实际返回方案对应；完整回合 reward sum 等于环境总账。
- actor/critic 梯度有限；一次有效优化确实改变参数，KL和clip_fraction可计算。
- 环境可合法恢复；故意NaN/Inf与损坏菜单被拒绝。

此阶段只证明训练闭环正确，不报告模型优于基线。

### 5.2 单种子小试

仅使用百桌训练场景，在线生成新的独立实例或使用预先登记的训练种子池。建议首个预算为32,768次实际环境动作，在8,192、16,384、32,768步固定验证。是否继续至65,536步按事先写明的开发信号决定。

起始配置：H=16、epsilon=0.02、gamma=1、GAE lambda=0.95、learning_rate=1e−4、clip=0.2、4个优化epoch、梯度范数0.5、target_KL=0.02。并行环境数、rollout与minibatch根据真实CPU/内存吞吐选择；minibatch128只是MLP起点，图模型需按图大小与显存调整。

首轮可用24个全新的百桌验证场景（regular/mixed/blocked各8个）作起点，全部模型共享。预先固定检查点规则，最终确认测试在模型和协议锁定后使用新的独立场景。验证集被反复查看，不当成最终显著性证据。

学习分支从同一个BC检查点开始：

1. BC冻结。
2. BC继续监督优化；预先固定额外教师采样预算，记录标签求解工作。
3. BC＋PPO，重新采集on-policy轨迹。

同时运行共享动作规则、随机、环境STOP及原Fixed3/Detour。记录教师工作、环境动作、优化步数、独立场景数和总训练时间。相同参数更新次数不自动等于相同计算预算。

G2学习曲线报告外部验证J、相对规则差距、回报、STOP比例、有效/重复动作、回退和完整时间；训练reward只作辅助诊断。

## 6. P5：计算效率与公平时间

已有32条三动作展示重放的历史分项均值为：菜单90.81ms、提案51.59ms、逐提案认证219.58ms、终验73.05ms。认证与终验占四项已记分量67.27%；这些分项仅解释记录elapsed的82.60%。这是历史数据描述，不是新测速，也不能作为不同机器部署比较。

先剖析认证中的不可变场景/导航准备、重复覆盖计算和相同路线重复检查。可以研究复用不可变预处理或已认证完全相同路线的证据，但须绑定输入/约束/验证器版本，保留最终独立检查和故障注入回归。不要为了加速直接删除约束验证。

训练吞吐先小测；首次场景准备与同场景多回合重置分开记录。部署时间包含预处理、初解、菜单、特征、策略、修复和终验；冷加载另列。共享优化也应用于对应规则与BC。

固定工作预算与相同完整时间预算分别比较。保留软期限/越界报告，不把原子修复称为硬实时。

## 7. 非单调性的消融与继续条件

若论文要主张非单调机制本身有效，应比较相同架构、初始化和训练预算的：

- 全程单调多步PPO（从current=best=anchor开始，epsilon=0）。
- 允许有限变差的多步PPO（epsilon=0.02）。

单调对照同样使用多步回报和STOP，不能缩减成一步贪心。仅在测试时关闭非单调不能替代匹配训练的正式消融。该消融可在主G2出现学习信号后追加，不必一开始开展多套长训练。

进入三种子训练前应看到：PPO在新验证场景上相对同初始化BC/继续BC具有可重复的改善趋势；对共享动作规则存在质量或完整时间方面值得继续检验的差距；改善不只来自单个异常场景。

若只胜过旧无记忆greedy、只训练集改善或只让变差动作比例升高，不能作为继续大训练的充分理由。大量STOP首先要检查搜索本来是否值得；不要自动降低工作罚强迫搜索。若固定动作预算有收益但完整时间无收益，分别报告两个结论。

G2本身是单种子开发小试，不直接承担最终稳定优势或跨规模泛化结论。
