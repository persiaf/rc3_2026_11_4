# 桌面任务覆盖与底盘路径规划：无学习基线

针对静态批次桌面任务，先计算带停靠朝向的左右臂代理可达关系，再选择服务停靠点、分配用臂并规划返回起点的二维底盘路径。默认运行 4×3、6×6、8×8、10×10 四种桌阵列，每桌独立随机生成 0～3 个任务，每桌设置 8 个停靠候选。

**没有训练神经网络；全部机器人尺寸是演示参数。** 输出满足当前几何代理和记录一致性约束，不代表真实机械臂、同步双臂协作或实机执行已经验证。

## 快速运行

以下命令从 `rc3_baseline` 目录执行。本机已有依赖，可直接运行：

```powershell
python baseline.py --seeds 5
```

默认使用种子 0～4、四个规模和四种方法，共生成 80 份方案。结果存入新的 `results_run_年月日_时分秒_微秒` 目录，命令结束会打印路径。每个种子的完整方案都保存；已有结果目录不会被覆盖。

新环境可以先建立独立环境，无需激活 PowerShell 脚本：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe baseline.py --seeds 5
```

本次实跑环境为 Windows、Python 3.13.5、NumPy 2.1.3、SciPy 1.15.3、Matplotlib 3.10.0；`requirements.txt` 固定了本次实测的三个库版本。每次运行都会另外保存实际版本。

只运行一个小场景：

```powershell
python baseline.py --scales 4x3 --seeds 1
```

自定义规模、种子、方法与停靠惩罚：

```powershell
python baseline.py --scales 3x2 10x10 --seed-start 10 --seeds 3 --methods nearest_feasible coverage_cost_2opt --stop-penalty 0.75 --no-plots --output results_custom
```

`--scales` 是桌阵列的列数×行数；`--seeds` 是每个规模的种子数量。`--no-plots` 跳过绘图，仍保存全部规划、服务清单、指标及运行环境。输出目录必须不存在或为空。非法参数会明确报错。

## 方法与优化目标

任务—候选—手臂可行矩阵为 `F[task, candidate, arm]`，手臂下标 0/1 对应 L/R；覆盖矩阵为 `C = F.any(axis=2)`。每个任务只分给一只手臂，按顺序服务理解。左右臂都可达时，选择肩部到目标距离较小的手臂。

目标指标为：

```text
objective_length_plus_stops_m = route_length_m + stop_penalty × number_of_stops
```

这是启发式覆盖选择与访问顺序优化，**没有全局最优保证**。选择停靠点时，候选必须能覆盖至少一个尚未分配任务，并且能从起点到达和返回。所有任务保留在分母中，不可完成的任务不会被删除或重采样。

| 方法 | 停靠点选择 | 顺序优化 |
|---|---|---|
| `nearest_feasible` | 距当前位置最近的可服务候选 | 无 |
| `nearest_feasible_2opt` | 同上 | 固定停靠集合后做 2-opt |
| `coverage_cost` | 最大化新增覆盖数 /（移动距离＋停靠惩罚） | 无 |
| `coverage_cost_2opt` | 同上 | 固定停靠集合后做 2-opt |

每对有/无 2-opt 的方法保留相同停靠集合和任务分配，以区分选择与排序的影响。2-opt 最多进行 60 轮最佳改进，适用于当前对称距离矩阵。贪心选择分数没有显式加入返回起点的增量成本，但最终路线和报告的目标均包含返回路程。

`selected_candidate_ids` 保存选点顺序；真正执行顺序以 `visit_order_candidate_ids` 和 `service_stops` 为准。到站只执行明确分配给该站的任务；2-opt 重排后不自动把其他站的任务提前完成。

## 几何参数与导航

`demo_config.json` 给出全部默认参数。可以复制后修改部分字段，未提供的字段使用默认值：

```powershell
python baseline.py --config demo_config.json --scales 10x10 --seeds 1
```

| 参数 | 默认值 |
|---|---:|
| 桌长×桌宽、桌面高度 | 1.00×0.70 m、0.75 m |
| 桌面边缘间通道宽度 | 1.20 m |
| 桌边到停靠中心距离 | 0.50 m |
| 桌面任务距边缘最小距离 | 0.04 m |
| 底盘包络圆半径、额外安全间隙 | 0.32 m、0.08 m |
| 左右肩部间距、肩部前向偏置 | 0.36 m、0.12 m |
| 机械臂球壳代理半径 | 0.10～0.90 m |
| 水平扇形半角 | 100° |
| 固定肩部高度 | 0.75 m |
| 固定升降高度元数据 `h` | 0.40 m |
| 每次停靠的等效路程惩罚 | 0.75 m |

`theta` 参与肩部坐标变换和可达性判断，单位为弧度。`h` 仅作服务配置元数据，**修改它不会改变肩部高度或可达性**；实际代理计算使用 `shoulder_height`。当前没有升降优化，也没有升降结构标定变换。

底盘代理障碍是按“底盘半径＋安全间隙”膨胀后的桌矩形。矩形膨胀是圆形底盘 Minkowski 膨胀的保守外包络，角部会更保守。零任务桌同样是障碍。

导航步骤：

1. 在规则桌阵列的通道中心线上构图，连接桌外停靠点。
2. 对每条候选图边检查膨胀矩形碰撞，剔除被阻挡的边。
3. 使用 Dijkstra 计算起点及停靠点之间的路径成本和前驱。
4. 上层规划后将每条导航腿展开为完整底盘折线。

最短路只是在这个通道图上的最短路，不是连续平面全局最短路。没有加入底盘转向成本、转弯半径或速度加速度约束；朝向不影响导航距离。

起点位于膨胀障碍内时直接报错。其余断连或被阻挡的候选不能被选用。不可服务任务会记录以下原因：

- `no_arm_feasible_candidate`：没有左右臂代理可行的候选。
- `no_navigable_feasible_candidate`：有代理可行候选，但没有能从起点往返的候选。

修改尺寸可能使任务不可完成，程序会如实保存部分方案和未服务任务。规则通道图不能直接替代任意障碍布局的导航规划器。

## 输出与数据接口

| 文件 | 内容 |
|---|---|
| `scene_plan_<规模>_seed<种子>.json` | 每个场景的桌面、任务、候选、稀疏 F、所有方法的完整方案与校验 |
| `service_schedule.csv` | 全部场景、方法的逐任务服务清单，按实际访问顺序排列 |
| `metrics.csv` | 每个场景×方法一行的原始指标 |
| `summary.json` | 按规模与方法汇总的均值、完整覆盖和校验状态 |
| `run_manifest.json` | 参数、种子、方法、源代码哈希、北京时间和完成状态 |
| `environment.json` | 实际 Python/库版本、平台及计时口径 |
| `edge_case_tests.json` | 四种方法的空任务和机械臂不可达测试结果 |
| `scales.png` | 每个规模第一个种子的路径概览 |
| `route_<规模>_seed<种子>.png` | 每个规模第一个种子的单场景路径图 |

CSV 使用 UTF-8 BOM，便于 Windows 软件读取。服务清单包含规模、种子、方法、访问序号、候选 ID、任务 ID、桌编号、L/R、任务三维坐标、停靠 x/y/theta/h、到达该站时的累计路程。累计路程不是预计到达时间。

JSON 中各方案的主要字段：

| 字段 | 含义 |
|---|---|
| `status` | `complete` 或 `partial` |
| `visit_order_candidate_ids` | 服务停靠点的执行顺序 |
| `service_stops` | 各站的序号、停靠位姿、累计路程、待服务任务与用臂 |
| `assignments` | 每项已服务任务对应的停靠点及用臂 |
| `route_polyline` | 包含起点、全部中间导航点和返回点的二维折线 |
| `route_leg_costs_m` | 起点→各服务站→返回起点的逐腿路程 |
| `unserved_task_ids`、`unserved_reasons` | 保留的未完成任务及原因 |
| `validation` | 求解后独立代理检查结果 |

`feasible_tasks` 只统计存在机械臂代理可行候选的任务；`reachable_tasks` 还要求至少一个可行候选能从起点往返。`coverage` 的分母是所有原始任务。部分方案的短路程不能与完整方案直接比较优劣。

`scene_s`、`reachability_s`、`navigation_preprocess_s`、`solver_s`、`validation_s` 分别记录场景生成、可达关系、导航预处理、求解、独立检查。`total_s` 是这五项之和，不包含导入、绘图、序列化和写盘。同一场景的预处理只执行一次，但每种方法的 `total_s` 都计入这份共同成本。

## 独立复验与测试

校验器仅使用 Python 标准库，不导入规划器、NumPy 或 SciPy。它重新读取并检查方案，不信任 JSON 中已保存的 `validation` 布尔值。

复验本次交付的 80 份方案：

```powershell
python validator.py results_20261102_v2
```

复验其他目录并保存报告：

```powershell
python validator.py results_custom --report results_custom/independent_validation.json
```

也可以直接传入单个 `scene_plan_*.json`。校验包括任务唯一分配、有效 ID 和用臂、代理可达性、访问顺序与逐腿终点、闭合路径、静止点及路径段碰撞、路程与目标值、服务位姿和服务清单一致性。非有限数值和缺失字段会被拒绝。

校验器独立重算每项已分配任务的球壳与扇形条件。它核对逐腿路程与输出折线的记录一致性，**不会重新运行最短路算法，也不是 IK 或机械臂碰撞验证器**。

运行行为回归测试：

```powershell
python -B -m unittest discover -s . -p test_baseline.py -v
```

本次 16 项测试全部通过。其中篡改测试覆盖 14 种非法记录；其余测试包括空任务、机械臂不可达、导航断连、碰撞候选剔除、起点碰撞、零代价服务、2-opt 的覆盖保留和已知交叉路线改进，以及命令行输出、未完成状态和覆盖保护。

`valid_model_plan=true` 表示满足已声明的代理与记录约束；只有同时 `all_tasks_served=true` 才表示完成全部任务。规划与复验命令完整成功时退出码为 0，参数错误、方案非法或任务未全部完成时为 2。

## 接入真实模型的边界

当前没有末端姿态约束、关节限位、IK、机械臂与环境碰撞、双臂同步干涉、连续关节轨迹或真实收拢包络验证。导航只验证底盘代理包络；服务按单臂独立、顺序操作理解。

可以在保留规划接口的前提下，把 `make_scene` 和 `feasibility` 替换为真实场景及前两部分生成的可达性数据。接入真实 F 时还必须同步更换校验器中的代理可达性复算依据；不能继续把球壳/扇形当作真实模型的独立证明。Python 数组下标与当前任务、候选 ID 一一对应，外部不连续 ID 需要显式映射。

若后续增加同步双臂协作，应输入已经验证的局部服务方案及其服务时间；仅有左右臂分别可达仍不足以判断协作合法。当前版本没有局部服务方案生成器、升降优化、容量约束、在线任务到达或神经网络训练。
