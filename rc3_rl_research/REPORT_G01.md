# G0/G1 完成报告

日期：2026-11-03。依据用户最后的第一阶段要求，本轮完成**具有非单调探索能力的可重放搜索环境，以及预先固定的 32 个百桌开发状态的多步诊断**。没有训练 BC/PPO，没有新增网络检查点，也没有改变 v4/v5/v5.1 的默认规划入口或历史实验结论。

结论：G1 的工程验收通过；G0 在有限菜单、深度 3 的范围内发现可复核的多步机制信号。它支持继续研究多步决策，**尚不支持 PPO 优于强规则、非单调探索普遍必要或部署规划更快的主张**。独立判定另见 `EXPERIMENT_RESULT_TO_CLAIM.md`。

## 实现的实质变化

1. 三层分别处理：新 replace 修复器能够返回较差可行提案；新环境按 `J≤J_best+0.02J_anchor` 接受 current；新运行器只认证和返回 best 或 anchor，不再追加旧运行器的 current 单调限制。原 improve 仍保留严格即时改进语义。
2. F/D 独立复制且数组不可写，外部输入贯穿使用 F∩A；必须重做的任务来自整个保留路线。局部禁用只影响当次候选池，完整路线规范化、覆盖检查与导出分工使用同一约束。
3. anchor/current/best、菜单与动作掩码、尝试历史、随机状态、预算、奖励和最终输出分开保存。每个提案认证，终止再认证 best；失败回退并修正奖励。STOP、horizon、工作预算是真终止，收集截断保留 bootstrap。
4. 随机、廉价 detour 贪心、简化自适应算子参考共用一个菜单与修复接口，只查询选中的动作。没有免费试遍全菜单；没有 proposal 缓存或隐式禁忌。后者目前是接口参考，不应当作已经调优的强 ALNS。

固定源码参考为 NeuOpt、CleanRL、RL4CO 的 3 个提交、12 个文件；采用 current/best 分离和可重放多步存储的思想，未直接套用构造式单步 PPO 或混淆终止/截断的代码。依据与精确代码链接在 `OPEN_SOURCE_NOTES.md`。

## 质量改善与预算奖励必须分开

加入预声明的工作罚后，补充描述性重算得到：

- 24／32 场景的已查询叶序列中，至少一条总回报高于根状态直接 STOP。
- 在 18 个严格质量见证场景中，10 个存在同样满足严格见证条件且回报高于 STOP 的序列，即全体 **10／32**。

这两个数来自保存账本的补充统计，没有替换预注册的 J 指标，也不是新增调参结果。它们表明质量收益未必抵偿计算成本，训练目标的尺度需要继续核查。

编号最早的严格见证为 case_01：100 桌、177 任务、800 候选点，seed=1854398144，动作索引 `[1,2,2]`。成本轨迹为：

`267.625042 → 268.563973 → 267.284244 → 266.318222`

根节点已查的一步最好值为 266.345313。所选序列最终质量奖励为 +0.488303，工作罚为 0.704733，总回报 −0.216430，低于直接 STOP 的 −0.171414；还存在相同终值的非变差首步分支。本例清楚展示后效，也清楚展示证据边界。曲线、表格和源数据指针见 `MECHANISM_CASE.md` 及 `outputs/mechanism/`。

## 工作和时间的记账范围

正式树诊断实际构建 12,800 次菜单，菜单计数 2,037,572,799 单元；提案计数 60,333,004 单元；搜索内认证 25,568 次。菜单与提案单位分别按上下文/候选扫描、DP 有限状态/转移等定义，**不是 FLOPs，也不能据数值比例直接推断 CPU 时间占比**。初始化与认证耗时另记。

树搜索不同分支复用可信内存前缀，物理 oracle 工作只对实际发生的构造/提案记一次；每条反事实 episode 仍按其路径收费。选定序列的第一次重放另执行 96 次提案；最终交付重放、独立原记录审计、G1 回归和机制制图各有单独回执，不混算成独立新场景。冻结前 case_00 的调试运行保留了全部 456 次查询与额外重放，另列在 `outputs/execution_accounting.json`，不进入正式 32 场景统计。

菜单或修复是原子操作，可能越过剩余额度，本实现明确属于**软工作预算**。可选时间上限也为软期限。32 个场景用四个独立分片加速离线诊断，没有把并行 oracle 的时间当作单策略部署速度。

本次环境 horizon=16，而有限诊断在深度 3 截止；step 已为下一观测构建的菜单在终止时照实收费，因此图中 End 存在额外费用。已知终止点之后避免无必要菜单构建，是后续可检验的工程优化；不能在本批已完成记录中追溯删除这部分实际工作。

## 后续应推进到哪里

当前可交付的是环境与机制证据。继续训练前，应固定同动作强规则的重复尝试处理、检查菜单成本与奖励尺度，并用独立开发配置比较冻结 BC、继续 BC、同初始化 BC＋多步 PPO。网络应获得导航关系和覆盖关系；时间比较包含预处理、初解、候选、策略、修复及验证。最终泛化测试需新的独立场景，不能把本轮已检视的 32 场景再当确认集。
