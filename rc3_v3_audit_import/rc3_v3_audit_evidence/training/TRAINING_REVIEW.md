# v3 训练、标签、STOP 与表达能力审计

## 判断

本版确实修正了v2只对初解监督的问题，也确实修复了旧STOP类别竞争造成的过早停止。正式模型是**多状态、即时收益监督的MLP**，不是新的PPO模型。当前失败点已经不能简单归因于“没有中间状态”“没训练够”或“STOP仍然过早结束百桌规划”。

独立离线诊断显示：模型在训练初解上已经学会了相当强的一步排序，但到验证初解上明显退化；同时，当前28维统计观测遗漏了替代候选进出窗口的导航距离。我们用原始环境和修复器构造出**所有观测完全相同、真实收益和STOP标签却相反**的两个抽象实例。这给出了比继续增加网络规模更直接的改进方向。

建议先验证显式利用候选覆盖与进出距离的廉价评分或可行修复下界。如果这种确定性评分已在同预算下达到目标，则保留无学习方案为研究主方法；只有在仍存在稳定、足够大的选择差距时，再研究学习预测这一剩余差距。本次审计没有重新训练、改动上传源码或利用冻结测试标签调参。

## 1. 正式轮与探索轮是两次监督训练

源代码位置：`train.py:19–39` 为监督损失；`train.py:95–149` 为六次训练和验证选模。两种架构分别采用三个种子，每轮384状态、batch16，共24次更新；每种子80轮，正式轮更新数为：

`2 architectures × 3 seeds × 80 epochs × 24 updates = 11,520`。

旧 `run_v3_20261102` 同样11,520次更新，仅用于STOP诊断。正式 `run_v3_stopfix_20261102` 重新训练并冻结。两轮合计23,040是**监督参数更新次数**，不能与v2的PPO环境动作数混为一谈。

| 项目 | 旧探索轮 | 正式STOP修复轮 |
|---|---|---|
| 输入schema | rc3-v3-budget28 | 相同 |
| 训练数据 | 同一个data.pkl | 同一个data.pkl |
| STOP训练 | 与窗口共用类别softmax | 独立全局二分类BCE |
| STOP推断 | 与单个窗口logit竞争argmax | sigmoid概率≥0.9才停止 |
| 最佳模型 | MLP seed43 epoch30 | MLP seed29 epoch70 |
| 验证平均降本 | 0.8175775% | 1.0016177% |
| 验证平均修复调用 | 5.6667 | 8 |

从旧源码快照 `source_before_stop_fix.zip` 与现有源码逐行比较，主要差异符合上述STOP修改，没有把探索轮测试结果冒充正式轮的迹象。旧检查点加载会保留`categorical_argmax`，正式模型元数据明确为`binary_threshold`。

正式部署NPZ为59,744字节（58.34 KiB，约60 kB）。由数组重新计数得到14,596个可训练参数；均值/方差缓冲区另有56个元素。正式选中MLP结构为28→64嵌入、两层64维逐窗口MLP，以及rank、gain、positive、stop四个输出部分。gain/positive为辅助监督，部署选择实际使用rank与stop，不能将它称为完整任务—候选图网络。

## 2. 数据确实包含中间状态，但独立样本量仍是96个场景

`data.pkl`先经pickle opcode检查，再使用严格白名单读取：只允许NumPy数值dtype、数值scalar、数值buffer重建与Counter。未执行任意pickle全局，未导入PyTorch。

独立统计如下：

| 项目 | 实际数量 |
|---|---:|
| 训练场景 | 96，全部100桌 |
| 验证场景 | 18，全部100桌 |
| 保存状态 | 384，每场景4个 |
| step0状态 | 48 |
| step>0状态 | 336 |
| 不同(scene_id, route) | 267 |
| 路线确已相对初解改善的状态 | 259 |
| step0至step7 | 各48 |
| oracle/detour/random来源 | 各128状态 |
| 有正收益的状态 | 349 |
| 全零收益状态 | 35 |
| 合法窗口标签 | 30,200 |
| 正收益窗口 | 4,353，14.414% |
| 零收益窗口 | 25,847 |

每个场景运行一条8步轨迹，按scene_id轮换三种教师，并保存奇数步或偶数步。不是每个场景分别运行三条教师轨迹。后续状态可以只改变mask与剩余预算而路线不变，因此384不能写成384条独立改善路线，更不能把30,200个重叠窗口标签当成30,200个独立场景。

这次已经补足“只有初解”的明显缺口。仍然只覆盖三种教师访问的状态，没有收集当前学习策略访问状态作为监督。但初解上的训练/验证差距也很大，说明当前问题不能只由中间状态分布差异解释。

重新计算合法训练窗口特征的mean/std，与正式NPZ逐元素差为0；正标签90%分位数`gain_scale=0.6853467226028442`，负/正权重比`5.937744084539398`也准确复现。data.pkl SHA-256与训练摘要声明相同。

### 划分与泄漏

缓存仅包含train与validation场景、训练states；测试只有外部case元数据。三份case清单种子两两不重叠。缓存场景seed顺序与训练/验证清单一致。训练标准化、标签、损失只使用训练states；验证场景用于完整路线选模。未发现当前实现直接读取测试标签或测试成本用于拟合的证据。

静态哈希和代码不能独立证明所有历史人工操作。需要区分**无直接测试泄漏证据**与**模型选择的不确定性**：同18个验证场景被用于六次训练、每次多个epoch的选择，又用于STOP方案诊断。冻结测试才是独立效果证据，18个验证上的最优数不能视作无偏性能估计。

## 3. 新增离线诊断：一步排序在验证初解已经退化

我用正式NPZ实际重放了18个验证场景的8步路线，精确复现平均降本1.0016177256%。对模型实际访问的144个状态额外计算所有合法窗口的真实修复收益，使用全路线缓存，共增加4,881次标签求解。这些是**离线诊断开销**，没有计作模型推断速度。

为避免“训练教师轨迹与验证模型轨迹不同”的混淆，先只比较step0，即从Fixed3初解出发、尚未进行任何局部修复的状态：

| 一步选择指标 | 训练初解48状态 | 验证初解18状态 |
|---|---:|---:|
| 有可改善窗口的状态 | 48 | 17 |
| MLP选中正收益的比例（仅可改善状态） | 85.42% | 41.18% |
| detour选中正收益的比例 | 39.58% | 47.06% |
| MLP捕获的一步oracle收益比例 | 65.12% | 19.52% |
| detour捕获的一步oracle收益比例 | 11.47% | 32.24% |
| MLP所选窗口的平均实际收益 | 0.55716个百分点 | 0.14072个百分点 |
| detour所选窗口的平均实际收益 | 0.09812个百分点 | 0.23237个百分点 |

“捕获比例”计算为这些状态所选收益总和除以各状态最大一步收益总和；不是全局最优差距，也不是最终整条路线的改善。以上为描述性诊断，不将同场景的多个窗口当成独立样本进行显著性检验。

对全部384训练状态，MLP在349个可改善状态上正收益命中78.80%，捕获一步oracle总收益60.85%；对144个验证模型状态，相应为32.35%与18.88%。在相同验证状态上查询detour，一步捕获比例为29.86%。

注意：在MLP轨迹上的detour一步反事实评分，不等价于detour独立运行8步的最终结果。已有完整验证rollout显示MLP 1.0016%高于detour 0.62894%；这与一步指标不矛盾，因为动作改变后续状态。论文应分别报告选择质量与闭环最终目标，不能相互替代。

直接改用已有gain头或positive头选最大，并未得到改进：在同144验证状态上，rank平均一步收益0.12520个百分点，gain头0.08189，positive头0.08248。因此不存在目前证据支持的“换一个现成输出头即可胜出”的修复。

这些结果支持继续研究**泛化与信息表达**，不支持把当前负结果笼统解释为完全没有学会排序，也不支持仅追加相同数据上的epoch。

## 4. STOP：旧问题真实存在，正式百桌运行中该功能基本未启用

旧验证诊断针对attention seed17：18例中13例提前STOP，其中12例仍有正收益窗口；关闭STOP后平均改善从0.74677%升到0.91346%，调用从5.611升到8。旧规则把一个全局“无改善”类别与许多单窗口类别竞争，窗口概率分散后即使仍有改善，也可能使STOP成为最大单类。

正式版改为独立BCE并设0.9阈值，确实解除了这种类别竞争。正式六个选中检查点在18验证均运行8步，stopped=0。

进一步检查正式部署模型：

- 384训练状态中35个全零状态，STOP一个也没触发；训练最大STOP概率0.74772。
- 144验证状态中8个全零状态，STOP一个也没触发；验证最大概率0.40151。
- 35个训练全零状态中34来自oracle轨迹、1来自random、detour为0；它们集中在20个场景，31个出现在step4以后。

所以百桌上的当前排序不足不能继续主要归咎于“STOP过早停止”；阈值0.9在这些样本上使STOP实际上不起作用。保留35个全零状态是必要修正，但不能据此声称已经学会有效的停止策略。降低阈值也不是自然答案：概率在训练和验证间的分布明显变化，且下面的观测反例说明有些STOP真值根本无法由当前输入辨识。

此外，`diagnose_stop.py:23`仍直接对logits做categorical argmax。其已保存报告针对旧模型，因此旧诊断成立；若未来用这个脚本检查正式binary模型，会绕过其0.9阈值，应明确它仅为历史脚本或改成按`policy.select`调用。这个工具问题未污染本轮正式测试。

## 5. 可复现的信息缺失反例：相同28维观察，真实收益不同

见 `observation_aliasing.py` 与 `observation_aliasing.json`。

构造三个任务与四个候选，当前服务路线为`0→1→2→3→0`。候选1、2、3分别覆盖三个任务；未选候选4同时覆盖前两个任务。所有候选位姿与覆盖矩阵F完全相同，停靠惩罚均为0.75。

导航图的主链为`0—1—2—3`，每条边长度1；候选4从节点2分支连接。实例A的分支图距离为0.1，实例B为10。D为各自树上的最短路矩阵。两个D均有限、非负、对称、零对角，且通过三角不等式检查。当前路线上的所有距离相同，参考目标均为8.25。

两个实例经原始Env输出的**全部3×28特征和合法mask逐元素相同**。但调用原精确修复器：

- A三个窗口的收益为`[0.55, 0, 0]`。
- B三个窗口的收益为`[0, 0, 0]`。
- 因此“是否应该STOP”的真标签也相反。

这是抽象F/D模型的信息反例，不声称已在当前随机测试场景发现相同观测碰撞，也不是实机反例。它证明：只看现有窗口统计，没有包含替代候选相对窗口入口/出口的导航成本，无法普遍确定真实修复收益。将同一观察送入更大的MLP或Attention，仍不能同时正确区分这两个实例。

优先补的信息应围绕实际子问题：候选对required任务的覆盖、`D(entry,candidate)`、`D(candidate,exit)`以及候选间必要距离。可以先用廉价单/双候选可行替换成本检查这些信息是否能稳定改进选择，再决定是否值得将其交给网络。

## 6. 当前训练目标的准确边界

rank目标是合法窗口即时收益平方根的归一化分布；另有收益回归、正收益分类和全零状态STOP分类。它不是未来多步回报、也不是单位计算时间收益。补入剩余预算特征不等于模型已受监督学习了多步最优预算分配。

平方根变换不改变理想目标分布的最大值排序，因此不能单凭用了sqrt就宣布损失错误；它会减小大收益与小收益动作的相对差距，是否影响有限模型需消融。当前记录不能把泛化不足唯一归因于这个损失，也不能断言替换为PPO会改善。

MLP每个窗口独立编码，STOP再做均值池化；Attention能交互窗口统计，却同样没有被提供上述关键候选距离。应先把“输入缺少什么”与“采用什么架构”分开。已有模型中MLP验证稍好、模型更小，可以作为当前记录的选择，不足以推论MLP普遍优于Attention。

## 7. 是否继续学习

建议当前冻结v3，将其作为学习效果受限的完整基准。后续只做一个有明确退出条件的诊断：使用同一Fixed3初解、候选窗口、修复器、验证器和预算，让廉价几何/覆盖评分直接利用候选进出距离。它若在同硬件下达到或超过MLP的质量—时间表现，应优先采用该无学习模型，完成用户的快速可靠规划目标。

只有当“廉价结构评分”与“离线选择器”之间仍存在稳定且值得优化的差距，才继续学习；学习对象应是该剩余差距、候选剪枝或计算分配，且需要新的冻结测试验证独立收益。不要把已查看冻结测试再次当成模型选择依据，也不要默认制造第四版训练来追逐一个更好的表格数。

本目录结果均为只读审计生成。没有修改原训练数据、原权重、原实验结果或上传代码；没有重新执行训练。对应JSON和脚本提供统计及反例复现入口。
