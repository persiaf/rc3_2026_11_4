# Two-stop 可行收益规则：验证集探索诊断

## 目的和边界

这次诊断检验一个具体方向：利用替代停靠候选间的真实图距离，为局部窗口计算一个廉价的可行改进信号，是否足以比几何绕行规则更有用。它不是新增训练，也不是新的正式测试。

只使用原 18 个百桌验证场景，全部预先指定，未读取 60 个测试场景。比较原 Detour、原冻结 MLP 和新规则，各场景各方法一次完整计时，方法顺序按 seed 随机交错；每种方法上限均为原来的 8 次精确 DP 修复。新规则额外扫描候选的工作全部计入模型/排序阶段与完整规划时间，因此“同 8 次 DP”不意味着相同总计算量。

原始项目代码、模型及数据未更改。脚本只在当前独立 Python 进程中临时绑定 runtime 所创建的环境，使规则可以读取当前路线；离开该调用即恢复原类。

## 规则数学定义

对窗口 W，先按原 `_local` 确定失去外部覆盖的任务集合 U、可用候选 P，以及固定入口 a、出口 b。原片段费用为

\[
C_{\mathrm{old}}=\sum_{(u,v)\in W\text{含入口出口}}D_{uv}+\lambda |W|.
\]

考虑所有能覆盖 U 的零、一个或两个不同停靠候选，计算：

\[
C_{\le2}=\min\{D_{ab},\ D_{aj}+\lambda+D_{jb},\ D_{aj}+D_{jk}+D_{kb}+2\lambda\}.
\]

每项仅在对应覆盖条件成立时进入最小值；空 U 才允许零停靠，双候选要求 j≠k 且联合覆盖 U。若没有合法零/一/二停靠方案，收益记为零。排序分数为

\[
g_{\le2}=\max(0,C_{\mathrm{old}}-C_{\le2}).
\]

有正分时选择分数最大的窗口，同分用原 detour 特征打破平局；全零时完整退回 detour。随后仍调用原精确局部 DP，不用这条短序列替换修复器，也不因分数为零而剪枝。

这是可行替代方案带来的**可实现局部改进下界**，不是所有动作收益上界。原 DP 允许更多停靠，外部规范化也可能进一步删减冗余点，分数为零不等于没有改进空间。

## 实际结果

所有 54 次最终计划均再次独立复验通过，任务完整且成本不超过 Fixed3。144 个所选分数与实际 DP 改进的下界检查全部成立。

| 方法 | 相对 Fixed3 平均降本 | 完整规划中位 | 排序阶段中位 | 平均 DP 调用 |
|---|---:|---:|---:|---:|
| Detour | 0.62894% | 348.72 ms | 0.11 ms | 8 |
| 冻结 MLP | 1.00162% | 365.91 ms | 6.05 ms | 8 |
| Two-stop 可行收益 | 0.66893% | 448.88 ms | 75.21 ms | 8 |

新规则相对 Detour 的平均成本下降仅 0.04014%，2 胜 / 15 平 / 1 负；相对 MLP 为 -0.33777%，4 胜 / 2 平 / 12 负。总诊断约 26.3 秒。

新规则的 144 次动作中，仅 **3 次**存在正的 two-stop 可行收益；另外 **141 次**最终仍按 detour 选择，但已经支付额外候选枚举时间。实际完整 DP 有 34 次正改进。这说明零/一/二停靠的廉价可行收益在这套强初解上非常稀疏，尚不足以支撑新的部署方法。不能因能够编码真实候选距离，就假定这条具体规则必然有效。

这是应当保留的负结果。它没有否定更充分的候选图表示可能有用，也没有证明原 MLP 泛化占优；这 18 个验证场景本来参与了 MLP 检查点选择，而且每方法每场景只计时一次。当前 Linux 计时与原 Windows 冻结测试不能直接比较。

## 重跑

将 `--source-root` 指向包含 `rc3_v3`、`rc3_improve`、`rc3_fast`、`rc3_baseline` 的原项目目录。输出必须是新目录：

```bash
python -B run_diagnostic.py --source-root /path/to/project --output diagnostic_repeat
```

结果：

- `results/case_metrics.csv`：54 个完整方法×场景记录。
- `results/summary.json`：汇总、对照、范围及来源哈希。
- `results/details.json`：原 runtime 轨迹、额外独立验证、144 个下界检查。
- `results/rule_coverage_diagnostic.json`：正分稀疏度及回退计数。
