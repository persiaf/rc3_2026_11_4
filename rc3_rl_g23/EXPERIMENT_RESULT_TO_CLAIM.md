## 1. 预登记的主张与实际结果

主问题是在同一合法动作、可行修复、预算与完整计时接口下，多步价值策略能否取得一步模型、规则以及无多步更新控制无法达到的实用增量。质量主门槛预先固定为：对以下五个比较对象，场景配对平均相对 J 改善至少 0.3%，且 95% 场景配对区间下界大于 0；返回方案全通过代理终验，且完整 0.8 秒软预算不得超限。J = 路径长度 L + 0.75 × 停靠数 K。

改善定义为 `100 × (J_comparator − J_multi) / J_comparator`。先在每个场景内对三训练种子和两次重复取均值，再以 **6 个独立新测试场景**为配对单位；180 次规划、36 个多步测量、修复步数均不是 180/36 个独立场景。

| 比较对象 | 平均改善 % | 95% 场景 bootstrap 区间 % | 达 0.3% | 区间支持正增益 | 主比较通过 |
|---|---:|---:|---|---|---|
| 同接口规则 | −0.266142 | [−0.527839, −0.062637] | 否 | 否 | 否 |
| 匹配一步净价值，可反复决策 | +0.051727 | [−0.099376, +0.225242] | 否 | 否 | 否 |
| 冻结 MC0 初始化 | +0.181418 | [+0.020492, +0.352293] | 否 | 是 | 否 |
| 等更新静态规则价值 | +0.159416 | [+0.020492, +0.299920] | 否 | 是 | 否 |
| 原 Detour16，受本轮完整软时限 | −1.088416 | [−1.696707, −0.517212] | 否 | 否 | 否 |

上述 10,000 次场景 cluster bootstrap 与执行侧 analysis.json 逐项一致。审查另枚举全部 6^6 = 46,656 个场景有放回重采样：区间小差异不改变任何门槛判定；详见 trace 中 independent_recalculation.json。没有针对结果挑选更有利的区间、统计单位或主目标。

180/180 份保存方案的代理验证记录有效，未发现 fallback，所有返回 J 均不高于同场景 Fixed3。独立保存记录复算核对了折线路长、分段路长和、J、K、任务唯一分配及 service_stops 一致性；场景碰撞与可达性独立重验由执行侧 plan_validation.json 提供，本审查不把算术检查冒称另一轮运动学验证。

**105/180 次完整规划超过 0.8 秒**。多步模型自身为 14/36：seed2301 为 2/12，seed2302 为 12/12，seed2303 为 0/12。即使只把超时约束限定到提出的方法，也不能通过。没有移除超时、失败或重复样本。原 Detour16 为最多 16 次修复的部署参照，最终测试实际 176 次修复，不能把其本轮每条轨迹均称为完成 16 次。

## 2. 规则可表达性与操作接受语义

12 个旧开发场景仅用于接口审计。原规则记录 192 次修复；同接口规则在共享资源允许范围内累计匹配 **104 次操作**，各场景前缀长度为 7、11、5、8、12、7、7、12、8、8、7、12。审查逐项核对了 improve 窗口 start/end 与原参考对应关系、前后路线以及成本非增关系。原参考还保存 required/pool；相同问题、路线、窗口与同一 `_local` 定义使二者任务语义一致。

规则下一窗口被优先保留于至多 16 非 STOP＋1 STOP 菜单，不能再把该规则动作菜单外缺失解释成模型排序失败。结论仅是登记的 12 个场景和资源前缀可复现，**没有证明共享预算无条件重现原完整 16 步，也没有证明任意新状态下所有历史等价**。Fixed3 锚点而非规则候选的存在提供返还成本保底。

`repair_counted.py` 复用原 Dense 算法，仅插入工作计数。improve 原语只有严格降低当前 J 时才返回新路线，因此规则路径上它与原规则的严格改进接受条件一致。共享环境随后另做证书验证，允许的通用接受边界是 `J_proposal ≤ J_best + 0.02 J_anchor`；替代 replace 原语使用旧提案器，不能将所有动作都描述为严格改进或把 Dense improve 说成主动接受当前成本上升。历史最好路线独立保存并终验。

W=200 万是带当前原语结算的工作代理，不是墙钟或精确硬上限。接口审计的原语完结可能越过 W，12 个前缀最终 W 为 2,003,888–2,179,501，均有结算；不宣称硬工作限制。最终测试共享方法未发生 W 超限，主要限制来自完整时间。G23 另加入规则扫描和 Dense DP 计数，不能将其数值 W 与 G22 无条件等同。

## 3. 真实闭环、目标与匹配对照

实现确实超出一次静态标签表回归：round0 在规则继续策略下收集真实后缀并拟合 MC0；冻结完整 MC0 参数、阈值 0 与选择规则；round1 用此快照到达状态并再次采集真实环境反馈，然后更新新的多步价值策略。它是 **一次受封顶、近似策略评价与改进的闭环**，不构成收敛、单调策略改进或充分覆盖证据。

三种子各仅 4 个不同百桌训练场景，所有训练场景总数 12。两个阶段合计 132 个已查询首动作标签：各 seed 的 round0 均 24 行；round1 为 24、12、24 行。seed2302 的 MC0 提早 STOP，round1 只保留 4 个根状态，没有新的菜单状态键；seed2301/2303 分别出现 3/4 个不同于 round0 的菜单状态键。因此不能写成所有种子都充分探索了新后继状态。

每条目标仅监督已真实查询的合法首动作，未查询动作保持未知。后缀按被评价的冻结规则或 MC0 继续，未把混合探索后缀误记成统一的 Q*。完整有限时域 MC 使用 gamma=1，无 next-action-max 或额外 bootstrap；剩余 h 包含 STOP，终点无续值。环境持有精确历史、当前/最好路线与规则失败集；网络使用局部图、候选特征和预算/差值/历史摘要，不能声称其表示无损重建全部全局状态。

STOP 的相对优势固定为 0，绝对 STOP 后缀仍支付待结算菜单和终验修正。一步标签是“首动作实际转移后立即 STOP”的总返回减同状态实际 STOP，并非只用即时 r，也并非整条部署路径只许一次搜索。多步标签是相同首动作后按冻结策略的实际有限时域总返回减 STOP。

已登记的额外标签复核保存 132 行 STOP、one、multi、static 后缀，全部目标复现；本审查又独立累计其中 **2,067 条保存后缀转移**，核对奖励＝质量−W/10^6、目标与原始训练行、STOP 基线、J/W 总回报、同一首转移和 h 限制。没有未结清时间截断标签。复核新增 1,497 次非 STOP 修复已计入原 8,192 限额，没有新优化或测试选择。

`matched_static_rule_value` 与 `multi_policy_iteration` 均从同一 MC0 完整参数副本开始，使用相同 round1 首转移 D1、相同容量、相同 fit 随机批次、相同 256 次追加更新；区别是后缀按规则或冻结 MC0 评价。冻结初始化仅 256 更新，其额外训练量混淆由等更新静态控制补足。一步模型总 512 更新，同样首转移与容量；各 seed 五次 fit×256，总 3,840 更新。复算还核对保存 init 与 frozen_init 的全部张量逐项相同，round1 policy_id 与其内容摘要一致。

网络将左/右臂可达边分开送入两个 hidden=32、单步消息传递的 G2 graph encoder，再合成每候选数值优势，并叠加共享上下文数值头。复用类内名为 actor 的线性层不改变本轮训练语义：其标量被直接数值回归，没有 actor 分类概率或分类 logits 差冒充收益。左右臂是已有代理可达关系，不是新增 IK、同步协同、运动碰撞或真实操作时间模型。

## 4. 完整时间、资源与可复现边界

完整计时从新场景生成前开始，涵盖准备、图、菜单、网络、修复、独立终验及测量期间的全局记账 I/O。当前修复、提前生成的菜单与必要终验可以跨越截止，因此 0.8 秒是软限，所有越界按协议保留并使资源门槛失败。原部署参考采用相同外层截止；共享方法使用相同接口和允许缓存，没有新增跨方法预处理缓存。仪表化开销已经计时；这些时间适用于本轮实现，不能直接写成移除仪表化后的部署时延。

## 5. 数据支持、不能支持与路由

支持：规则候选及所测前缀的操作语义对齐；独立 STOP 相对数值价值与真实有限后缀；实际环境反馈参与的一次近似策略迭代；当前离散代理模型内返还可行性和 Fixed3 成本保底。多步相对冻结初始化/等更新静态控制的平均改善与正区间可如实作为次要探索证据，数值均低于 0.3%。

不支持：预登记质量主张、相对强规则/匹配一步的实用 RL 优势、替换默认部署规划器、完整 0.8 秒资源达标、稳定跨种子改进、收敛、越谷机制、跨规模/任意分布泛化、真实机械臂可行性或总任务完成时间更短。尤其 seed2301/2303 的多步最终测试 0 次修复并返回 Fixed3，seed2302 的正收益同时伴随 12/12 超时；不能择优只报告 seed2302。

缺少的证据是更充分独立场景、稳定跨种子增量、时限达标、真实机理/机器人验证及后续论文 claim audit。**这些缺口在本次止损规则下不授权追加当前方向实验。** 不触发 ablation-planner，不做跨规模扩充，不重新校准阈值或换速度目标。若论文必须以 DRL 为核心，服务停靠点、任务分组、访问顺序联合构造属于需独立立项与预注册的新任务，本报告不预言其成功，也不执行该转向。

建议论文措辞：“在规则动作对齐后的封顶试验中，我们实现了以冻结继续策略为基础的一次多步价值改进闭环，但六个新场景上的结果未达到预登记的强规则、一步学习与资源门槛，因此不将该局部窗口选择与停止模型作为主要 DRL 有效性结论。”
