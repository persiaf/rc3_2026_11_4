## 3. 为什么不建议继续盲目增加PPO轮数

### 3.1 多步PPO实现本身成立

原`train.py`保存真实每步观察、mask、action、old log probability和value，执行真实修复再产生后续状态。GAE在回合终止处正确清零，概率比使用已保存旧概率，clip为0.2，包含actor/critic/entropy更新。没有发现“单步分类冒充PPO”或旧概率错误重算的主要问题。

奖励为 `100*(J_before-J_after)/J_initial`，总和恰等于最终相对成本改善。它优化质量，不直接优化CPU耗时。

### 3.2 初始状态标签重复较多，中间状态标签为0

BC用了96个初解状态，其中95个有正收益。100轮训练主要重复这批状态；没有改进后路线的监督标签。475个正收益窗口占3,830个合法窗口约12.40%。独立重算的特征均值和标准差与检查点逐元素一致。

三个种子的BC最佳验证点都在第10/20轮，第100轮均更差；PPO最佳点也都早于第30轮。选中PPO相对选中BC只增加0.0046979个百分点验证改善。应增加训练状态多样性、检查搜索空间与预算表达，而不是直接追加相同数据上的epoch。

### 3.3 观察不是完整状态

完整有限时域状态应包含固定实例、当前路线、已尝试上下文和剩余预算。网络只看到24维窗口统计及mask，未显式输入剩余步数，也压缩了任务—候选覆盖结构。不能称其为充分Markov观察。建议增加剩余预算、相对参考成本、累计改善量；增加特征后必须升级schema并重新训练，不能把旧权重称为已学会新增信息。

## 4. 找到并修正的具体问题

### 4.1 仅按局部节点缓存会漏搜

原签名只含入口、窗口节点、出口。外部路线改变后，同一片段的必要任务可能变少，原窗口仍被屏蔽。

已运行的6任务、7候选反例：成本16.5的初解，先尝试前三停靠无改善；修复后半段后降为14.75。新后半段额外覆盖原片段的一项任务，再修原片段本可降为14.0，但节点签名未变，被旧mask屏蔽。

新签名为 `(局部节点, 必要任务IDs, 候选池IDs)`，且仅缓存确定性DP的无变化结果。F/D/惩罚/上限固定时，这些信息确定局部子问题。成功动作不永久缓存。这样既能让真正改变的子问题重新进入候选，也能保留未改变子问题的无收益记录。

最初探索过每次成功后清空全部缓存，但在8步预算下会浪费动作并使部分冻结模型结果变差，因此没有采用。探索数据保存在`development_history/`，不作为最终补丁结果。更准确的缓存也不保证每个学习策略在每例固定预算下都比旧mask好，仍需测量。

### 4.2 反复完整展开和验证占了大量时间

原Fixed3分别导出验证三条路线，即使某条成本更差。补丁先比较三条组合可行路线，按成本尝试独立验证最优者；正常情况一次验证即可得到Fixed3已验证参考。若验证失败会试下一个候选，没有可验证参考则明确失败。

局部搜索保留已验证reference；中间路线只是内部候选，先过组合约束与成本检查，最后再展开最有希望的候选并独立验证。失败时尝试已保存的其他候选或返回reference。没有将“未验证中间候选”交给执行端。

这支持最终方案可行及`J_out <= J_reference`，不意味着每个内部状态都能立即在实机执行，也不是硬实时算法。规则、BC、PPO统一使用这套机制。

原百桌PPO记录的模型推理总中位数约6.66ms，而候选验证约69.36ms，repair块约62.91ms（还混入特征重建）。网络并非最大开销。原Fixed3分量`candidate_validation_s=0`只是没有单独累计，并非没有验证成本。

### 4.3 BC命令可能误用PPO权重

原`plan.py --method bc`在未另指定checkpoint时仍指向默认PPO权重。原冻结测试使用不同权重路径，不受影响。本补丁为BC/PPO提供不同默认NPZ，并检查阶段匹配；阶段错误直接拒绝。

另用8个不重叠的百桌开发场景（seed4200000200～4200000207），对当前邻域进行诊断，48份计划全部验证通过。

| 初解与选择器 | 相对该初解平均成本下降 |
|---|---:|
| Fixed1＋随机 | 0.1365% |
| Fixed1＋几何规则 | 0.7348% |
| Fixed1＋逐步最佳即时窗口 | 1.4492% |

默认Fixed1的340窗口中5个任务超限、0个候选超限，最大池仅24。此处没有证据支持把候选cap从80增大作为优先项。步长2→1使正收益窗口43→83；宽3→4却使约21%～24%窗口超过8任务上限。因此应按必要任务数构造多种宽度/对齐窗口，而非一味放大窗口。

## 7. 数学模型与可证明性质

给定任务集合T、服务配置集合Z、可达张量F[i,j,a]、静态导航图G及其最短路距离D。对独立单臂任务，C[i,j]=max_a F[i,j,a]。当前目标为：

`J(route) = sum(D[route[k], route[k+1]]) + lambda * number_of_service_stops`，lambda=0.75等效米。

移除窗口W后，必要任务U为“其余保留停靠不再覆盖的任务”。保留路线已经覆盖其他任务，局部修复只需重新覆盖U。候选池包含原片段候选、覆盖U的可导航候选，并排除保留路线上的停靠。

局部DP状态`V[S,j]`表示覆盖U中任务子集S并结束于候选j的最低局部成本。初始代价`D[entry,j]+lambda`；转移`V[S union C[k],k] = min_j(V[S,j]+D[j,k]+lambda)`，要求增加覆盖；终值加`D[j,exit]`。

在非负最短路距离、非负停靠惩罚、独立任务且没有额外顺序/容量/同步约束下，零新增覆盖停靠可被最短路直接跳过，所以此DP在限定局部候选及固定端点内精确。时间复杂度O(2^q*m^2)、空间O(2^q*m)，q为必要任务数。它不是整张地图全局最优求解器。

最终可靠性来自：reference已通过独立验证；任何替代输出都必须完整合法、全部任务服务、成本与展开结果一致且不高于reference；否则保留reference。因此输出满足可行性及`J_out <= J_reference`。reference为Fixed1时只能保证不劣于Fixed1；reference为成功认证的Fixed3时才保证不劣于该Fixed3。

## 8. 下一轮推荐的最小研究路线

1. **冻结工程接口。** 使用本次精准失败缓存、统一最终验证，保留Fixed1/快速Fixed3部署选项。先明确完整时间预算与成本指标。
2. **只在训练集收集多步教师。** 从Fixed3初解开始，记录0～7次修复后的状态，混合教师、规则、当前模型轨迹；监督有效窗口和收益。当前96训练场景即可先形成最多数百个中间状态，实际数量以终止和去重为准。
3. **先做监督收益排序。** 沿用小注意力网络，或增加廉价MLP/树模型对照；学习即时收益/有效概率，保留无收益状态，加入剩余预算。若引入停止动作或时间惩罚，应明确新的优化目标。
4. **再扩大可用邻域。** 以必要任务数≤8控制窗口，使用不同对齐和宽度；先用便宜特征筛候选，再限制实际DP调用。不要把局部收益界直接当整动作上界：canonicalization还可能删除片段外冗余停靠。
5. **最后决定PPO投入。** 对已有监督模型作小规模微调，与同一初解、mask、修复器、验证和预算下的BC比较。若没有稳定额外收益，论文以监督引导修复为主，PPO作为消融结果。
6. **冻结新的测试清单。** 这次108例已经用于诊断，后续留作回归集。新正式结果保持100桌训练/验证，测试各尺度，分别报告固定DP次数、固定完整时间预算和质量—时间曲线。各训练种子单独评测，或事先声明验证选模协议；不能把方法×场景当独立场景。

训练应额外记录：每步正收益率、前k窗口收益捕获、剩余预算、每步成本下降、KL、clip fraction、entropy、critic误差/解释方差，以及DP与完整验证分项时间。先确认排序与状态覆盖有改善，再看总训练损失。

## 9. 三个研究内容的衔接

| 研究内容 | 应回答的问题 | 输出给下一部分 | 建议展示 |
|---|---|---|---|
| 一：升降双臂操作空间与任务可达性 | 什么底盘姿态、升降高度和用臂组合能服务任务？ | 候选配置、F或合法服务模式、可达裕度 | 高度/朝向/双臂可达域、真实IK抽样验证、约束消融 |
| 二：可达约束下的停靠与路线联合规划 | 选择哪些停靠、怎样排序才能完成任务并降低成本？ | 可行初解、强参考、小实例最优值或下界 | 分离规划vs联合规划、停靠数/长度、精确解差距 |
| 三：预算约束下的快速覆盖修复与跨规模迁移 | 怎样快速获得不劣参考的完整路径，学习如何有效分配修复预算？ | 最终验证路径、服务顺序和失败诊断 | 质量—完整时间、BC/PPO/规则消融、100→其他规模、错误模型回退 |

建议第三部分题目采用“面向大规模桌面任务的覆盖保持局部修复与快速规划”，待强化学习独立收益证实后再突出PPO。方法创新应落在机器人服务覆盖关系、局部子问题定义、预算分配和可验证保底，而不是“用了注意力＋PPO”。

当前机械臂仍为固定高度球壳/扇区代理；升降h没有真正参与肩部高度变换，独立单臂可达的并集不等于同步双臂可行。若有必须双臂同时操作的任务，需要离线建立合法联合服务模式，加入双臂互碰/对象姿态等约束；第三部分仍可只在二维场景训练，在线读取离线操作空间约束，不必训练关节动作。

论文应分开报告：模型内任务覆盖率、底盘导航/停靠执行率、真实机械臂操作成功率。当前648/648属于第一类。0.75等效米的停靠罚项也不直接等于真实执行时间；若目标是周期时间，需给出移动时间与站点服务时间模型或实测校准。

## 10. 运行方式

在本目录运行。独立补丁仅依赖NumPy、SciPy和threadpoolctl；无需安装PyTorch进行推理。原三种子训练仍使用用户原包的PyTorch代码。

```bash
python -m pip install -r requirements.txt

# 建议当前实际使用：快速Fixed3，输出JSON路径与CSV服务顺序。
python -B -m rc3_improve.efficient --method fixed3 --scale 10x10 --mode blocked --output my_results/fixed3.json

# 现有冻结PPO接Fixed3初解的研究接口：8次修复，最终成本不劣该已验证初解。
python -B -m rc3_improve.efficient --method ppo --reference fixed3 --budget 8 --scale 10x10 --output my_results/ppo_fixed3.json

# BC使用自己的权重，阶段误配会拒绝。
python -B -m rc3_improve.efficient --method bc --reference fixed3 --budget 8 --scale 8x8 --output my_results/bc_8x8.json

# 保持旧窗口mask，只比较延后验证的效果。
python -B -m rc3_improve.efficient --method ppo --legacy-attempt-mask --output my_results/ppo_same_mask.json

python -B -m unittest test_patch -v
python -B benchmark_patch.py --output patch_benchmark_repeat --cases 8 --repeats 3
python -B diagnose_neighborhood.py --source-root . --cases 8 --output neighborhood_repeat
```

也可用`--scene scene.json`传入原schema实例；无候选、导航断连、非法输入会保留任务IDs并返回明确失败状态，不会静默删任务或重采样。预算是修复次数，不是毫秒截止。固定代理高度以外的升降输入会被拒绝。

独立验证JSON文件：

```python
import json
from rc3_baseline.validator import validate

bundle = json.load(open('my_results/ppo_fixed3.json', encoding='utf-8'))
for name, plan in bundle['plans'].items():

```

无损重导出原权重：


## 11. 开源依据与适用范围

- [Learning to Delegate 官方代码](https://github.com/mit-wu-lab/learning-to-delegate)：学习局部子问题选择、传统子求解器修复；[supervised.py](https://github.com/mit-wu-lab/learning-to-delegate/blob/main/supervised.py)包含监督回归/排序设计。最直接支持本轮下一步多步教师与收益排序。
- [NeuOpt 官方项目](https://github.com/yining043/NeuOpt)、[NeurIPS 2023论文](https://papers.nips.cc/paper_files/paper/2023/hash/9bae70d354793a95fa18751888cea07d-Abstract-Conference.html)：灵活k-opt与学习改进路线。当前实现没有复现其专门动作分解、解码器或不可行区域探索，不能直接借用其性能结论。
- [POMO 官方项目](https://github.com/yd-kwon/POMO)、[原论文](https://papers.nips.cc/paper/2020/file/f231f2107df69eab0a3862d50018a9b2-Paper.pdf)：多轨迹与共享基线思路，不意味着本任务必须更换为POMO。
- [RL4CO PPO官方说明](https://rl4co.ai4co.org/docs/content/api/rl/ppo/)：所述自回归构造PPO把整个构造视为一步，不使用多步GAE；不能把该接口无修改套用到当前多步修复环境。当前自行实现的多步PPO已有代码依据。

以上来源用于方法定位，不作为本机器人实验的性能证据。当前项目应记录具体提交/hash；上游主分支可继续变化。
