# 第二版训练实现与检查点核查

本文件只依据上传的第二版代码、清单、训练日志及独立重算；未重新执行 PyTorch 训练。本环境没有 PyTorch，未安装额外深度学习运行时。检查点通过严格类型白名单读取张量，以 NumPy 实现单场景前向并复演动作。

## 结论

第二版实现了真正的多步、同策略采样、截断概率比 PPO。它不再是将一次分类或单步策略梯度称为 PPO。现有证据足以说明模型已训练、保存、重新加载，并在冻结测试中用于选择真实修复动作。证据尚不支持 PPO 比 BC 更有实际价值，也不支持将有效路线的保证归因于神经网络。

目前找到一个可运行反例证明的漏搜问题：已尝试窗口的缓存键只含局部路线节点；外部路线改善改变覆盖关系后，相同节点片段可能值得重新修复，但仍被屏蔽。这会损失改进机会，不会直接使保底方案失效。

## 1. 执行与数据证据

- 96 个训练、24 个验证场景均为 10×10；108 测试场景包含 4×3、6×6、8×8、10×10 各 24 个，12×12、14×14 各 6 个。三个清单的种子两两不交叉。
- 对结果清单声明的 18 个源文件、4 个数据清单和2个模型文件计算 SHA-256，24 项全部匹配。静态哈希能验证交付一致性，不能单独证明历史上从未查看测试数据。
- 优化器更新数可准确拆分：每种子 BC 使用 95 个正收益场景，每批最多 8 个，共 12 批；100 轮为 1,200 次 BC 更新。PPO 每轮 32×8=256 步、4 遍、每批 128 步，30 轮为 240 次更新。3 个种子合计 3,600 次 BC 更新、720 次 PPO 更新、4,320 次总更新。
- PPO 总回合数为 3×30×32=2,880，环境动作 3×30×32×8=23,040。它们反复采样固定的 96 个训练场景，不是 23,040 个独立场景。
- 选中的 BC 是 seed 17、第20轮；PPO 是 seed 17、第5轮；部署权重与选中 PPO 的哈希相同。每个模型有 76,994 个可训练参数以及48个特征均值/方差缓冲量。部署文件322,229字节，约314.68 KiB。
- 独立 NumPy 推理复演了4×3普通场景 seed600733272与10×10障碍场景 seed1711564331的 BC/PPO，共4次。8步动作序列、最终停靠序列、目标成本均与上传记录一致（成本容差1e-7），展开方案重新通过独立验证。不能据此声称本次重新执行了全部26个含 PyTorch 的单测。

详见 `audit.json`、`replay_and_audit.py`；训练初始教师标签重算详见 `teacher_audit.json`。

## 2. PPO 数学实现核查

对应 `train.py`：

1. `collect` 第13–32行：每个环境保存其真实当前特征/掩码、动作、采样时 log probability、value 和执行后的 reward；直到预算结束或没有合法动作。每次成功修复更新当前路线，后续动作面对新状态。
2. `advantages` 第35–45行：逐回合逆序计算 GAE，终止价值为零，回合间重置；当前问题是明确以8步预算终止的有限时域目标，因此这里的终止处理适用。不能在未来把外部截断直接当成自然终止而继续沿用零 bootstrap。
3. `ppo_update` 第48–70行：使用存储的 old log probability，概率比 `exp(logp-old)`，clip [0.8,1.2]，全批次优势标准化，value平方误差、0.01熵项与梯度裁剪。优化4遍小批次；属于 PPO 的合理实现。
4. rollout 为 eval 模式、更新为 train 模式，但编码器 dropout=0，也没有 BatchNorm；未发现由 dropout 差异破坏重要性比的情况。
5. rollout 的观察数组是拷贝，不会被下一次路线更新原地改写。更新时重新使用相同掩码，没有明显动作掩码错配。

没有发现“只训练 critic”“旧概率在更新时重算”“假多步”这类实现错误。另一方面，PPO 代码存在不等于 PPO 对这个问题有独立收益；性能必须由等预算对照证明。

## 3. 已证实的失效缓存：外部覆盖变化后错过可改善窗口

位置：`environment.py` 第43–45、56行。签名为 `[入口, 被移除候选, 出口]`，不含保留路线的覆盖状态。

最小反例使用一条直线上的非负最短路距离，停靠惩罚0.75。候选1位于x=5.5，覆盖任务0、4、5；候选2～7位于x=1～6，分别只覆盖任务0～5。初始路线为：

`[0, 2, 3, 4, 5, 6, 7, 0]`，成本16.5。

先尝试窗口 `[2,3,4]`，入口0、出口5；必须服务任务 `[0,1,2]`，精确修复不能降低成本，因此签名 `(0,2,3,4,5)` 进入 attempted。随后修复末端 `[5,6,7]`，得到 `[5,1]`，完整路线为 `[0,2,3,4,5,1,0]`，成本14.75。候选1在窗口外覆盖任务0，因此前一个窗口现在只需服务 `[1,2]`，可以删去候选2，得到成本14.0。可是局部节点签名未变，原代码仍将该窗口屏蔽。

`stale_attempt_counterexample()` 直接调用原始 `ImprovementEnv` 和 `repair_window`，没有模拟修复返回值。只对初解构造函数注入了已知可行初始路线。

修复选择：成功改变路线后清空 attempted，最简单且语义清晰；或者把 required任务集合、相关候选池/保留覆盖信息纳入缓存键。前者可能多花一些重复检查预算，应统一在 BC/PPO/规则/随机环境中应用并重新测量。新搜索环境的结果不能冒充原冻结模型在原协议下的测试数据。

## 4. 训练为什么可能已经平台化

### 已观测事实

BC只从96个训练初解取特征和逐窗口教师收益，没有改进后路线的监督状态。已独立重建全部96个训练初解：共有3,942个窗口，其中3,830个可执行，475个为正收益（约占合法窗口12.40%），95个初解至少有一个正收益窗口。重建特征的均值与标准差和BC检查点逐元素完全一致。PPO面对改善后的路线时，必须靠较少的在线交互弥补初始状态监督的分布差异。

| 种子 | BC最佳验证改善 | BC第100轮改善 | PPO最佳验证改善 | PPO第30轮改善 |
|---|---:|---:|---:|---:|
|17|0.920152%|0.657375%|0.924850%|0.844960%|
|29|0.820271%|0.728399%|0.863967%|0.839871%|
|43|0.840293%|0.675396%|0.876524%|0.810332%|

BC最佳检查点都在第10或20轮，三个末轮均低于最佳；PPO最佳也都不是末轮。因此继续增加相同数据上的轮数，没有现有学习曲线支持。过拟合、训练/推断状态分布差异等是可能原因，不能仅凭这些曲线断言唯一原因。

选中的 PPO 相对选中 BC 只在验证上增加0.0046979个百分点。三个种子训练不等于三种子测试：当前冻结测试只测试各阶段按验证集选出的 seed17。现有场景 bootstrap 不包括训练种子不确定性。

### 观测与有限时域

完整环境状态至少应包含固定实例、当前路线、历史尝试状态、剩余预算；对这个完整状态而言，转移是确定的。网络却只看到24维窗口统计及合法动作掩码，缺少剩余步数、参考成本以及完整覆盖/候选距离结构。不能把这个压缩观测直接称为充分 Markov 状态。

当前每步奖励为 `100*(J_before-J_after)/J_initial`，所以总奖励恰等于相对初解的最终成本下降。它是质量目标的有效奖励，并非公式错误。预算通过8步终止作用于回报，但网络没有显式看到还剩几步；相同当前局部特征在还剩1步与还剩8步时可能对应不同价值。奖励也没有包含 DP 耗时或墙钟剩余预算，所以它不会自动学出最快的规划策略。

仅接受改进动作使回报非负，但它仍不是独立的一步 bandit：一个修复可改变后续覆盖关系与可修复窗口，反例已经表明动作相互依赖。应保留多步研究可能性，同时通过多步教师、不同预算和同时间对照判断是否值得 PPO。

## 5. 建议改动顺序

1. 修复 stale attempted，完善检查点 phase 校验；统一所有方法的搜索/验证机制。保持已验证初解为兜底。
2. 在验证集先测局部搜索可达到的剩余空间：规则、随机、学习、逐步oracle必须共享窗口、修复器、初解与预算。若高预算局部oracle仍不及Fixed3，先改邻域/初解/修复能力，不应优先加训练轮数。
3. 增加状态分布而非重复同一批初始标签：在训练场景的多步修复中收集经过0～7步的状态，给未试窗口标收益；可混入规则、随机、当前策略形成的数据。新标签仅来自训练集，验证集用于方案选择，最终再冻结新的测试集。
4. 显式输入剩余步骤/预算、当前成本相对初解、已获得收益；如果研究重点确实是任务—候选关系，再引入稀疏二部图编码。先做小型消融验证这些变量的价值，不必立即加大网络。
5. 比较同墙钟预算或同质量目标下的时间。若增加耗时惩罚，需要声明新的权衡系数与硬件计时口径；固定8次DP调用不是相同毫秒预算。
6. 在继续投入 PPO 前，补充行为克隆、简单回归/排序模型的等预算对照。回归预测收益或改善概率可直接利用精确局部教师，未必需要复杂序列优化。可保留PPO为候选，不能预设它必须胜出。
7. 训练日志补充 KL、clip fraction、熵、value误差/解释方差、每步接受率与收益；当前写盘只保存混合loss、训练/验证改善率，虽然函数计算了KL，却没有写进 history。

这份核查的可重复证据与源代码路径均在同目录脚本和JSON中。对真实机械臂可达性、升降、同步双臂约束的结论仍取决于上游模型；这些训练统计不能代替硬件或真实IK验证。
