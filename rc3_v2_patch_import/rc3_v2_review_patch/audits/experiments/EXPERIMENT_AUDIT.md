# 第二版实验独立复核

## 复核范围

对象为上传的 `rc3_improve_delivery_v2.zip` 解包内容。本目录中的脚本只读取原始代码、清单、原始指标及计划，不修改上传目录。所有统计来自逐场景记录，未复训网络。

`audit_stats.py` 对每一组比较使用 20,000 次场景配对 bootstrap、随机种子 20261102。区间仅描述所冻结模型在测试场景抽样下的不确定性，不包含训练随机种子不确定性，也未作多重比较校正。

## 1. 数据协议与结果完整性

- 训练 96 场景、验证 24 场景均为 10×10 桌。
- 测试 108 场景：12、36、64、100 桌各 24；144、196 桌各 6。
- 训练、验证、测试三个清单之间的 seed 交集为空。
- 与上一上传包中可枚举的 2,049 个历史 seed 也没有交集。这个检查覆盖旧 `*cases.json` 和 `metrics.csv`，不声称覆盖没有落盘的历史尝试。
- 648 条方法×场景记录恰好对应 108 个场景×6 种方法。全部记录为成功且无回退；648 不能当成 648 个相互独立的场景。
- 评测 manifest 所列源码、数据、检查点的 24 个 SHA-256 全部与本上传包一致。
- 数据生成代码先写出测试清单，再生成训练标签；训练代码和清单支持本次冻结协议。静态文件本身不能独立证明所有历史操作的先后顺序。
- 评测 manifest 未直接列出 Fixed3 的 recipe IDs 或 `selector.npz` 哈希，虽然当前源码/随附模型解出的是历史选择 `[0,1,7]`。下一版应将固定组合也明确冻结到 manifest。

证据：`summary.json`、`hash_checks.json`、`prior_seed_overlap.json`。

## 2. 成本效果：学习有有限证据，PPO 额外贡献未证实

以下正数表示左侧方法成本较低，单位为百分比。

| 测试组 | 比较 | 配对平均下降 | 95% 区间 |
|---|---|---:|---|
| 百桌，24 例 | BC / Fixed1 | 0.8021 | [0.5519, 1.0675] |
| 百桌，24 例 | BC / 随机 | 0.4550 | [0.1239, 0.7470] |
| 百桌，24 例 | BC / 几何规则 | 0.2408 | [-0.0184, 0.5062] |
| 百桌，24 例 | BC / Fixed3 | -0.8385 | [-1.6490, -0.0994] |
| 百桌，24 例 | PPO / Fixed1 | 0.7814 | [0.5390, 1.0424] |
| 百桌，24 例 | PPO / 随机 | 0.4342 | [0.1055, 0.7268] |
| 百桌，24 例 | PPO / 几何规则 | 0.2201 | [-0.0234, 0.4718] |
| 百桌，24 例 | PPO / BC | -0.0213 | [-0.1309, 0.0795] |
| 百桌，24 例 | PPO / Fixed3 | -0.8595 | [-1.6672, -0.1205] |
| 小规模，72 例 | BC / 几何规则 | 0.0679 | [-0.0740, 0.2069] |
| 小规模，72 例 | PPO / 几何规则 | 0.0854 | [-0.0690, 0.2410] |
| 小规模，72 例 | PPO / BC | 0.0177 | [-0.0166, 0.0679] |
| 大规模，12 例 | BC / 几何规则 | 0.5652 | [0.3266, 0.8129] |
| 大规模，12 例 | PPO / 几何规则 | 0.5759 | [0.4354, 0.7278] |
| 大规模，12 例 | PPO / BC | 0.0095 | [-0.2013, 0.2065] |

判断：

1. 对相同局部修复预算的随机选择，BC 和 PPO 都有成本改善证据；不能把这些改善全部归功于 PPO。
2. 百桌与小规模上，BC/PPO 超过几何绕行规则的独立收益均不确定。
3. 较大规模的 12 个场景中，BC 和 PPO 都超过几何规则；这是值得保留的学习信号，但样本少、场景家族和物理参数未变，不能表述为任意规模泛化。
4. PPO 相对 BC 在三组中均无明确额外收益。
5. 目前 Fixed3 的组平均质量和组中位规划耗时均好于学习法；并非每个实例都优于学习法。例如百桌 PPO vs Fixed3 恰好 12 胜 / 0 平 / 12 负，后者胜出的幅度更大。
6. BC/PPO 在 108 场景中有 **93 个最终成本相同、91 个服务路线相同**，但动作序列仅 19 个完全相同。这支持“动作排序变化常落到相同局部终点”的诊断，不支持“PPO 根本没有更新动作”的说法。

证据：`group_statistics.csv`、`paired_comparisons.csv`、`bc_ppo_route_comparison.csv`。

## 3. 计时口径和真实热点

上传记录的百桌规划中位数为 Fixed1 48.45 ms、Fixed3 146.52 ms、随机 163.72 ms、几何规则 176.61 ms、BC 212.33 ms、PPO 193.36 ms。共享预处理另计，中位约 149.59 ms。PPO 冷地图总时间中位 329.78 ms。不能用不同分量中位数相加替代总时间的中位数。

评测每场景每方法重复 3 次并随机方法顺序，最终记录每场景中位数；模型已加载，进程启动和文件写盘排除。由这些场景中位数再求 P95，得到的是场景差异下的 P95，不是单一场景运行时抖动的 P95。

### Fixed3 有可避免的导出与验证开销

`rc3_improve/evaluate.py` 的 `run_method` 在第 43–44 行构造并完整导出验证 Fixed1；第 50–58 行又对 recipe 0 和 7 分别完整导出验证，甚至在成本不可能改善时也这样做。因此每次 Fixed3 正常运行有三次完整路径展开和验证。

上一版 `rc3_fast/planner.py` 的 `choose_and_solve` 先构造三条路线，用矩阵成本选择最佳者，最后 `Planner.plan` 只导出验证一次。这是两版计时差的重要原因；硬件、场景与口径也不同，不能直接宣称模型或求解器本体变慢。

在本次 Linux 环境中额外做了 3 个百桌场景、各 3 次的小剖析，各版本结果成本完全相同且验证通过：

| 模式 | 原 v2 三次完整验证 | 保留已验证 Fixed1，只验证最佳改进候选 | 旧式选择后一次最终验证 |
|---|---:|---:|---:|
| regular | 117.99 ms | 112.93 ms | 77.35 ms |
| mixed | 166.46 ms | 136.97 ms | 80.06 ms |
| blocked | 126.10 ms | 84.96 ms | 53.62 ms |

此为少量固定顺序执行的诊断，只用于证实开销来源，不作为替代完整基准或实机时限。第二列保留了已验证初解，第三列是历史执行方式的正常成功路径，保底语义不同，应明确区分。

### 网络不是首要延迟来源

百桌 PPO 的八步网络推理总中位约 **6.66 ms**，候选完整验证中位约 **69.36 ms**，记录的 `repair_s` 中位约 **62.91 ms**，初解完整生成另计。BC 的八步模型总中位约 6.71 ms，候选验证约 80.45 ms。先换更小网络不会消除当前大头。

`repair_s` 并非纯 DP 耗时：`environment.py` 第 69 行在 `step` 内调用 `observe()`，路线改变时会重算所有窗口特征；该调用被外层计入 `repair_s`。`feature_s` 因而低估全流程特征总耗时。下一版应分别记录 DP、特征刷新、路径展开、几何验证和初解构造，避免根据错误分解做优化。

Fixed3 第三条候选的记录 `candidate_validation_s=0`，是因为该分量只在局部改进分支累加，不代表 Fixed3 没有验证开销。总规划时间仍包含这些开销。

证据：`fixed3_profile.json`、`profile_fixed3.py`、`group_statistics.csv`。

## 4. 复验与当前证据边界

- 原始 `test_repair` 和 `test_reliability` 的 16 项非 Torch 测试在当前环境复跑全部通过。`original_non_torch_tests.log` 是完整日志；这不应写成当前环境重跑了全部 26 项或重新训练。
- `revalidate_saved.py` 对落盘计划忽略旧验证布尔值，重新计算几何、用臂、任务、服务事件、路线成本检查；同时由冻结清单重新生成场景比对任务和几何，并检查所有最终成本不超过同场景 Fixed1。最终结果见 `independent_648_plan_validation.json`。
- 所有几何结论仍只针对肩偏移球壳/扇形代理及膨胀矩形障碍的通道路径；没有真实 IK、机械臂轨迹避障、同步双臂操作或升降动作实机证据。

## 5. 下一轮优先级

1. 保持同一初解、同一修复器与同一终验语义，消除可避免的全路径重复展开验证，并给强基线同样的优化。
2. 同时报告等修复调用预算和等完整规划时间预算；8 次 DP 调用不等价于 Fixed3 的三次构造。
3. 在加长 PPO 训练之前，测当前邻域的可改善空间和学习选择能追回的差距。不要把局部动作空间本身没有优质解的问题当成训练不足。
4. 给 BC/PPO 相同且足够强的规则对照；需要保留随机规则，但增加随机动作轨迹种子才能量化规则自身的随机性，不能把不同随机轨迹当成新场景。
5. 若论文要主张训练稳定性，需对全部训练种子冻结的模型分别测试、报告场景和训练种子的不同不确定性；当前测试只对应各阶段按验证集选出的模型。
6. 这一轮已用于诊断和设计修改，下一轮正式结论应使用新冻结测试清单。旧 108 例可保留为回归集。
