# 外部接口共同可用臂分配补丁

## 修复内容

原第四版 `export_external` 优先使用规划表 F 允许的左臂。当 F 同时允许 L/R、复验表 A 仅允许 R 时，左臂分配被最终验证拒绝，尽管同一条路线使用右臂可通过。这属于**保守误拒绝可行解**。

本补丁只修改任务导出时的手臂分配：

1. 在已经选择的每个停靠点，计算 `common = problem.F[:, j] & audit_F[:, j]`。
2. 从共同允许的手臂中选取，仍在两臂皆可时优先 L。
3. 此站没有共同可用臂的任务继续保留，后续已选停靠点仍可服务它。
4. 全部任务分配后，继续由原 `validate_external` 分别检查 F、A、导航与记录，并实际执行 `service_checker`。回调拒绝或异常的语义不变；不会将另一臂未经回调确认地视为成功。

不改路线生成、规范化、目标函数、训练、模型、代理模式或其他文件。由于路线生成仍根据 F，补丁不提供全局完备性保证。

## 复现命令

在此目录运行，`--source-root` 指向含 `rc3_v4`、`rc3_v3`、`rc3_improve`、`rc3_fast` 和 `rc3_baseline` 的完整第四版源码根目录：

```bash
python -B test_external_common_arm.py --source-root /path/to/unpacked-v4 --output-dir results
```

依赖仅为现有 Python/NumPy 及原项目源码。程序先使用原模块构造反例，再在内存中加载本目录的修订副本运行测试，不覆盖上传文件。若只检查差异，可直接阅读 `external_common_arm.patch`。
