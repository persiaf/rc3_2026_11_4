# 冻结旧 MLP 的同预算描述性补充评测

本目录补齐原第四版没有执行的“冻结 v3 MLP vs Detour、400 ms 软预算”比较。补充方案在已知原第四版结果后确定，不能倒推、替换或放宽原第四版采用门槛。当前机器的结果与原 Windows 数据分开报告。

## 固定协议

- 精确读取原 39 个测试场景中的 18 个百桌场景，包括原保存的任务、桌面和候选；不生成新测试、不修改场景。
- 冻结原 v3 `policy.npz`，使用第四版已有 `LegacyMLPPolicy` 工程适配器。NPZ 原加载函数显式 `allow_pickle=False`，无 PT / pickle 加载，无训练、阈值调整或检查点选择。
- 直接复用原 `rc3_v4.evaluate.run_once` 和 `rc3_v4.runtime.run`。两方法均为 400 ms 软预算、256 次调用上限；每场景各 3 次，按原种子加 753911 生成的随机排列交错执行，共 108 次。
- 延续原 2×2、seed 130041 的开发场景预热。每个百桌场景公共预处理只做一次，预处理、模型加载、文件读取和结果保存均不进入规划计时。
- 规划计时包含认证 Fixed3 初解、特征、模型、局部修复、终验、返回和会话线程控制。原子修复和最终验收允许超过截止时刻；本实验不提供硬实时保证。
- 原 `run_once` 返回后执行的额外独立复验不计入规划时间；每次另与独立复验后的原保存 Fixed3 方案交叉核对成本界。
- 所有重复均保留。每场景方法成本取三次均值、耗时取三次中位数，不能挑选最优重复。配对比较采用 18 个场景的百分比收益均值，20,000 次按场景重采样的 percentile bootstrap，随机种子 731203。
- 区间只表达固定场景组内的条件性不确定性，不包含训练种子、硬件变化或重复计时噪声的完整不确定性；没有多重比较修正。软预算下调度负载会改变实际可完成的修复次数，所有重复差异均保留。

## 复现

```bash
python run_frozen_mlp_budget.py --source-root /path/to/extracted_delivery --output-dir /path/to/new_output
```

输出目录已有 `manifest.json` 时脚本拒绝覆盖。原源码、模型和输入场景在运行前冻结哈希，结束后再次核对。原始源文件始终保持不变。

## 输出

- `manifest.json`：补充协议、运行平台、原文件哈希、预算和统计口径。
- `plans/scene_plan_*.json`：每次计划、原始完整运行信息、执行顺序、独立验证和 Fixed3 界。
- `repeat_metrics.csv`：108 次实际运行，保留时间、成本、调用、接受次数、终止原因和超时。
- `scene_metrics.csv`：36 条场景×方法汇总，含三次重复的成本/时间/调用范围。
- `paired_scene_metrics.csv`：18 条逐场景 MLP vs Detour 配对数据。
- `validation.json`：逐次验收和成本界。
- `summary.json`：汇总、场景配对收益及 95% CI、P95 和超时统计。
- `RESULTS.md`：完成后的中文结果解释。

P95 同时报告“18 个场景的三次耗时中位数”的 P95 与“54 次全部运行耗时”的 P95，不混用两个分母。所有数据属于冻结后的描述性补充，不是新的训练或采用门槛试验。
