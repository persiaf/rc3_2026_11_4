# 第四版训练、结构输入与推理工程复核

## 结论

第四版的六组训练记录、教师数据、选模结果、NPZ 权重和现有源码互相一致。新增的图输入确实修补了旧 28 维统计缺少候选入口/出口距离和候选间距离的问题；它是一次有内容的结构输入消融。正式训练属于收益监督学习，不是 PPO 或其他在线强化学习。本次没有重训、没有加载 PT，也没有使用 39 个新测试场景调参。

已经完成的本轮实测包括 7 项无 Torch 单测、结构模型在 18 个原验证场景上的 144 步全输出等价检查，以及两种实现各 3 次的 108 份完整规划检查。新隔离缓存适配器保持输出、动作和最终方案一致，显示一定工程提速潜力，但当前计时有明显离群，不能据此更改第四版正式采用结论或承诺部署时延。

| 原验证场景 | 18 |
| 教师状态 | 384，每个训练场景 4 个 |
| 有正收益状态 / 全零收益状态 | 349 / 35 |
| 合法窗口动作 | 30,200 |
| 正收益动作 / 零收益动作 | 4,353 / 25,847 |
| 教师轨迹来源 | oracle、detour、random 各 128 个保存状态 |
| 保存步骤分布 | 第 0～7 步各 48 个状态 |
| 变体 / 随机种子 | 2 / 3 |
| 每组训练 | 80 轮，batch size 8 |
| 总梯度更新 | 2×3×80×(384/8)=23,040 |
| 历史记录行 | 54，即 6 组各记录第 0、10、…、80 轮 |
| 新测试元数据 | 100 桌 18 例、36 桌 9 例、196 桌 9 例、400 桌 3 例 |

23,040 次是对固定 384 个教师状态反复优化的梯度更新数，不能写成 23,040 个独立训练场景或新生成标签。每组有 9 次验证，先选组内轮次，再按相同 18 个验证场景选种子。此流程合理使用验证集，但反复选择意味着验证收益不是独立泛化估计。

本轮安全读取两代数值缓存后逐项比较：第四版除新增 `graphs` 和 `graph_schema` 外，原来的场景、状态、28 维特征、mask、收益标签、初始路线、参考成本、轨迹、案例元数据与统计完全不变。第四版 `data.pkl` 的 SHA256 为 `82114aa6ce456fa136a814595331ec6aeab5a90acd4269165ece3b114bd25553`，与数据清单和训练摘要一致。训练摘要记录的 `train.py`、`model.py`、`features.py` 哈希也与现源码完全一致。

数值缓存使用 `pickletools` 先检查 opcode，再用限定 NumPy 数值类型的白名单反序列化；没有执行任意 pickle 全局对象。脚本不调用 Torch，也不读取 PT 内容。

证据：`training_audit.json`；原始 `rc3_v4/data/manifest.json`、`rc3_v4/training/summary.json`、`rc3_v4/training/history.csv`。

## 2. control 与 structured 究竟比较什么

两变体使用同一网络结构、相同训练状态/标签、同样种子和更新预算。每个模型均有 **38,438 个可训练参数**，不包含均值/标准差缓冲区。六份 NPZ 均可通过纯 NumPy 加载器的字段、形状、有限值和元数据校验，归一化参数与仅在训练合法动作上重新计算的结果逐位相同。

结构模型新增的信息包括：

- 每个候选的入口→候选、候选→出口距离，以及候选之间完整局部距离矩阵。
- 必须重新覆盖的任务与候选之间分左臂/右臂的可达关系。
- 候选位置、方向、高度、是否在当前路线等 10 维属性，以及任务的 4 维属性。
- 候选和任务的有效性 mask。

候选/任务信息经 32 维嵌入与双臂消息聚合，再经过两层含距离偏置的注意力块。注意力打分包含

\[
\frac{QK^\top}{\sqrt{32}}-\operatorname{softplus}(\beta)D.
\]

候选均值池化和最大池化得到图嵌入，与 28 维统计分支相加后，生成窗口排名、预测收益、正收益分类与 STOP 输出。

`control` 在图编码之前把候选、任务、可达关系和距离的数值全部归零，但保留 mask。由于候选嵌入此时相同、可达消息为零、距离为零，图分支在数学上成为可学习常数；它不会获得结构模型的实际几何/可达信息。候选数只可能造成浮点求和次序等微小数值差异，不能视为有效结构信号。因此“相同名义参数规模、同一架构的信息消融”成立；“有效信息容量相同”不成立。

这比将不同大小的 MLP 与注意力网络直接比较更能解释图输入的作用，但即使结构模型均值略好，也仍需正式配对统计支持，不能从新增信息和参数数量直接推出“图结构已被证明有效”。

证据：`rc3_v4/model.py`、`rc3_v4/features.py`；本轮 `training_audit.json`。

## 3. 损失与选模：当前应称为收益监督的局部搜索调度

令合法动作的教师即时收益为 \(g_a\ge0\)，排名监督目标为

\[
q_a=\frac{\sqrt{g_a}}{\sum_b\sqrt{g_b}}.
\]

总损失由四项组成：正收益状态上的软排名交叉熵；“所有合法窗口收益为零”的 STOP 二分类；缩放收益的 Smooth L1 回归；以及权重为 0.2 的正收益二分类。回归项对正收益动作加大权重。数据导出的收益尺度为 0.68534672，正负动作类别权重为 5.93774408。AdamW 学习率 3e−4，权重衰减 1e−4，梯度范数裁剪为 1。

排名标签表示一次修复和规范化后的即时收益，没有价值回传、优势估计、策略概率比或 PPO clipping。多步环境验证不能把监督训练变成 PPO。合适表述为：**收益监督的结构化窗口选择器，嵌入有预算的覆盖保持局部搜索**。

| 变体 | 种子 | 选中轮次 | 原验证平均降本 |
|---|---:|---:|---:|
| control | 17 | 20 | 0.984765% |
| control | 29 | 30 | 0.996219% |
| control | 43 | 40 | 0.959132% |
| structured | 17 | 60 | 1.287293% |
| structured | 29 | 20 | 1.172079% |
| structured | 43 | 20 | 1.246611% |

最终 control 选 seed 29/epoch 30，structured 选 seed 17/epoch 60，与全部历史行的验证最大值一致。最终 NPZ 文件和相应种子文件逐字节相同。结构选中模型为 156,184 字节，约 152.52 KiB。

随包 STOP 诊断记录显示，两个变体在 35 个全零训练状态上都没有触发 STOP；选中模型的 18 场景验证也均使用 8 次调用。本轮在结构模型的 18 场景复跑中再次得到每场景 8 步。由此可写“STOP 头已实现，当前停止收益未证明”，不宜宣传已学会节约搜索预算。本轮未重新执行全部 384 状态的 STOP 诊断，不能把随包记录冒充此次实测。

证据：`rc3_v4/train.py`、`rc3_v4/training/stop_diagnostic.json`；本轮 `training_audit.json`、`cache_validation18/summary.json`。

## 4. 结构输入解决的问题与仍存在的边界

旧反例中，两个实例的 28 维统计相同，但替代候选的通行代价不同。新输入包含入口/出口和候选间距离，可以区分该反例；本轮实际执行 `test_known_aliasing_separated_by_distance` 通过。这支持“修补已知遗漏”，不是只换了网络名字。

局部图只表示此次必须重新覆盖的任务。它没有完整表示候选对窗口外任务的覆盖、窗口外路线顺序和其全部距离。修复后 `canonical_route` 可能因新的交叉覆盖而删去窗口外冗余停靠，因此完整规范化后的收益未必由这个局部输入唯一决定。排名头又是逐窗口计算的，并不通过跨窗口注意力读取其他窗口的细节。

该信息边界主要影响收益预测和窗口排序的可辨识性：有些全局后效只能在实际修复与规范化之后知道。它不等于可行性错误，也不证明它是当前未过采用门槛的唯一原因。可行性仍由完整问题上的覆盖修复、验收与独立验证负责。没有必要为了宣称“充分状态”不断扩大神经网络或马上重训；当前研究完全可以限定为局部信息下的启发式调用排序，并报告在同一调用预算下的实测收益。

注意力汇聚本身也不是所有可能图状态的单射编码，不能仅凭输入了原始局部 F/D，就宣称恢复了完整马尔可夫状态或获得最优规划保证。

证据：`rc3_v4/features.py`、`rc3_improve/repair.py`、`rc3_v3/environment.py`、`rc3_fast/solver.py`、本轮 3 项 feature 测试。

## 5. 数据划分与可信边界

本轮验证了新 39 个测试种子彼此不同，并且与 96 个训练和 18 个验证种子无交集。训练源码只使用训练教师状态和原验证场景选模型；图特征构造不调用修复 oracle，相关单测通过。没有发现把教师收益作为图输入的情况。

随包 `split_audit.json` 记录扫描 3,111 个历史来源文件、排除 2,863 个种子。上传包未包含完整原始工作区，也没有原 v3 `test_cases.json`，因此本轮不能独立证明对全部历史实验的排除，只能核验当前能见的 train/validation/new test 划分和扫描声明。源码哈希与日志一致也不等于有独立可信时间戳，不能单靠这些文件证明预注册的历史先后顺序。

39 个新测试案例已经成为已观察的正式结果。不能因为其中某个未选种子更好，再改选该种子并沿用同一测试集声称独立泛化。400 桌仅有 3 个场景，不能写成对所有 400 桌实例的可靠性保证。

## 6. NPZ 和旧 MLP 适配器

本轮实际加载六份种子 NPZ，逐一核对参数数目、训练 metadata、训练归一化和选中轮次。未加载 PT。随包 Torch/NumPy parity 记录报告每变体 144 个状态无动作不一致，最大输出差分别约 2.86e−6 和 1.03e−5；本轮环境没有 Torch，因此没有重复该跨框架检查。

本轮实际执行了旧 MLP 适配器 4 项测试：18 个原验证场景、初始和一次确定性变化后的状态中，全部输出头逐位一致，动作相同；无每动作线程池上下文；拒绝非 NPZ/非 MLP；拒绝无效观测。适配器仍使用原冻结权重，只把 BLAS 线程管理移至完整规划会话。它是工程修改，不是重新训练的新模型。

随包旧 MLP 微基准摊销了 8 次推理的线程上下文开销，未包含特征、导航、修复和最终验证，不能当成完整规划加速倍数。任何与 Detour 的速度结论应使用同机同预算的完整规划测量。

本轮本分项实际测试合计 **7/7**，耗时 **10.625 秒**，见 `non_torch_tests.log`。该数字不包含其他审计分项，也不包含需要 Torch 的 6 项 model 测试。

## 7. 已完成的有限工程诊断：缓存路线不变时的图嵌入

现有 GraphPolicy 已缓存原始局部图，但每次动作仍重新 collate 并运行整个图编码器。在同一 Env 中，若 F/D、模型权重、任务/候选语义固定且完整路线和窗口布局不变，图编码也不变。剩余预算只进入 28 维统计；已尝试动作的 mask 改变排名屏蔽和 STOP 池化。可以缓存图嵌入，同时每步重新计算统计分支、全部输出头和 STOP。

本轮隔离适配器 `graph_embedding_cache.py` 以 **Env 对象身份 + 完整路线 + 每个窗口 start/end 顺序** 判断失效，限定同一规划与同一模型，不以窗口 ID 单独作为缓存键。每次新 Env、路线变化或窗口布局变化都会重编码。**F/D、权重、任务和候选语义必须在 Env 生命周期中固定；以后若插入任务、修改地图/可达关系或替换权重，必须创建新 Env 或显式使该缓存及原环境缓存失效。** 不能把此适配器直接视为支持在线任务插入的动态缓存。

先在 1 个原验证案例验证，随后按批准范围扩到 18 个原验证案例。每个案例原版和缓存各做 3 次交错完整规划；不读取新测试成本、不调阈值、不重训。结果：

- 144 个动作步骤：rank/gain/positive/STOP 全部数组逐位相同，全部动作相同。
- 108 份完整规划：同一场景的整个最终方案对象相同，全部通过原独立终验，无 fallback 故障。
- 与原训练所选结构模型的 18 项验证收益相比，最大差为 4.09e−14 个百分点。
- 每场景 3 次取中位数，再跨场景取中位数，完整规划为 **627.38→585.62 ms**；模型调用总计 **163.57→121.77 ms**；纯推理部分 **81.98→42.85 ms**；缓存命中/重编码次数中位数为 **4/4**。
- 18 场景中 17 个完整规划中位耗时下降；逐场景百分比降幅中位为 7.35%。另 1 例存在明显系统波动：原版 803/4836/726 ms，缓存 761/1004/3354 ms，该例中位反而慢约 25%。没有剔除此例，也没有追加重跑挑选结果。

完整规划测量包含基线路径构造、模型与缓存开销、修复、最终验证和线程上下文；不包含双方共享的场景预处理和模型磁盘加载。这里的 627/586 ms 来自当前审计环境，不能与原 Windows 报告的 427/275 ms 直接相减。

因此结论应为：**等价缓存已完成数值与路径验证，在原验证集显示提速潜力；尚不能保证稳定加速，更未达到新采用证明。** 正式测试和部署决定保持原状。缓存是可以复用的低成本工程方向，无需为它增加训练轮数。

## 8. 交付与复现

本目录提供：

- `training_audit.json`：安全读取、数据复用、归一化、参数、选模、哈希、划分和验证成本对照。
- `audit_training.py`、`safe_numeric.py`：支持独立 source root 的只读审计。
- `graph_embedding_cache.py`、`cache_diagnostic.py`：隔离的缓存适配器和限定原验证集的诊断。
- `cache_one/summary.json`、`cache_validation18/summary.json`：全部诊断原始记录与等价检查。
- `non_torch_tests.log`：此次 7 项测试的执行回执，明确不是上传包的旧日志。

示例命令：

```bash
python -B audit_training.py --source-root /path/to/v4_upload --output-dir /path/to/audit_output --cache-summary /path/to/cache_validation18/summary.json
python -B cache_diagnostic.py --source-root /path/to/v4_upload --output-dir /path/to/new_validation_diagnostic --scenes 18 --repeats 3
```

建议后续工作顺序是：冻结此次训练与正式测试的结论；优先保留可行性修复和独立验证的工程主干；用隔离缓存以及已有旧 MLP 线程适配器评估低成本改进；只有当新的独立实验问题和接受门槛明确后再安排训练。当前证据不支持为了越过 0.77% 的数字再盲目增加训练轮数或扩大网络。
