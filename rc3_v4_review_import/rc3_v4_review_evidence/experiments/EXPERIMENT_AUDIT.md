# 第四版实验独立复核

审查日期：2026-11-03。原始资料来自 `rc3_v4_delivery.zip` 的只读解压目录。本次没有训练、调参或重跑完整规划；没有加载 PT、pickle 或其他可执行模型对象。原始 Windows 性能数据已重算统计，但没有在当前机器重新测量速度。

## 1. 复核结论

**第四版的统计、落盘方案和未采用新模型的决策能够复现。相比第三版，本轮已经出现了有限测试集上的学习质量收益，但新增结构输入的独立贡献，以及这种收益在相同实际时间下的用途，仍未得到充分证明。**

本次先审查 `rc3_baseline/validator.py` 与 `rc3_v4/report.py`，然后使用经审查、独立于规划器的原验证器逐份验证所有保存方案。统计重建、配对区间和采用门槛由新增审计脚本另行实现，未调用原报告统计函数。这属于对原独立验证器的实际复验，不是另写了一套具有不同几何实现的验证器。

|实际执行的复核|结果|
|---|---:|
|保存方案重新验证|855 / 855 通过|
|对独立验证后的 Fixed3 参考方案检查成本界|855 / 855 通过|
|重新计算成本与原始记录比较|855 / 855 一致|
|从原重复运行重建场景×方法汇总|357 / 357 一致|
|冻结文件 SHA-256 核对|29 / 29 一致|

验证结论只覆盖已声明的二维导航、任务覆盖、左右臂关联和代理操作空间约束。它不等价于真实关节空间可达、双臂全过程无碰撞或机器人已经实际完成任务。855 份计划共享 39 个场景与同一类模型假设，也不是 855 个独立环境样本。

## 2. 39、357、855 的正确分母

39 个新场景由百桌 18 例、36 桌 9 例、196 桌 9 例、400 桌 3 例组成。

|实验分组|场景×方法记录|每条重复数|落盘运行数|
|---|---:|---:|---:|
|固定调用数主比较：39 场景×5 方法|195|3|585|
|400 ms 软预算：18 场景×3 方法|54|3|162|
|训练种子：18 场景×2 架构×3 种子|108|1|108|
|合计|357|不统一|855|

不能用 `357×3` 解释总次数。种子分析使用相同的 18 个百桌场景，每个模型各执行一次，不能把它解释成 54 个新的独立场景。

## 3. 百桌主结果：质量收益存在，但结构输入贡献未证实

所有非 Fixed3 方法使用 8 次局部修复调用。目标为 `J=导航路程+0.75×服务配置数量`，是等效长度目标，不是直接测得的完成时间。表内成本下降先逐场景相对 Fixed3 计算，再取平均；时间先在场景内取 3 次重复的中位数，再在 18 个场景间取中位数。

|方法|平均 J|相对 Fixed3 平均降本|完整规划中位数|规划 P95|预处理＋规划中位数|
|---|---:|---:|---:|---:|---:|
|Fixed3|268.086|0|93.61 ms|145.72 ms|339.67 ms|
|Detour8|266.376|0.651%|274.67 ms|350.56 ms|514.87 ms|
|冻结 v3 MLP8|264.985|1.163%|279.41 ms|411.21 ms|526.83 ms|
|Control8|265.011|1.152%|441.36 ms|548.27 ms|656.81 ms|
|Structured8|264.350|1.418%|427.12 ms|626.45 ms|660.44 ms|

完整规划包含初始参考路线、特征构建、模型、修复、终验和会话线程设置；公共导航与可达性预处理单列。两项时间都不包括进程/模型加载、场景生成、额外审计和磁盘输出，不能称为严格的完整冷启动延迟。P95 来源于每场景重复中位数的分布，不是所有重复运行的混合 P95。

以下使用场景配对百分比 `100×(J参照−J方法)/J参照`，按固定排序的场景键，以种子 731203 执行 20,000 次场景 bootstrap。区间未包括训练种子不确定性，也未进行多重比较校正。

|方法 / 参照|平均配对降本|95% 场景区间|胜 / 平 / 负|
|---|---:|---:|---:|
|Structured8 / Detour8|0.7699%|[0.4509%, 1.0842%]|15 / 0 / 3|
|Structured8 / Control8|0.2651%|[−0.1005%, 0.6223%]|12 / 1 / 5|
|Structured8 / 冻结 v3 MLP8|0.2550%|[−0.0706%, 0.5802%]|11 / 2 / 5|
|Control8 / Detour8|0.5038%|[0.2261%, 0.7618%]|15 / 0 / 3|
|冻结 v3 MLP8 / Detour8|0.5138%|[0.1977%, 0.8319%]|14 / 1 / 3|

最后一行是此次审计追加的描述性比较，不是本轮原定的主要采用门槛。它揭示一个值得保留的新结论：**旧轻量模型已经在本轮新场景上取得相对 Detour 的正向质量信号，而新结构模型尚未显示相对该轻量模型稳定的额外收益。**

不能把 Structured 相对 Detour 的全部 0.77% 归因于新增任务—候选—双臂图输入，因为同网络屏蔽图输入的 Control 也已经获得约 0.50% 的收益。旧 MLP 权重冻结未变；新场景、统计口径与线程适配的存在，也不允许把本轮结果说成旧权重的算法能力又提高了。

旧 MLP / Detour 的“总体规划中位数之比”为 1.017，但逐场景时间比的中位数约 1.088，且 P95 更高。因此只能说本轮总体中位耗时接近，不能说它在所有场景或尾部延迟上只慢 1.7%。

三个种子的平均方向一致；只有种子 43 的同种子结构消融区间未跨零。三个 Structured 对 Detour 的平均收益与场景区间均为正，但三组场景完全相同，不能合并成三倍样本量宣称高置信度泛化。

主表使用原验证集选择的 Structured seed 17 / epoch 60 和 Control seed 29 / epoch 30。不能因为 seed 29 在新测试上更好，就用它替换主结果或采用决策。

## 5. 同时间预算：学习网络的调用效率抵消质量收益

|400 ms 软预算方法|相对 Fixed3 降本|实际规划中位数|平均修复调用数|超过 400 ms 的运行|
|---|---:|---:|---:|---:|
|Detour|1.593%|440.11 ms|23.37|54 / 54|
|Control|1.254%|442.43 ms|10.48|54 / 54|
|Structured|1.488%|444.86 ms|10.02|54 / 54|

Structured 相对 Detour 的平均配对收益为 **−0.1084%**，95% 区间 **[−0.4570%, 0.2026%]**。因此没有同时间质量优势的证据；也不能反过来声称 Detour 已经显著优于 Structured。三者实际时间接近，但 Detour 完成的修复次数超过两倍。

该实验是允许原子修复和最终验证超时的软预算，最大超时约 68.04 / 85.93 / 71.09 ms。不能写成“保证 400 ms 内返回”。原 Windows 同时间预算下未评测旧 MLP，这是判断轻量模型实际用途的直接证据缺口。后续已在当前 Linux 机器另行完成冻结模型补充，结果见下文，未与原表合并。

## 6. 时间分解指出真正的新增代价

下表均为百桌场景的分项中位时间。不同分项的中位数不可相加后当作完整规划中位数。

|方法|统计特征|选择器整体|其中图输入构建|其中推理|局部修复|最终验证|
|---|---:|---:|---:|---:|---:|---:|
|Detour8|40.12 ms|0.10 ms|0|0|86.22 ms|32.62 ms|
|冻结 v3 MLP8|55.43 ms|1.87 ms|未单列|未单列|88.69 ms|36.34 ms|
|Control8|57.04 ms|124.15 ms|49.40 ms|66.51 ms|89.65 ms|35.74 ms|
|Structured8|61.86 ms|130.48 ms|60.78 ms|64.41 ms|91.30 ms|36.54 ms|

新网络选择器开销约 125–130 ms，旧 MLP 约 1.9 ms。模型文件小和参数量小不自动等于完整规划快；局部窗口图构建与重复推理才是本版可见的新增时间。Control 也支付图构建成本，因此它适合检验输入消融，却不能替代轻量 MLP 这个部署效率参照。

## 7. 门槛执行与冻结证据

`paper/EXPERIMENT_PLAN_20261103_v8.md` 声明了主要比较、0.2% 质量阈值、配对区间下界大于零、相对 Detour 总体规划中位时间比不超过 1.25，以及全部方案通过验证。原 `evaluate.py` 在测试循环开始前写 manifest，具有验证集选模守卫，并随机交错重复测量顺序；保存的模型和源文件哈希与当前包一致。

## 8. 本版相对第三版应如何更新研究结论

1. 将“学习尚无价值”改为更准确的表述：固定 8 次修复时，学习选择器对规则选择器存在有限样本质量收益；新结构输入的独立增益与同时间优势尚未证明。
2. 把冻结旧 MLP 明确保留为效率参照和质量模式候选。本次后续已在同一批冻结百桌场景、相同软截止定义下补充旧 MLP；没有按测试结果重选种子或重训，补充结果单独报告。
3. 36 / 196 / 400 桌分组应分别报告。尤其 400 桌仅 3 个压力场景，Structured 平均降本约 0.200%，低于 Detour 的 0.235%、旧 MLP 的 0.347% 和 Control 的 0.404%；应表述为压力规模可运行，不应表述为大规模稳定优势。
4. 论文中“可靠”可由代理模型内完整性、独立终验与相对认证初解不劣界支撑；“学习有用”必须另外用质量—时间曲线与正确配对参照支撑。两种证据不可互相替代。

### 冻结后的描述性补充，单独报告

在完成上述原始结果复核后，按明确限定的协议，在当前 Linux 环境用原 18 个百桌场景对旧 MLP 与 Detour 执行各三次随机交错的 400 ms 软预算评测，共 108 次、耗时约 59.98 s，全部通过实际验收与原 Fixed3 界核对，原文件哈希未变。直接复用原 `run_once` / `runtime`，没有改动算法和预算语义。

旧 MLP 相对 Detour 平均配对降本 **0.2880%**，95% 场景 bootstrap 区间 **[0.0268%, 0.5818%]**，12 胜 / 2 平 / 4 负。实际规划中位 **449.38 vs 446.53 ms**，平均调用 **7.44 vs 8.17**，双方 54/54 次超过 400 ms；全部运行 P95 为 **486.35 vs 497.25 ms**。结果支持轻量模型的小幅、条件性质量收益，但不代表硬实时或广泛稳定优势。

补充协议在已知第四版结果后确定，不能反推原采用门槛；当前 Linux 结果不与原 Windows 表合并。没有重新评测 Structured，因此不能用跨平台数据推断旧 MLP 在同时间下胜过 Structured。全部文件及更详细限制见 `../mlp_budget_supplement/RESULTS.md`。

### 科学图各面板的聚合口径

- **A：百桌质量—时间。** 18 个新百桌场景；同场景同方法 3 次运行的目标取均值，规划时间取中位数；纵轴为各场景相对 Fixed3 降本百分比的均值，横轴为 18 个场景规划时间中位数。非 Fixed3 方法均为 8 次修复上限。
- **B：配对质量区间。** 每个点是相同 18 个场景的逐场景配对降本百分比均值；横线为按场景重采样 20,000 次的 95% percentile bootstrap 区间，随机种子 731203。同一场景的运行重复不当作独立样本；区间不包含训练种子不确定性，多重比较未校正。旧 MLP / Detour 一项是冻结后的描述性补充比较。
- **C：三个训练种子。** 仍是同一批 18 个百桌场景，各训练种子每场景执行 1 次；柱高是逐场景相对 Fixed3 降本百分比均值。不是 54 个独立场景；图中无置信区间，不能据柱高差异推断显著性。每个种子的检查点都按旧验证集选择。
- **D：400 ms 软预算。** 18 场景、每方法每场景 3 次；成本和时间采用 A 的两层聚合规则，修复次数为全部运行平均值。显示的 440–445 ms 是实测完整规划中位数；每种方法 54 次运行全部超过 400 ms。旧 MLP 没有进入原 Windows 软预算实验。

可移植性小问题：原 manifest 使用 Windows 反斜杠路径，原报告函数未在 POSIX 上归一化该路径。本审计显式处理路径分隔符后仍严格核对原哈希；这不是本次 Windows 结果作假的证据，但直接在 Linux 重跑原报告时应修复，否则会出现缺文件式的哈希错误。

原始实验审计没有重跑原 40 项测试、六组训练或全套规划，没有再做真实机械臂验证；实际完成的是原 855 份方案复验，以及另列的 108 次旧 MLP / Detour 软预算补充。两组工作的平台、用途与分母分开报告。
